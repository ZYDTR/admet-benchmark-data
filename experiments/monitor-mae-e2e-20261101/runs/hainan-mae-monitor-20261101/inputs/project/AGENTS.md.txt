# ADMET 宿主训练唯一入口

团队私有项目。本文件是准备、算力观察、训练、取回评分、发布、Chat分析和主控验收的统一入口。先读 `policy.json`、`docs/source-map.md`，再按 [项目Skill索引](skills/INDEX.md) 进入本角色规范及对应run/周期合同。所有项目专用Skill只在此项目内维护与注册；全局仅保留项目路由和通用基础设施能力。已读内容无需循环重复读取。计划只是授权范围的记录，不自行授予计算或远端写入权限。

## 固定规则

- 外部预训练权重允许使用，但必须保持冻结。这来自用户已向赛方确认并在本聊天重申的条件；不得冒充公开网页逐字条款。`requires_grad=False`、`eval()`、推理无梯度、优化器排除编码器参数、运行前后参数与 buffer 摘要一致均需实际检查。磁盘 checkpoint 摘要不变单独不足以证明内存中未微调。新预测头允许训练；从零训练方案另行登记，不能混成预训练底座微调。
- 原始赛事要求、用户确认、本地控制和未确认项分开记录。读取 `policy.json`；不得把旧 Harness 的随机初始化、只能本机 Docker 或未部署网关当成通用赛事禁令。
- 本入口当前仅使用官方 train.Y 学习，内部划分做早停；训练执行方的 valid/test 只输入 Drug_ID、Drug。预测、标签评分和赛事上传分别处理。官方允许 valid 调参；2026-10-31 用户明确由指定取回 Thread 在本机用 valid 真值及固定评分器评分，主控独立验收，评分与训练隔离是本地控制。评分报告和问题诊断进入逐批登记的专职分析 Chat；经主控核验来源、行映射与evaluation_scope后，可提供本批明确准入的valid真值用于诊断，分析访问不等于新公开发布授权。历史aggregate_only任务不变。准备/训练会话只接收技术指南与盲输入，不接收私有验证标签、精确分数或逐行误差。外部补标签、教师伪标签和测试拟合仍不纳入。
- 保留任务、分区、原始行号和全部输入行；ID 可以重复或为空。未经新的清洗授权不删行、不去重、不改标签。模型内标准化仅在内部训练划分拟合并保存，输出还原到给定 Y 数值尺度。已发现的清洗包仅有审计，尚未替换基线。
- 实际运行前执行 `python3 -B scripts/check_plan.py runs/<run_id>/PLAN.json`。该检查只核对计划与允许输入；不能代替代码、GPU、路径、运行及冻结状态审计。
- 海南相关一切操作先完整读工作区 `rules/skills/hainan-compute-access/SKILL.md` 及命中的连接参考。只能经既有 Windows 路由；全部目标机写入、副作用、环境和缓存都在 `<AUTHORIZED_PROJECT_ROOT>`。绝不停止他人服务、删除或改动他人文件。先核实资源，再选卡，启动前复核，记录 GPU UUID、PID、启动时间并持续观察，仅处理自己的有身份作业。
- 只有主控或用户明确指定的宿主执行会话可按当次授权亲自使用连接入口。准备 Agent 仍不取得凭据或任意远端 shell。不能自行再派发 Agent、Thread、CLI 模型或转交执行权限。
- 每次 run 独占目录；失败留证，不覆盖旧尝试。运行状态不明先查询原作业，不能重复提交。模型、输入、代码、环境、日志及产物均保留摘要。不自动上传赛事或推送仓库。

## 项目路由

2026-11-01 用户另行授权专用手动官网提交与查分Thread，先用 GPT-6.1 Terra，随后明确改由新 GPT-6.1 Sol Thread接手；当前身份见 `submissions/thread.json`。入口 [submissions/README.md](submissions/README.md)，规范为 [赛事提交Skill](skills/competition-submission/SKILL.md)。这是每次明确手动请求范围内的官网上传例外；`policy.json` 中训练/自主循环的 `official_upload` 排除及旧run合同保持原样。材料进入固定批次不自动触发提交，该角色不训练、不监控其他Thread、不建定时、不回传精确官网分数给准备/训练方。

准备方使用 `skills/ml-preparation-only/SKILL.md`，主控每次派发冻结到目标机实际可读的任务包并明确要求读取；OpenCode仍从mini Context Infrastructure根进入。训练方使用 `skills/admet-frozen-training/SKILL.md`；独立 `gpt-6.1-sol/xhigh` 观察Thread按 `skills/hainan-resource-observation/SKILL.md` 每10分钟只读记录到 `resources/hainan/`。训练执行Thread也固定为 `gpt-6.1-sol/xhigh`，先读资源日志，陈旧/缺失时自行查询，实际启动前总要再次直接复核。取回评分方使用 `skills/hainan-training-retrieval/SKILL.md`，网关和主控研究使用下述证据Skill。角色不能凭其他角色的规范扩大自身授权。

Chat网关按用户2026-11-01最新授权使用混合通道：可用内置Browser新建本批普通Chat并核实Pro；真实会话ID可用后优先原生发送/续问、读取正文。如果首条消息前没有原生可寻址的真实ID，允许Browser发送一次已封口的首条正式任务，核实服务端接收后交回原生接口。不得为占位另发消息、未知发送后重复提交或用Work Cloud替代Pro Chat。文件继续允许Browser从真实附件页取回。创建、首次发送、原生接管分别留证，具体见项目证据Skill。

持续整理实验历史、构建新Chat阅读包及登记结论验证/推翻时，使用 `skills/admet-evidence-review/SKILL.md`；本地实例入口 `exchange/catalog/README.md`。该Skill不扩大训练、标签或发布权限。

`policy.json` 保存适用约束；`evidence/` 保存源规则快照与出处；`docs/source-map.md` 说明旧 Harness 的采用/排除；`scripts/` 是无凭据检查入口；`tests/` 是离线反例；`runs/` 保存计划、实现和证据。原 Harness、旧基线和准备 Agent 交付只读。

原单作业试验 `runs/hainan-skill-pilot-20261030/` 已失败留证。用户随后授权主控修复跑通；`runs/hainan-frozen-training-20261031/` 已完成真实训练和独立验收，参考报告见其 `acceptance/report.md`。执行会话只写指定 run，不能改本入口、policy、Skill 或验收标准；这些由主控按用户要求维护。新方案/配置另建 run，先登记来源和预算，不能重放完成的 run。

每个可用阶段更新 `docs/working.md`（仅主控修改）；获准提交时分阶段提交，无推送授权时保留本地记录。本项目 Python 检查仅用标准库、`-B`，不在只读检查中隐式训练。

## 主控复核与新版 Skill 派发

用户要求主控持续审读各角色的实际行为和产物。每发现需要沉淀的新问题，在创建或修订Skill前重新完整读取[Best Practice Skill Writing](../../rules/skills/bestpractice_skill_writing.md)，判断问题应进入项目Skill、固定工具或验收反例；以真实失败和证据为依据，不把未确认根因写成事实，不靠不断堆叠提醒替代代码修复。保留旧版、修订原因和可检查的成功标准，更新本项目skills/INDEX.md；项目专用能力不注册到全局。

此要求覆盖准备、训练、资源观察、取回评分发布和Chat网关。下次向相应Thread派发新任务或明确重跑时，主控须在对方实际可读的任务位置交付当前适用Skill及命中引用的冻结版本，提示中明确要求使用，并登记路径、版本/摘要及任务身份。对方读取记录与实际行为分别验收，不能仅凭“已读”或回显摘要判通过。长期Thread有旧历史也必须收到本次版本绑定。

新版本用于后续派发；正在执行任务的冻结输入、历史规则快照和失败原件保持原样，紧急恢复另有版本化决策。Skill修订本身不授权追加训练、评分、发布或模型会话。主控工作记录区分代码检查通过、真实运行通过和新版Skill模型行为尚未实测。

主控消费已到达的结果是当前任务的一部分：答复状态/疑问后继续处理，不能只记review_pending就结束并等用户催。每个需动作回报应有真实接续决定、负责人和证据，或明确外部依赖/用户阻点；交接细则见[项目接续合同](skills/admet-evidence-review/references/handoff-completion.md)。该合同不新增常驻轮询或训练授权。
