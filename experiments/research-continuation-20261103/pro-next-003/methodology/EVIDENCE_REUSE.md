# 验收证据复用与职责

2026-11-02 用户要求减少重复核验。目标是让每次检查回答一个尚未解决、影响当前决策的问题；已有可靠结论继续使用。方法由 Agent 判断，不增加统一检查程序或新的逐项审批。

## 什么可以复用

复用对象须有明确来源身份、实际检查及覆盖范围、结果和未验证项，且与本次用途相容。已审读代码的版本、固定资产摘要、输入与行映射、评分实现、脱敏视图和公开 commit 均可成为依据。仅有模型说“通过”、来自待验对象自行生成的可信摘要，或版本不明的旧报告，不能替代实际证据。

同一可信版本和范围内，下游引用原验收及必要身份关联即可，不重复运行整套测试、逐文件哈希、全部评分或重读全部历史。首次接触的可变副本或新传输由接收方做一次相应完整性检查；后续角色消费该检查记录。新文件/修改内容、依赖或尺度/行映射变化、失败、矛盾、来源不可信或检查未覆盖当前用途，才重查受影响部分；范围无法界定时可扩大。重查时简述具体触发与待解决问题，不能仅以“再保险”或换了 Thread 为理由。

验收有范围，不是永久通行证。既有实现正确性可复用，每次新训练的实际更新、冻结参数及 buffer、数据身份、预测覆盖、资源影响与退出证据仍由训练方产生；新评分的输入行身份仍由评分方核对。GPU 当前占用、连接身份与主机密钥、进行中的写入和作业状态会变化，必须依据当次现场。执行权限、标签边界和不影响他人始终保留。

## 谁检查什么

2026-11-02用户进一步明确：准备质量先观察一两轮，稳定后停止每轮验收。下述一般复用规则不把新批次、新产物或正常配置调整本身当成再次审查准备质量的理由；不会把这项工作转交Terra或训练方。当前GLM16任务作为第一轮，是否还需第二轮依据实际证据决定。

| 对象 | 负责形成证据 | 下游的工作 |
|---|---|---|
| 准备执行与质量 | 准备方自检和交付；主控先观察一两轮GLM实际执行 | 确认Skill下执行稳定后不逐轮验质量；明显失败、重大变化或新问题才定向检查。正常新批次不自动触发复查，训练方核实本机实际运行条件。 |
| 准备运行状态 | Terra只读取已登记请求的运行状态和必要终态消息 | 回传状态、时间、错误与消息中已有的交付位置，不打开产物、读代码、测试或判断质量；主控直接接收交付。 |
| 新训练运行 | 训练方证明本次学习、冻结、行覆盖、环境、资源和退出 | 主控判断新结果是否足够用于评分；不重演训练方已覆盖的全套运行审计。缺口和异常作定向独立核查。 |
| 新预测评分 | 指定取回方按固定评分器一次评分，并绑定来源与完整行集合 | 固定数学已独立验过且实现未变时，主控读取结果及来源/覆盖回执，不再全量重算。新增指标、实现变化或数值矛盾时独立复算受影响项。 |
| 原件取回与公开视图 | 取回方验证新传输、来源和新增脱敏视图；发布后验证新增对象与必需入口 | 主控审新增公开范围、脱敏风险与关键变更；网关消费固定发布回执，不重复下载全库。旧公开对象按固定 commit 引用。 |
| 外部Pro返回包（启用时） | 网关验证一次目标、运输完整性及可读结构，报告明确缺件 | 主控专注新科学主张、实验定义和采用决定，不重复 ZIP/全部文件哈希，也不重做整份研究。 |

主控对质量负责，不等于亲自重做每个角色的工作。关键结论首次建立、上游证据欠缺或冲突时保留独立审查；有证据的既有验收不会因换角色而自动失效。

## 让研究和交接服务实验

当前采用一个本地Astra Extra High与一个登记Pro独立并行研究，详见research-mode与共同实验纲领。Astra维护唯一研究账本并归并两路候选，主控唯一派发。共同上下文和关键索引实读，已验历史按版本继承。Pro按已有用户偏好可复用原Chat，但本轮问题与证据截止时间重新绑定，旧聊天不代替新输入。两路都能全面研究，重叠用于检验解释，避免重复评分/运输等已验工作。Astra本轮不另派Agent；Pro可沿其已获授权能力按互补问题研究，不能以虚构角色扮演称真实并行。

一次研究给出足够支撑后续多个实验批次的具体方案、对照、成本和条件分支。主控在已授权预算内按证据选取并登记；无需每个头或每个小批都再研究。先到且可靠的方案可准备/执行，晚到建议去重并结合最新实验增量纳入。重要反证、新科学分支、计划覆盖的实验完成或可用方案耗尽时再研究。用户要求的深度、广度和交叉核验保持，避免以减少研究内容换速度。

完整历史持续累计，用固定原件链接、已验摘要和新增索引交付；不每批复制、重新脱敏和复核未变化的全部历史。新增材料与已有材料的关联必须可追溯。来源稳定、输入核验并完成整批评分后可先报分，后续质量材料与公开视图继续整理；公开候选未审完不提前发布。各角色报告自身完整耗时、依赖等待和重复工作原因，重叠时间不累加。

本规则用于新的派发或主控明确版本化接续。正在运行的冻结任务与历史原件保持，不能因修改规范宣称当前阶段已通过。规范修订成功的依据是职责和触发条件清楚；实际省时效果须由后续真实批次验证。

## 缩短端到端等待

主控按真实变化定义准备任务：交代已验实现及来源、本次新增能力、可复用的资产和环境、必须解决的缺口。现有实现已支持且证据充分的配置，可由获授权训练方直接消费；不把每批重新开OpenCode、重建环境或重写检查套件作为仪式。确需新接口才派相应准备，不能以跳过准备名义省略未验证的科学变化。拆分会话须有可独立交付的内容和预期端到端收益；多个会话重复同一套上下文和接口不是默认提速方法。

完整取回承诺与下一步必要依赖分别表达。所有可能影响质量的已授权原件仍须保留并可追溯，已委派的完整归档继续独立完成；Astra可按研究直读权限直接消费远端原件，不要求每次研究新增全量取回。在来源可靠、该项评分/研究所需证据已齐时，可先交付可用结果，剩余归档继续。研究所需的规则、对照、失败与关键原件不可用时，相关问题仍未就绪，不能用摘要或partial标签冒充完整。每次提前交接说明已就绪范围、尚欠材料及对结论的影响；不改运行中的冻结任务，也不自动放宽发布或标签范围。

训练与取回方共用有来源身份的交付清单：明确谁已取到哪些对象、谁补齐余项、下一步需要哪些内容。一次新传输由接收方核验后可供下游复用；不让模型或归档的重复搬运挡住已齐的评分输入。传输合并、连接复用、压缩与有限并发可按实际瓶颈选择；不增加相应源主机写权限、不提高到影响他人的负载，也不固定每run一次连接或固定并发数。没有分项计时只能报告应用接收吞吐，不能把压缩、工具缓冲与连接时间都归为物理网络慢。

发布前的材料整理、脱敏、候选审读、上传、读回和主控交接分别承担时间。已知本批必需的入口、研究问题及规则引用一起准备，避免大包发布后为两个小文件再走完整角色交接；Prompt全文可由网关按冻结模板和已发布事实直接发送，不要求额外上传一个Prompt文件。固定版本与新增对象完整性仍由发布方证明一次，方法随目标能力选择；网关不重复下载整库。不可提前公开未经审读的内容来换速度。

准备完成到观察方发现、产物就绪到主控消费、放行到实际派发，都属于交接延迟。使用当前服务确实可用的终态事件或观察能力；事件不可用时，由专用观察方结合预计时长和调用成本选择有界观察，不能仅靠反复唤醒主控。运行中不提示或修准备会话、不新增授权外定时。可靠交付回报到达即可接续，不等待与下游无关的报告润色或记账轮次结束。

耗时验收覆盖明确起止窗口，使用不重叠阶段解释全部墙钟；角色活跃、工具执行、后台工作和资源等待另列，重叠不相加，未测细项保留未知。已能支持判断的时间证据直接使用；不为计时再造一套阻塞交付的流程。优化是否有效看同类任务的准备至可训练、学习完成至可评分、分析材料就绪至实际发研究的跨度，以及返工和新增检查范围，不能只看某条上传命令。
