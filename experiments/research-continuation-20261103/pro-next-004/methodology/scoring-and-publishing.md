# 本机 valid 评分与分析材料发布

适用 v1.5.0。当前本地Astra与Pro可并行研究，模式见control/research-mode.json。本地研究交付无需发布；下文公开仓库/Chat运输要求仅适用于主控明确派发的Pro旁路。以下2026-10-31说明为历史授权来源。用户于 2026-10-31 明确指定：取回 Thread 负责取回后用 valid 打分，将比赛规则、重要数据和训练材料整理为 Chat 可读的包；独立 Chat 网关负责发消息和收回问题/指南。同日用户改选上传 ZYDTR 公开仓库、以固定链接供 Chat Pro 阅读并实测各阶段耗时。此分工不需要再逐次确认同一登记范围，实际任务仍须有明确 run、输入及输出身份。

## 成功结果

同一个 run 的原始预测、批准的 valid 真值、指标定义和评分器版本一一对应；结果可复算，失败/未定义指标不伪装为零。分析包包含当前比赛规则来源、用户确认的冻结条件、本地控制、相关数据、配置/代码/日志/模型证据、评分/诊断和材料缺口。本地交付有准确路径、范围和来源；公开分支还需共享端内容一致与真实读取证据。

当前唯一明确的取回执行会话为 `operation-ref-45108974a7afeca8`。它从宿主固定入口读取 valid，在本机评分；各算力主机训练和mini准备方的valid/test样本保持盲输入，可另接收任务级/分组级精确汇总评分与技术诊断；选模阶段保留valid，最终合训由用户另行决定。网关只能接收评分材料和交接回执，不因此取得重新评分、训练或服务器控制权。

## 评分身份与方法

- 当次 `SCORING_TASK.json` 登记 run/task 集合、预测路径及 SHA、原 valid/盲投影摘要、固定指标与评分器摘要、私有输出目录、允许进入分析包的字段。它把已授权范围具体化，不自行增加新训练或评分任务。
- 先核对任务、split、原行号、Drug_ID、Drug 和完整行数；重复/空 ID 按原行保留，不能仅按 ID join。拒绝漏行、额外任务、重复行身份、非有限预测、错误尺度/类别和非 valid 分区。
- 使用宿主审读固定评分实现，不执行准备 Agent 的 score.py、返回脚本、模型或 pickle。单任务严格覆盖该任务全部 valid，多任务严格覆盖本批登记集合，不补造其他任务预测。
- 可参考既有 `evidence-ref:ref-9353905f3c2e0f2d` 和 `evidence-ref:ref-00b264c607be28fe`。前者硬编码 22 任务/11735 行，不能原样用于 Caco2 单任务；新包装入口须审读并验证范围，评分公式仍使用固定实现。
- 按任务原指标评分，保留指标方向、定义、真值/预测/评分器摘要及覆盖率。AP 与官方 AUPRC 等价性、官方聚合公式未确认时明确写出，不发明官方总分。诊断指标与主指标分列；已用于调参的 valid 分数不是独立最终泛化证明，登记使用次数。
- 原真值和完整带标签记录仍存本机私有评分区；指定分析 Chat 可接收评分与问题诊断包，字段由发布清单明确列出。逐行残差/真值具有标签信息，不能通过改名当作无标签数据，也不能流入 OpenCode 或训练会话。

评分输出至少包括 `scores.json`、`validation-report.md`、`scoring-receipt.json`，以及存在且获准的逐行诊断；记录 `scoring_completed` 与 `scoring_verified`，不以取回成功替代评分完成。按[复用与职责](evidence-reuse.md)，未变固定评分器沿用已有数学验收，本次来源和全行身份由评分入口验证一次；主控据此审读新分数及异常，不例行再读全部真值复算全批。新增指标、代码变化、来源冲突或数值异常时定向独立核验，记录原因和额外标签访问。输入不匹配先保存失败回执，不修改原件凑齐。

## 发布归取回方，Chat 收发归网关

启用Pro外部研究时，既有方案使用 ZYDTR 公开 GitHub 仓库作为 Chat 阅读入口；本地完整归档为权威原件。首轮目标是既有 `ZYDTR/admet-benchmark-data` 的新增 `experiments/public-repo-20261031/`，不覆盖原数据。具体许可清单由当次任务和主控审读绑定；用户已明确授权这次公开发布，无须重复询问。保留提交 SHA 与固定版本 raw/页面链接，提供 START_HERE 和集中可读文本入口，不能依赖 ZIP 自动展开或链接自动递归。主控验收新增候选范围后才上传；取回方验证新增发布对象及核心入口与批准内容一致，复用旧固定commit的发布回执；这证明可取，Chat实际读取由网关另验。

将规则、重要数据、实际实验原件、评分和历史问题统一索引。核心可读入口用 Markdown/CSV/JSON，完整原件可另作归档；每一项给出来源、版本、摘要、用途、读取状态。不得仅放摘要后宣称 Chat 已看完整原件。大型文件依已核实的目标限制分包，保留整体和分件摘要，不能假定 ZIP 自动展开。

研究可用与全部大文件归档可以有不同完成时间，按本批问题的证据依赖判断；缺少相关原件时不得称该问题材料已齐。完整取回和已授权发布仍须完成，后续归档版本不得冒充原研究当时已读取。已知本批导航和研究补件随候选一并准备；网关可直接发送封好的Prompt全文，不额外上传Prompt作为必经步骤。发布方自行选择足以证明新增Git对象、实际公开正文及核心入口一致的方式，旧验证由下游继承，不能用抽样冒充未覆盖对象的逐字节验证。

材料发布清单只含本实验相关内容；不上传凭据、连接配置、无关个人/他人信息、整个工作区或私有带标签评分工作文件。科学源码、日志、配置等必要原件含基础设施信息时产生脱敏衍生件并保留源摘要映射；不能默默丢弃会影响质量的证据。已获准公开的数据以固定版本引用。权重的再分发须有许可依据，否则保留原来源/hash和未直接公开的限制。公开评分可被任何人读取，不能宣称对准备方实现技术保密。准备/训练可读取主控交付的精确汇总反馈；反馈须绑定run/task/split、指标/分组定义和评分回执，排除逐行valid真值、残差、查表答案以及可还原个体答案的分组或差分。若原分析包含受限逐行信息，另生成获准反馈文件及来源映射，不能整包转发。未来不同发布目标以当次用户授权为准，旧私有方案不再覆盖本次公开选择。

独立记录打包/脱敏、候选审读等待、上传、匿名读回，以及交接网关的 UTC 时间和单调耗时。传输量、复用量、重试与失败保留。共享端可读与目标Chat读取分开计时，没测到的阶段标未测。端到端当前试跑入口在 `evidence-ref:ref-6958fcac6f7d7a4f`。

封口后上传并读回核对，生成 `publication-receipt.json`：packet_id/version、清单摘要、目标位置/权限、每文件来源和持久引用、上传校验、Chat 实读状态、时间。取回方负责 uploaded_and_verified，网关在目标 Chat 中确认 read_verified；两者分别记状态。

取回方把完整评分/发布回执交给主控验收和网关收发，不直接给 Chat 发分析提示。网关后续完整取回 `analysis.md`、`issues.json`、`next_batch_guide.md`、`next_experiments.json` 、`review.json` 和 `search_space.json`；问题及指南在本地累积，主控提取获准的准备指南派给 OpenCode，保留来源映射。

## 已验证范围

v0.1真实海南取回通过。2026-10-31公开仓库首测中，指定取回Thread完成两run的Caco2 91行固定MAE，主控独立Decimal50和固定函数AST核验通过；393个批准文件已正常追加发布到固定commit，匿名逐文件大小/SHA读回和主控独立复核通过。证据见本轮control/publication-acceptance.json与acceptance/independent-scoring.json。该结论覆盖当前单任务、完成且稳定的两run和一次公开版本，不覆盖其他任务评分或长期增量发布。Chat实读/完整收回仍由网关和主控单独判定。

新增或修改的公开衍生件由取回方验证字节完整性和科学语义。JSON比较结构、数值和科学字符串，CSV核对原行与列值，代码只允许审读过的基础设施脱敏；不能将Markdown链接正则套入任意文本。未改且已验的公开视图引用原证据；主控审新增范围与实际脱敏风险，不再次逐叶全验所有旧视图。发布校验只覆盖新增/改变对象及新入口链接，旧固定commit的已验原件不重新全库下载。封口时的pending字样是历史状态，实际发布回执要明确固定commit及当前状态，不能为更新状态偷偷改已批准文件。
