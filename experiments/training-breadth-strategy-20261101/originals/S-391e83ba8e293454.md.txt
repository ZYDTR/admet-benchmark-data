# 复现材料与范围

## 两种不同的验证

推理复现：固定 checkpoint、输入和推理程序，重新产生预测。训练复现：依据允许的原始数据、初始化、代码、环境与配置重新训练，再检查模型指标和预测。报告必须写清执行了哪一种；当前交付没有进行真实比赛训练。

## 工程证据包

`bundle` 只从 completed run 的固定范围打包，核对文件哈希，包含执行计划、配置与代码快照、日志和声明产物。原始官方数据与个人凭据不包含在包中。缺失或修改过的产物阻止打包。训练和推理 run 分开保存，推理记录链接其训练来源。

复核者通过官方途径取得同版数据，在目标环境构建/取得已审查镜像，再使用记录的代码与配置重跑。镜像 ID 不能单独重建软件环境：模型接入时应补齐依赖锁定、构建文件、软件版本和必要的硬件说明。

## 已知限制

源文件哈希和运行日志是可检查证据，不是不可伪造证明。默认本地执行器防误用，不能阻止有完整宿主权限的操作者修改全部文件。不同框架/设备的数值一致性要依据官方最终要求确认。不能把本项目的工程检查或 synthetic demo 当成赛事复现通过。

官方公开页目前要求入围交源码复现，没有公开逐项强制材料或误差范围。本项目的包是团队准备方式，收到正式审核要求后由 competition-contract 技能核对差异。
