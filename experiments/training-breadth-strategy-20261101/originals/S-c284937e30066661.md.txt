# 训练排障：从现象找到最小检查

用途：曲线异常、模型学不动、验证不稳定、指标突变或训练崩溃时读取。下表提出的是候选解释，不是自动诊断规则。证据不足就保留多种解释。

## 先准备能回答问题的观测

至少保留逐任务训练/验证指标、有效标签数、训练损失、学习率随 step 的变化、checkpoint 选择依据、运行时间与失败日志。梯度范数、参数变化、预测分布、显存和输入吞吐量按故障需要补充，不要求每个 batch 记录全模型。

比较 train 与 validation 前，使用一致的标签、变换、指标和评价模式。在训练样本上单独用 eval 模式计算诊断指标；不要把含 dropout、增强或正则项的训练目标与不含这些项的验证损失直接相减后宣布过拟合。每次推理仍应正确切换模式。[S1]

## 现象 → 替代解释 → 检查 → 下一步

| 观察到的现象 | 常见解释，均需核验 | 优先检查 | 可能的下一步；不能据此断言什么 |
| --- | --- | --- | --- |
| 小训练子集损失也不降 | 学习率不合适、没有更新、标签/输出错位、掩码错误、表示不可区分冲突标签 | 检查梯度与参数实际变化、目标/输出形状、样本映射；关闭非必要正则 | 先修复链路，再做少量学习率诊断；不能直接断言架构不行 |
| NaN/Inf 或大幅损失尖峰 | 非有限输入、非法变换、数值溢出、学习率过大、空标签批次的除零 | 定位首次异常 batch、输入/目标/掩码、loss 分母与数值精度 | 根因明确后再试学习率、warmup、裁剪或精度调整；不要只用 nan_to_num 掩盖问题 |
| train 很好，validation 先好后坏 | 过拟合、标签噪声、训练验证分布差异、评价模式错误 | 同口径曲线、早期最佳 checkpoint、样本结构/标签分布 | 试早停、正则、容量或任务组织；不能仅凭差距断言某个原因 |
| train 与 validation 都差 | 优化不到位、表示不足、正则过强、噪声大、目标/指标错配 | 小子集诊断、训练时长与学习率、简单对照、标签语义 | 据证据选择训练策略或表示实验；不能机械加深模型 |
| 不同种子差异大 | 样本少/正类少、优化不稳定、早停敏感、数据顺序差异 | 同划分重复的逐任务结果、正负样本数、曲线、实际种子设置 | 先改善稳定性或补充确认；不能挑最好种子代表通常性能 |
| 总 loss 降，个别任务退步 | 大样本任务或大尺度损失主导、掩码/权重错误、负迁移 | 每任务有效数、loss 与权重、分组/单任务对照 | 调整任务归一化/权重或组织；总 loss 不是每个任务的成绩 |
| 改动后分数突然大涨 | 真正改进，也可能是泄漏、切分变化、指标口径改变或错位 | 数据/划分/标签/评价版本、预测键、是否误用真值或缓存 | 先审核可比性再确认收益；异常高分不是自动成功 |
| 训练更久验证仍明显进步 | 预算或调度尚未覆盖收敛区间 | 最佳 checkpoint 是否总在末端、实际学习率与步数 | 在预算内延长并复查调度；不能仅把 epochs 变大而忽略已衰减至极小的学习率 |
| OOM、超时或吞吐很低 | 分子大小分布、批处理、缓存/I/O、模型容量或机器负载 | 失败 batch 的图规模、显存峰值、数据加载/计算耗时 | 优化资源配置；batch 改变需记录实际更新数并复核学习率；不能判定科学路线失败 |
| 训练中指标不错，重载预测变差 | 错 checkpoint、模型模式/特征/scaler 不一致、任务列错位 | 对同一合法验证样本比较重载前后输出和变换状态 | 修复 train/predict 一致性；不要重新大规模调参 |

数值不稳定的诊断参考 Google FAQ；预算与调度的关系参考 number-of-steps。[S2][S3]

## 小子集拟合检查的正确用法

从已准入的训练分区选择一个很小且目标有效的子集；子集大小以能快速定位问题为准，不绑定万能数量。先移除非必要增强与正则，确认输出语义、损失与更新链；诊断预算明确，产物标为 diagnostic。

对于给定表示完全相同却标签冲突的样本，确定性模型不能同时拟合两种答案。对不可约噪声、损失固有下界、饱和数值等，也不要求“loss 必须精确为零”。无标签的任务/批次不能凭空产生监督信号；跳过或采用有定义的归约规则，避免把空均值变成 NaN。[S1]

核对损失函数期望的输出类型。例如 PyTorch `BCEWithLogitsLoss` 内部包含 sigmoid，应接收未做 sigmoid 的 logits；不能先压成概率再作为 logits 送入。输出形状的意外广播、列顺序错位或 mask 后分母错误，同样可能让代码正常运行却训练错误。[S4]

只在 train 上进行这个诊断，不拿 validation 或测试数据反向传播。通过检查后恢复原先声明的正则、训练与评价设置；诊断配置不是最终配置。

## 如何读曲线而不被曲线骗

- 曲线同时标注 step/epoch 与 wall time；不同 batch 或图大小下，epoch 相同不代表更新次数/成本相同。
- 记录原始数值，平滑曲线只辅助阅读；不能以平滑后的小差异替代证据。
- 训练目标与评判指标分别展示。例如分类交叉熵下降不保证 AUROC/AP 同步提高。
- 记录 best 与 last checkpoint 的区别。提前决定选模指标、方向、评价频率和早停规则；别在多个指标中事后挑一个最有利的解释。
- 少样本任务上指标会跳变。先看有效样本及类别计数；无定义指标按 [评价约定](evaluation.md) 保留原因，不填零。

## 排障完成的判定

保存能复现故障的最小证据、修复动作及修复后的同条件检查。将程序错误与模型无收益分开登记。先读 [比较契约](run-comparison.md) 再解释两个 run 的差异；工程失败时保留 failed run，不覆盖旧产物。
