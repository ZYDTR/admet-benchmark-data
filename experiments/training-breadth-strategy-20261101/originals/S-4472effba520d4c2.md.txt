# 海南算力服务器：project-owner 工作区

类型：API Guide / Workflow。创建：2026-10-30；更新：2026-10-31。写作依据：[Best Practice skill writing](../bestpractice_skill_writing.md)。

## 目标与最高约束

在已验证的 private-compute 上完成用户**明确交代的当次任务**，全部项目改动及副作用收敛在 `<AUTHORIZED_PROJECT_ROOT>`，不影响其他人的文件、服务和作业。**保护目录外环境的优先级高于完成任务。**

涉及这台机器的连接、资源查询、文件读写、上传下载、模型接口排查、执行、训练和清理，必须先加载本 Skill；其他 Skill、脚本、API、后台任务、经 Windows 间接执行均不能绕过它。普通“连接一下”“看看”“排查”“继续”默认只读。本 Skill 不授予服务器通用管理权限。

**授权只限当前任务。** 明确要求在 project-owner 内创建或修改某个内容，才可做对应改动；过去创建目录、提供密码、共享账号、其他机器的长期权限均不构成后续写入授权。明确任务也不授权目录外改动，不能把“修好”“跑通”“都同意”解释为解除本边界。

**可用算力约定（用户明确补充，2026-10-30）：已有训练任务授权时，可直接使用确认空闲的 GPU；已被他人使用的 GPU，若剩余资源足够且经核验不会影响现有任务，也允许共享使用。并行数由实际资源决定，三路只是例子，不是额度或上限。无需逐卡、逐作业重复询问，也不以另行预留、部署训练网关或 OS 沙箱为一概禁止启动的前提。** 具体选卡、共享条件和并发按下文验收；这个约定不把单纯连接、检查或修改 Skill 的请求变成训练请求。

## 不可越过的边界

| 范围 | 硬约束 |
|---|---|
| 默认读取 | 可读 project-owner 内与任务有关的内容，以及必要的机器身份、CPU/内存/磁盘/GPU、监听端口等系统元数据。目录外同事的项目、配置、日志、历史和凭据不属于默认可读内容；需要时先取得对应只读范围。不能全盘搜索或借共享账号翻他人数据。 |
| 唯一写入根 | `<AUTHORIZED_PROJECT_ROOT>`，大小写固定。创建、编辑、上传、解压、下载、安装依赖、日志、缓存、临时文件、checkpoint、产物和清理均受此根约束。`<PRIVATE_RUNTIME_PATH> 是历史同一数据路径，但操作统一用规范路径，不能把整个 `<PRIVATE_RUNTIME_PATH> 当工作区。 |
| 路径与文件身份 | 写之前核验根及目标的真实路径；目标须等于根或为其真正后代，不能用字符串前缀判断。检查已有祖先、符号链接、硬链接和实际挂载：拒绝经链接/绑定挂载写到目录外，拒绝修改 `st_nlink > 1` 的已有普通文件。解压/同步拒绝绝对路径、`..`、链接和特殊文件；不用 `--delete` 波及共享父目录。不能靠 `cd` 或 `chroot` 字样宣称隔离已成立。 |
| 环境与隐式写入 | 禁用用户启动脚本、自定义插件和自动更新等非必要副作用。Python 使用 `-B`；缓存、临时目录、包管理器、下载器、JIT/扩展编译、训练框架及跟踪日志的实际落点均须在 project-owner 内。共享 `~/.cache`、`~/.local`、`/tmp`、`/dev/shm`、全局 Conda/venv 等不在写入范围；需要写这些位置的程序先停下，采用经验证的私有路径或隔离运行方式。禁止 `sudo`、全局/`--user` 安装、修改 shell profile、SSH、系统配置或外部文件权限。 |
| 服务与网络 | **绝对不停止、重启或杀掉他人的服务、进程和作业，也不通过重置 GPU、释放端口腾算力。** 不修改防火墙、端口转发、Tailscale/Headscale、sshd、systemd、计划任务、Docker/容器或共享模型配置，不改监听地址或部署常驻服务。8001 不通也不能顺手重启别人的 GLM。可按任务授权启动、查询和停止本次有身份记录的自有训练作业。使用既有 Windows 通道，不写 Windows 文件、不改它的服务/网络；不影响 Air、小美或 Mac 的入站保护。 |
| 共享资源 | 未有明确计算任务时不发推理/压测请求、不加载模型、不跑训练。已有授权时，可选空闲 GPU，也可使用满足下文不影响他人条件的共享余量；预算同时考虑显存、GPU 计算/带宽以及整机 CPU、内存、磁盘/IO。遵守现有调度、预约及独占规则；没有此类机制时，不凭空增加管理员分配前置条件。`CUDA_VISIBLE_DEVICES` 只选卡，`nice` 不能限制 GPU 算力，均不证明共享无干扰或 OS 隔离。 |
| 他人文件 | **绝对不删除、覆盖、移动或清理他人的文件、目录、环境和缓存。** 即使磁盘不足、训练失败或文件属于同一 `private-compute` UID，也不能动用他人的数据来腾空间。只处理本次任务在 project-owner 内明确创建并记录身份的产物。 |
| 异常与清理 | 临时连接/认证异常按下文有界恢复，不因单次失败终止整个任务。真实文件权限拒绝、身份/路径漂移、目录消失或影响范围不明时，阻断相关写入；OOM仅处理自有作业，未知任务状态先查询原作业。不得为了恢复或回滚越界；清理/取消只限本次明确创建且有身份记录的目录、文件或作业，不按共享 UID、进程名或宽泛通配符处理。 |

同一 `private-compute` UID 能触及别人的文件，**project-owner 目录及本 Skill 是执行约束，不是已部署的 OS 安全沙箱**。宿主操作方须审阅实际运行代码、命令及写入路径；资源预算、选卡和运行监测也不能声称绝对零资源影响。未知代码或副作用无法核实时，先解决具体缺口；没有 OS 沙箱本身不阻止宿主执行已审核、符合上述边界的授权训练。若任务确实需要独立账号、受控队列、容器或配额，由管理员准备，不能自行修改目录外系统。SSH 服务本身的登录审计等系统行为不等于项目取得了日志写入/清理权限。

## 可用 GPU、共享余量与并行训练

“可以用”须来自当前占用证据。连接后结合 GPU 索引与 UUID、显存使用、利用率和进程/作业归属判断，必要时读取现有调度或预约状态。利用率低但仍有他人进程、模型驻留或预约的卡应记为占用，再判断是否满足共享条件，不能直接当空闲，也不能仅因有进程就一概禁用。查询失败、归属不明或指标异常记为 `unknown`，不推定余量可用。共享 UID 不能证明一个进程属于自己的任务，只读取判定所需元数据，不翻同事项目内容。

空闲与设备健康分别验收。候选 GPU 的同一 UUID 还须有当前只读健康证据，例如 `nvidia-smi -i <UUID> -q` 中的 `GPU Recovery Action`、设备错误及计算模式；显存和利用率均为 0 不代表可用。出现 `Reset`、`Reboot`、`Drain P2P`、`Drain and Reset` 等恢复要求时，不向该卡提交新作业；字段缺失或查询失败不能记作健康。此时按既有任务授权核验其他卡或停止并报告，不自行 reset、重启驱动、重启机器或停止他人进程。恢复由获授权的管理员处理。首次 CUDA 初始化失败时，先核对健康状态、原始错误和本作业限制，再决定有依据的任务内修正；不能反复绕开拒绝或只改库补丁而忽略设备状态。

共享使用的前提是有证据支持不影响现有任务。不能仅看一次剩余显存或低利用率：结合有代表性的时段观测、已有任务的峰值/突发需求及可读的性能指标，给对方保留余量，并估计自身峰值显存、计算/带宽、CPU、内存和 IO 需求。现有独占/预约规则或无法判断的突发需求都不能当可借余量；证据不足时换卡、降低并发或排队，不拿他人的运行服务做探测性压测。优先使用已有可用的分区、配额或共享调度能力，但不能为此重配置他人的设备或服务；没有这些机制并不自动禁止共享，须明确实际可执行的自有负载控制、监测与退出条件。

资源检查与启动有先后依赖：初选后在实际启动前复核候选卡，避免沿用旧快照。满足空闲或共享条件即可使用，不必让用户逐卡批准；这项判断不等于技术上锁定了资源或保证永久零干扰。共享作业应从经过预算的低负载开始，检查自身峰值及现有任务可观察的延迟、吞吐、排队等指标是否仍在既有正常波动或服务目标内；没有足够证据排除影响时停止共享。出现可归因于本任务的退化、对方资源需求上升或冲突，只缩减、暂停或停止自己的相关作业，必要时换卡或排队，绝不调整或停止对方作业。

并行数由当下资源和任务需求决定，**没有固定为三路的额度或上限**。可一任务一卡，也可在满足上述共享条件时多个任务同卡，包含与他人任务共享；逐作业及合计峰值预算都须可承受。优先使用足够的空闲资源，资源不足时自动降低并发或排队，不能为凑并行数抢占。

每个作业明确绑定所选 GPU（保存 UUID 与索引映射），分别使用 project-owner 内的代码/输入、输出、缓存、临时目录和日志，避免框架默认占用所有卡。记录任务 ID、PID/进程组与启动时间，设置任务合适的 CPU 线程、数据加载进程、内存需求、时长和输出预算；已存在的可用限额机制应使用，并区分配置目标与实际强制限制。启动后核验实际 GPU/PID、显存和整机负载，运行中根据自身用量调整并发。异常恢复与取消只作用于身份匹配的自有作业，不按共享 UID、`python` 进程名或整个 GPU 清场。

依赖安装和首次导入也属于执行边界。设置 `TMPDIR`、`HOME` 或数据加载进程数为 0，不足以覆盖库的隐式写入；首次运行前须审读相关行为或采用可核验的任务内限制，结果用实际写入证据验证。已知 joblib 的导入探测可创建 `/dev/shm` 信号量；不需要多进程时可在导入前设置 `JOBLIB_MULTIPROCESSING=0`，并验证本次完整依赖导入无越界。这个开关不代表其他库也安全。Landlock 等限制是可选实现，其 CUDA 兼容性和覆盖范围须实测，不能把它写成通用训练前置条件，也不能将未成功的辅助库补丁当作标准方案。每次失败及修正各留独立编号、启动前快照和退出证据，不覆盖上一尝试的 `prelaunch` 等记录；短暂越界后自动删除仍计为失败。

## 临时连接失败与自动恢复

用户于2026-10-31明确要求：偶发拒绝不应终止后续自主训练流程。固定路由、账号、凭据来源和严格主机密钥不变时，连接超时、重置、短暂不可达，以及已登记凭据的一次 SSH 认证拒绝，可以自动退避重试连接和只读检查，无须每次询问用户。`Permission denied` 必须区分 SSH 认证与远端文件权限；不能仅凭退出码255就重试所有操作。主机密钥变化、主机/UID或路径不符、凭据文件异常、明确账号锁定/失效及真实文件拒绝不属于暂时性重试。

固定只读客户端默认每轮最多4次，失败后分别等待2、5、10秒，原有单次超时保持。恢复后重新确认身份及必要的环境/资源检查，成功即继续原授权任务；仅连接重试成功不等于全部前置检查成功。每次失败、退出码、退避和最终结果都保留并脱敏，不能由末尾成功掩盖曾失败的阶段。

重试用尽时保存 `waiting_for_connection`、当前 run/阶段及原作业身份；不把尚未执行的训练判为失败，不丢弃进度。若已有获授权的持续执行机制，至少冷却5分钟后从只读连接检查恢复；持续不恢复或需要用户处理时才通知。没有持续执行机制时如实报告等待状态，不暗示会自行唤醒。这不授权额外训练、扩大参数搜索或新建自动化。

只读恢复与写入重放分开：连接失败时阻断依赖写入/启动，但允许恢复检查继续。上传、部署或训练启动若已发出而响应丢失，先用同一 run、启动锁、PID/启动时间、退出记录和产物摘要查询原操作；确认未执行或满足既定幂等条件才可恢复。已有作业继续观察，不能另起一份。不要把通用 SSH 执行函数整体套上自动重试；只读客户端的重试也不替任意训练 launcher 提供幂等保障。

## 可用入口

机器、凭据位置、双层主机密钥与真实故障见 [连接基线](references/connection.md)。不复制密码到 Skill、命令参数、输出、证据或远端。

附带的 [只读连接脚本](scripts/read_only.py) 只有三个固定动作，无任意命令、目标或路径参数；默认只读身份核对：

```bash
python3 -B <LOCAL_WORKSPACE>/rules/skills/hainan-compute-access/scripts/read_only.py
python3 -B <LOCAL_WORKSPACE>/rules/skills/hainan-compute-access/scripts/read_only.py resources
python3 -B <LOCAL_WORKSPACE>/rules/skills/hainan-compute-access/scripts/read_only.py workspace
```

`identity` 验证主机、UID、project-owner 目录；`resources` 读取一次有界资源快照；`workspace` 只列 project-owner 第一层的最多 200 项元数据，不跟随链接、不读正文。CLI通过 `query_with_retries(action)` 仅对这些固定只读查询执行上述恢复，并返回 `retry` 回执；底层 `query(action)` 仍为单次查询。`resources` 当前不返回 GPU 进程归属、预约或健康/恢复状态，选卡还须按本 Skill 补充必要的只读查询，不能仅凭该快照判定可用。脚本不会建目录、修连接配置、启动模型、改变权限或安装依赖。缺依赖则返回错误，不能自动安装或切换机器。

需要这些动作以外的操作时，仍由本 Skill 约束：先明确本次目标与已有授权，再审计实际命令及其路径/资源/网络副作用。脚本不提供通用 `exec` 或“允许写入”开关。新增任务专用实现不能替代这里的边界，也不能直接交给持有共享凭据的实验 Agent；ADMET 作业还须遵守其 [远端作业规范](../../../adhoc_jobs/admet_sap_setup_20261029/remote-execution/SKILL.md)。

## 验收与输出

- 连接成功有严格主机密钥验证、`private-compute` / UID `1012` 和真实 project-owner 根的证据。只连通 Windows 或看到端口不算登录成功；身份/主机密钥变化必须停止。
- 只读任务：返回请求的事实、采样时间及具体原始错误，无人为发起的远端文件/服务变更；读取失败记 `unknown`，不能记成无占用或无故障。资源快照不是预留。
- 写入任务：记录当次明确授权、根内精确变更清单和验证结果；运行前已确认全部写入及副作用的边界，运行后核对任务文件与自身进程/资源结果。无法核验目录外影响时标记未通过，不能以“在目录里运行”替代验收，也不为验证而全盘扫描别人文件。
- 训练任务：有启动前的资源与占用证据、选定 GPU UUID/索引、任务级及合计峰值预算、实际并发理由；共享时另记对方需求余量依据、正常性能基线、可执行负载控制和退出条件。启动后实际 GPU 与 PID 符合记录，输出均在 project-owner 内；N 路并行须分别查询 N 项自有作业及合计用量。持续保留共享影响观测；没有符合条件的空闲或共享余量时排队/降并发。结束记录退出码、产物和自有资源释放情况，不能以进程启动代替训练完成。
- 交付简述实际结果、改动、证据和未验证项。需留证时，在本机 `contexts/infrastructure/hainan_compute_YYYYMMDD_<主题>/` 保存脱敏 JSON；远端必要记录只在 project-owner 内且须包含在任务授权内。不要为了状态询问额外在服务器写回执。

回执最少包含 `observed_at`、`request`、`authorization`（只读或明确写入范围）、`target`、`workspace`、`checks`（pass/fail/unknown）、`changes`、`resource_budget`（未运行则为空）、`outside_scope_changes`、`limitations`。计算任务另含 `resource_observations`、`jobs`（任务 ID、GPU UUID/索引、PID/启动时间、目录、状态与退出码）及实际并发。没有审计证据时将目录外影响记 `not_verified`，不能臆造完整系统零变更证明。

## 已验证事实与陷阱

- 2026-10-30 通过新凭据和固定主机密钥成功登录；17:23 仅按用户要求创建 project-owner，属主 `private-compute:private-compute`、权限 `0775`。不是独立 Linux 账号，也没有资源预留。
