# 结果导向的 Skill 写作

## 目标

让没有历史上下文的 Agent 找到所需规范，并自行判断任务是否完成。

## 验收标准

- 先检查 [唯一索引](../INDEX.md) 是否已有相近能力；优先修订现有技能。
- 技能有一句目标、独立可判断的验收、可用资源与边界、输出格式/位置；方法保留推理空间，只固定确有依赖的顺序。
- 触发描述包括真实任务意图及边界，索引能到达技能；背景细节按需引用，不复制整份赛事规则。
- 缺数据、工具不可用、证据冲突时仍能给出准确状态与可继续的工作。
- `check-context` 通过；新增/改变路由用一个没有前情的 Agent 完成实际任务，记录读取链和结果。关键词匹配测试不能代替此项。
- 经验只来自真实结果。可写风险分析，但不能把尚未发生的假设写成既往踩坑。

## 资源与边界

设计依据见 [参考来源](../../docs/sources.md)，上游是 grapeot 的 Best Practice Skill Writing 和 Project Scaffold。本项目不照搬作者个人偏好或工具权限。按 [验证策略](../../docs/test.md) 设计任务；给执行 Agent 原始任务和入口，不泄露预期路由或修复结论。

元数据使用两项单行字段 `name` 与 `description`；name 和目录保持一致。局部技能保存在 `skills/<name>/SKILL.md`，只通过一个根入口暴露给宿主。对检查器而言保留本文件同样的四个中文章节名，内容结构可按任务调整。

## 输出

技能文件、更新后的 INDEX、必要资源、验证证据及任务交接。结果写入 `docs/validation.md`，不得用未执行的测试凑通过数。结构检查预算是上限，目标仍是删除对完成任务没有帮助的内容。
