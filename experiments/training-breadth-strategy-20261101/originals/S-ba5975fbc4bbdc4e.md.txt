# 数据准入边界

## 官方规则与团队默认

[赛事契约](../competition/contract.json) R01 明确禁止其他外部数据。2026-10-30研究时，用户已明确转述赛方确认：外部预训练权重可用，但必须冻结。该规则作为user_confirmed记录，不再统一禁用冻结权重。具体checkpoint、许可、附加资产与全程冻结仍需核验；外部拟合参数、教师分数和额外样本不能从这条确认自动获得许可。

当前执行器仍只支持random初始化和官方原始输入，尚未实现冻结资产加载、审计与缓存复用接口。政策澄清不代表接口已经完成；接入需harness-development做明确扩展，不通过伪造资产类型或放开网络绕过边界。只读研究与数值基线设计可以继续。

查算法论文或 API 文档不会自动变成新增训练样本。用外部服务给官方分子补标签、输入外部分子嵌入、加载外部模型或归一化参数，则改变模型输入或初始化来源，必须审查。研究笔记、网上代码中的常量和配置同样可能携带这类信息。

## 准入材料

原始文件放入 `data/official/` 时记录来源、下载时间、角色、SHA-256、文件说明和审查者。用户已提供GitHub数据，固定commit与67CSV审计见 [研究数据画像](research/2026-10-30/data-profile.md)；该研究快照尚未登记成正式manifest。可以根据实际下载记录接续准入，不需重新从零寻找数据，也不能用本项目规则说明冒充下载证据。程序只验证声明与字节一致性，不独立认证数据合法性。

配置 schema 见 [runtime contract](runtime-contract.md)。所有未接入输入保持 pending。当前示例不能靠把 status 改成 approved 获得有效数据，缺失文件、证据和标签仍会阻塞。

## 派生数据

首版执行器只接收官方原始输入。特征、词表、标准化器和缺失掩码在审查后的适配器内生成，记录父输入、代码版本和拟合数据范围；保存在该 run 的产物中。独立派生缓存的复用接口尚未提供，不能将缓存标为 competition_official 来绕过来源契约。

首版正式训练入口要求独立的train与validation文件；本轮用户快照实际有每任务train/valid/test三个文件，结构已确认。后续版本若只给一个标注文件，再增加有父输入和划分证据的分区接口，不能复制同一文件冒充两个角色。标签单位与历史变换未确认的部分仍保留，但不妨碍原Y的基线设计；当前正式执行器的标签门槛需由明确数据契约满足，不能改状态绕过。

## 缓存与镜像

HF_HUB_OFFLINE 仍可读取已有缓存，所以每次运行使用独立 tmpfs 缓存，并审查镜像与适配器是否预置权重、拟合参数或数据。镜像哈希只固定内容，不能证明内容合法。镜像构建阶段可下载批准的软件依赖，不能顺便预下载训练资产。依赖与模型数据分开审查。

## 发现误用时

标记受影响的 run；保留记录；追踪派生特征、参数和 checkpoint 的依赖；从允许的输入重新生成受影响的结果。已提交且确认受影响的情况由参赛负责人依据官方要求处理。Agent 不替用户发送说明或操作赛事平台。

## 当前已观察的来源提示

Chemprop 文档明确说明某种 descriptastorus 归一化使用 ChEMBL 分子拟合的参数；使用相关功能前核实政策。此处是已核实的工具特性，不是“本队曾违规”的经验记录。来源见 [sources](sources.md)。
