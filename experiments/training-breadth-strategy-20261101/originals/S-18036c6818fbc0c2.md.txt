# 搜索、比较与选模：给每一轮一个预算和结论边界

用途：要扫参数、比较架构、扩大探索、确认微小收益或挑最终候选时读取。先满足 [比较契约](run-comparison.md)，不能靠更多 trial 补救不可比的结果。

## 1. 一轮解决一个主要问题，不是只能改一个数

声明本轮三类变量：[S1]

| 类别 | 例：比较 Atom 与 Bond message passing | 处理方式 |
| --- | --- | --- |
| 研究变量 | Atom / Bond 实现 | 是本轮要比较的差别 |
| 配套变量 | 学习率，必要时正则/调度 | 各方案在同样预算原则下分别调整；不靠一个有利于某方的默认值定胜负 |
| 固定条件 | 实际验证样本、标签、评价、输入特征定义、选模规则 | 同轮保持一致；变化需另立对照并限制结论 |

单因素对照适合定位一个变动。参数有交互时，用小型联合搜索或显式消融；所有变量一起改也可以用于寻找完整方案，但那只能支持方案比较，不能归因给某一部件。一次研究不需要探索所有可能参数。

## 2. 先做少量合理点，再决定是否扩展

固定一个可用基线。优先把会使模型完全学不动的设置调到合理范围，再投入结构搜索。正的尺度参数（如学习率）通常适合在数量级上探索；零正则作为单独分支，不放进对数采样。

多维空间可用有限随机/准随机搜索；它是实用起点，不是每个任务必胜的算法。[S2] 一两个离散选项可以直接列举，不必为几次运行引入优化平台。贝叶斯搜索也需要可信目标、适当搜索空间和预算。

若最佳点贴着范围边缘，检查是否值得向外扩展；若所有点不稳定，先排障；若均无可辨收益，缩小问题或暂停。不能只因“还有参数没试”就无限续跑。

## 3. 公平是什么，必须提前说清楚

选择比较目标：固定 wall time / GPU 小时下谁更好，还是合理充分训练后谁更好。两种问题可能有不同答案。记录每条路线的 trial 数、总成本、参数量和推理成本；相同 epochs、hidden size 或 seed 不自动意味着公平。

同一轮使用相同的真实验证样本与标签，而非只核对同名 split。对架构合理调配套参数，但不允许获胜者独享大量追加搜索而隐去成本。明确分别报告“单一配置比较”和“各方案调优后比较”。

## 4. 短跑筛选后要让候选完成应有训练

短跑可用于检查实现、稳定区间与明显不可行的资源配置。若使用提前淘汰，记录规则、最少训练资源和不同架构收敛速度的风险；早期差不能直接证明最终差。[S3]

增加训练预算要复查学习率 schedule、warmup、早停与 checkpoint 选择。候选应在目标训练预算下重新比较。不要将调试子集或极短训练的排名写成完整数据上的架构结论。

## 5. 确认收益，不把“最高的一次”当作事实

每个候选和基线用同一评价约定复核。必要时用预先选定的多个种子重新训练，报告每次结果、均值与离散程度。3 个种子可以是资源有限时的初步检查，不是统计显著性的自动门槛；不同架构同 seed 也不意味着初始化或随机轨迹严格配对。

种子重复主要检查训练随机性，不能证明对验证样本的选择不敏感。独立留出的确认集、预先声明的额外划分或适当的交叉验证可补充这种证据，但必须遵守官方数据约束并承认成本。bootstrap 等不确定性分析要尊重分子/骨架分组；不能把高度相关样本当独立样本随意计数。

长期用同一 validation 决定改动，会对 validation 本身产生选择偏差。[S4] 团队共享搜索记录；如有确认集，事先约定用途，不反复窥看后继续调参并仍称其未用。官方测试不参与拟合；线上分数也不能被无限当作无偏反馈。

收益小、波动大时写“不确定”。成本显著上升时明确性价比。没有官方聚合公式就按逐任务结果与提前声明的本地选择规则决策，不能倒推一个对当前赢家有利的总分。

## 6. Agent 的停止与升级规则

- **立即暂停正式运行**：数据/标签/评价契约不明确，来源不满足要求，或疑似泄漏；保留证据并转对应技能。
- **停止当前 trial 并排障**：数值异常、不可恢复资源错误、预算触顶；失败不等于该架构无效。
- **结束本轮**：已回答问题、达到预设停止条件、预算耗尽，或继续试的价值低于确认候选/修复流程。
- **追加探索**：写出新证据、下一问题和剩余预算；在已有授权范围内继续，不为每次低风险 trial 反复询问用户。
- **收敛到交付**：预留实际够用的重训、推理、导出和复核时间；先测运行耗时，再排资源，不臆测可以扫完整个空间。

预算至少包括最大 trial 数、每次最大时长/资源、总预算和截止点。没有预算时先完成计划与成本估计，不能默认开启无限自动搜索。本文是 Agent 的工作规范，Harness 尚未实现自动搜索调度器或这些预算的统一强制执行；实际执行边界仍看 [运行契约](runtime-contract.md)。
