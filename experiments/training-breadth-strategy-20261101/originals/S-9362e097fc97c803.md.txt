# ADMET 冻结底座训练

类型：Workflow。创建：2026-10-31；更新：2026-11-01（控制面复核；旧冻结任务不变）。写作依据：[工作区 Skill 写作标准](../../../../rules/skills/bestpractice_skill_writing.md)。适用主控或用户本次明确授权的宿主执行会话；准备 Agent 不因此获得训练或服务器权限。

## 目标与入口

把已批准的数据、固定底座和新预测模块变成可复现的训练产物，并以真实执行证据证明底座没有更新、数据身份完整、资源和文件边界得到遵守。启动进程、输出 loss 或模型自报成功均不构成交付。

唯一项目入口是 [admet_training/AGENTS.md](../../AGENTS.md)，由它路由 `policy.json`、规则来源映射、输入和各 run；不复制一套会漂移的赛事规则。外部预训练权重必须冻结是用户确认的参赛条件。旧 Harness 的随机初始化、固定本机 Docker 或未部署网关不能冒充赛事要求。

海南上的一切操作另须完整读取 [hainan-compute-access](../../../../rules/skills/hainan-compute-access/SKILL.md) 及命中的连接参考。固定主机、经 Windows 路由、project-owner 唯一写入根、他人服务和文件保护均不可放宽。已授权任务可核验健康空闲卡或符合不影响他人条件的共享余量后执行；不因过去失败要求用户重复批准同一范围，也不把一次单作业授权扩成参数搜索或并行实验。

## 不可变的训练条件

- 外部底座 `requires_grad=False`、`eval()`，编码无梯度；优化器参数集合只含获准新模块。训练前后内存中所有参数和 buffer 的摘要相同，磁盘权重摘要也相同；新头须有有效优化步和实际参数变化；梯度应有限，整体存在非零梯度，不要求每个参数、每一步都非零。仅检查 checkpoint 文件没变不够。
- 当前入口只以官方 train.Y 学习；在官方 train 内划分拟合与内部验证部分，后者用于早停。执行端的 valid/test 只含 Drug_ID、Drug，不读私有标签、不做教师补标签或 test 拟合。官方 valid 可调参与本地标签隔离是两件事；本轮授权没有评分就只交付预测。
- 原始任务、分区、行号、ID、SMILES 和行数全保留。空 ID、重复 ID 不能被字典覆盖；未经授权不清洗、去重、改标签。标准化只在内部训练部分拟合，保存转换和划分，预测还原原 Y 尺度。
- 每次 run 有独占目录和当前规范版本的 PLAN，记录输入/权重/代码/依赖摘要、超参数、GPU 与预算。先通过项目 `scripts/check_plan.py`；历史计划规范摘要失效时新建获准版本，不能回写旧计划制造一致。计划通过不是运行成功。
- 从首次导入开始控制全部缓存、临时文件、编译、日志和安装路径。只用审核过的私有环境；复用旧自有环境时只读使用，不修改其依赖。导入前禁用不需要的 joblib 多进程探测；只设 TMPDIR 或 workers=0 不够。
- 候选 GPU 必须同时通过健康、占用和任务预算检查，实际启动前复核；Recovery Action 要求恢复的卡不能接新任务，绝不自行 reset 或动别人作业。只在本任务身份匹配时缩减、取消或结束自有进程。

## 可用实现与选择

本项目训练执行Thread固定为 `gpt-6.1-sol/xhigh`，与专职算力观察Thread分开。每次训练先消费[资源日志](../../resources/hainan/README.md)的最新观察及时间/UUID；15分钟以上、缺失或unknown时可自行查询。实际启动前始终直接复核健康、占用和预算，并保存所用观察ID及启动前原件。观察不预留卡、不替训练执行、不扩大PLAN额度；详见[资源观察合同](../hainan-resource-observation/SKILL.md)。

[已实测参考及证据](references/validated-run.md) 给出 CheMeleon/Caco2 的代码、环境、冻结检查、带边界的 CUDA 预检查和运行记录。它是一项固定配置的可审阅实现，不是可无修改重放的通用 launcher。新任务登记自己的 run、GPU UUID、输入、预算与幂等启动身份；不能把参考脚本的旧目录、旧卡号或完成锁直接复用。

合理的效率优化是复用已核验的私有环境、在同一固定编码器/特征配置下缓存编码结果、只训练轻量新头。缓存身份至少绑定权重、特征实现/配置、任务/分区、完整输入摘要、行序、dtype/维度和解析掩码；任何身份不匹配都不能沿用。拟合后的标准化器仍受训练划分约束。需要批量调参或并行时遵守当次授权和资源核验，当前单卡结果不能替它背书。

代码或运行限制有变化时，先完成有界的真实 CUDA 计算与完整依赖导入检查，再启动长任务，因为“能 import”不等于 CUDA 能计算。限制机制可按环境选择；参考实现使用 Landlock 和仅处理本进程线程命名的兼容层，覆盖范围见参考记录。不能为了兼容广泛放行目录外写入，也不将该实现强制成所有环境的前提。

状态不明时查询原作业，不重投；已知失败按原因在独立尝试留证，不覆盖 prelaunch、退出和日志。设备问题先复核健康；预算/OOM问题只调整自有作业。输入不合法、无合格算力或依赖副作用不清楚时保存明确的失败/未验证状态，不能伪装成功。

偶发连接/认证失败进入自动恢复，不结束整个训练任务。海南的错误分类、退避与等待状态统一遵守[连接恢复规则](../../../../rules/skills/hainan-compute-access/SKILL.md#临时连接失败与自动恢复)：只读连接/检查可有界重试，恢复并补齐必要身份、环境和资源检查后自动继续原授权任务，无须因一次偶发异常询问用户。检查尚未通过时，只阻断依赖写入/启动；真实身份、路径、标签或冻结条件不符仍为硬失败。逐阶段检查返回状态，不使用会掩盖前置失败的裸多行 shell。

启动命令已发出但响应丢失时，先按 run、独占启动锁、PID与启动时间查询原作业；正在运行就继续观察，已完成就收集验收，不能重新提交训练。连接重试用尽保存 `waiting_for_connection` 和原阶段，已有获授权持续执行机制冷却后再接续，不丢弃训练状态。记录恢复尝试及最终检查结果；后续补查不能假装先前已通过，但成功恢复本身不构成验收失败。

## 选卡变化与资源等待

选卡依据是任务预计需求与不会影响他人的资源余量，不能以已用显存必须0或某个任意小阈值代替判断。保存同类实测峰值或估算依据、当前任务峰值预算及安全余量，覆盖显存、计算/带宽、CPU、内存和IO。有人使用的卡也可按通用连接Skill的共享条件核验后使用；只看到空余显存不足以排除对方突发需求和计算干扰。运行中出现冲突，只缩减或停止有身份的自有作业。

单卡任务绑定的是当前核验通过的GPU，不是主控过去选过的卡号。原卡在部署前被占用时，允许在同一任务预算内重新核验其他卡；仅重新绑定GPU UUID/索引及其派生摘要，不改科学配置、数据、冻结规则或学习次数。已准入的固定运行实现、设备资格判定或绑定格式需要修改时，保留旧件并由主控重新验收，不能以“换卡”跳过准入。部署或启动已发出则先查原状态，不能把换卡变成重复学习。

显存必须为0是某些已验实现的保守条件，不是通用规则。驱动也可能有少量开销；少量显存、没有PID或一次低利用率均不足以单独认定空闲。结合多次同UUID观测、完整进程视图、健康、预算及现有调度条件判断。若当前实现只能接受0 MiB，应明确记录这一局限，不能静默绕过，也不能直接声称少量占用就是驱动造成。

没有合格卡时保存 `waiting_for_resources`，在已有资源观察登记中记录run、资源需求、真实状态文件、来源主控、执行Thread与授权截止时间。用户已明确要求观察与训练直接衔接：观察Thread更新记录后，把有意义的资源变化通知原训练Thread；训练方读取记录、现场复核，在同一已准入任务内接续。主控不逐次转发常规资源通知。没有新资源时不重复唤醒执行Thread或添加定时器；通知不构成新训练、追加额度或修改源码授权。

训练完成、实质故障、预算到期、准入源码/科学方案或规则需要调整时回主控处理；普通资源等待由上述既有链路接续。主控负责训练任务与代码准入、独立结果验收以及下一阶段交接。具体失败与本地重绑定入口见[资源接续记录](references/resource-selection.md)。

## 部署传输与恢复

部署成功以目标端精确文件清单、摘要及独立接收/准入回执为准。已有自有权重可在核对来源路径、普通文件/非链接身份和完整摘要后复制到新run，避免每轮重复跨网络上传；不得以旧模型输出替代新训练。传输计时与训练计时分开，大小/截止时间/实际接收字节和接收进程身份应可观察。只看客户端超时不能判断远端是否写入。

超时先按原请求查接收进程与目录/部署回执、启动锁和学习证据。确认无活动接收者、部署未发生或已满足事先定义的幂等条件，且学习未启动，才可在当前授权内恢复部署；无法确定时查询原操作，不重投。已存在的成功部署只校验并接续，不覆盖。固定训练源码与冻结规则不因传输恢复改变，失败原件保留；具体已发生案例与验收边界见[部署传输记录](references/deployment-transfer.md)。

## 成功的证据

真实运行中已发现环境摘要误报和进程退出时的监控竞态，见[运行恢复教训](references/runtime-recovery.md)。预检worker成功、外层监督成功、开始学习和完成学习须分别记录；对本次只准一次学习的试跑，重新启动须先证明旧作业已退出且学习未启动；保留失败、新版本证据及全run首次学习锁。这个限制不能自动推广成永久禁止断点恢复。将来是否可恢复已有学习，由明确的批次恢复预算决定；未知状态始终先对账。

外层监督失败、科学worker完成、产物完整性和科学可用性分别判定。外层异常保留真实退出码；已经生成的完成凭据和产物仍由主控独立审查，不因一个监控字段读取失败就自动丢弃或重训。监测未知不能填零；应保存当次PID身份、原始状态与缺字段证据，有界复核，并按实际完成/边界证据决定后续。当前2026-11-01 v4出现worker返回0、监控125的实证；根因和完整验收尚未确认，不能写成竞态已证实。

| 验收项 | 可判断的结果 |
|---|---|
| 连接与资源 | 严格主机密钥、主机/UID、真实路径一致；启动前健康/占用原件、GPU UUID、预算和 PID/启动时间；运行中实际 GPU/PID 匹配。 |
| 真实学习 | CUDA 编码、前向/反向和优化步已发生；优化器与编码器分离，新头张量变化，loss/梯度有限；不能用 CPU 回退替代 GPU 实测。 |
| 底座冻结 | 参数及 buffer 的完整运行前后摘要相等，checkpoint 摘要不变，eval/no_grad/梯度状态有实际断言与来源可核对的代码。 |
| 数据与推理 | 只准入约定 CSV；完整行身份和有限预测，模型重载推理一致；所有使用的预处理状态可重建。 |
| 文件与资源释放 | 审读源码和实际文件写入轨迹或同等证据；所有成功项目写入在批准根内，拒绝的外部尝试保留说明；退出码、产物摘要和登记的自有进程/GPU释放均核实。 |
| 主控验收 | 交叉核对源代码、系统原件、输入摘要及产物；不能只读取执行会话的 success 字段。未测分支明确保留。 |

本 Skill 的 [只读证据检查器](scripts/check_evidence.py) 接受参考格式的本机 run 目录，不联网、不训练、不加载 pickle、不读私有标签；直接核对摘要、冻结记录、head 原始张量存储、预测行身份和退出证据。它不代替原始代码/轨迹审读，也不适用于任意模型布局。

## 交付规格

在 `adhoc_jobs/admet_training/runs/<run_id>/` 留存 `PLAN.json`、`source/`、带尝试编号的 `raw/`、`artifacts/` 或冻结取回目录、`acceptance/report.md`、`acceptance/result.json`、`status.json` 和 `CONTINUE.md`。回执包含 `training_completed`、`freeze_verified`、`write_scope_verified`、`own_resources_released`、`scoring_performed`、`upload_performed`、证据相对路径和未验证项；未验证用 `null` 或明确状态，不用默认 true。

报告区分训练完成、预测完成、本地评分和赛事提交。只有本次授权范围全部完成才标完成。训练执行方写本run结果并交主控；项目工作记录、Skill与索引由主控维护，执行方不修改。资源观察是用户要求的独立常驻职责，单次训练结束不停止它；其他任务专用监控按各自已登记停止条件收口。
