## 一、先把三个名字放到正确的位置

| 名称 | 它是什么 | 大白话理解 |
|---|---|---|

| **MPNN** | 消息传递神经网络框架 | 每轮收集附近的信息，更新自己的表示 |
| **D-MPNN** | 一种具体的消息传递设计 | 主要沿着“有方向的化学键”传递和更新信息 |

**也就是说，“GNN 和 D-MPNN 哪个好”本身不能直接回答，因为 D-MPNN 就属于 GNN。需要先指定你拿哪一种其他 GNN 来比较。**

## 二、D-MPNN 到底比普通的原子消息传递多了什么？

这里的“普通”特指**原子中心的 MPNN**，不代表所有其他 GNN 都一样。

### 1. 原子中心 MPNN：每个原子维护自己的状态

假设一个分子局部有三个相连的原子：\(A-B-C\)。

原子中心的做法可以理解成：

> B 看看 A 和 C 发来了什么信息，再更新“我这个原子在当前分子环境中是什么样”的表示。

交换几轮之后，每个原子的表示就包含了附近越来越大范围的结构信息。

这个过程中也可以使用化学键特征。**不能理解成“原子模型不看化学键，D-MPNN 才看化学键”。** Chemprop 的原子消息传递实现同样使用边特征。:chatgpt-content-reference{index="1"}

### 2. D-MPNN：每个有向化学键维护一个消息状态

对于 A 和 B 之间的一条键，计算时会建立两个方向：

\[
A\rightarrow B,\qquad B\rightarrow A
\]

这两个方向有各自的表示。

它的一个关键设计是：**避免消息刚沿一条键传过去，下一步又直接沿原路传回来。**

例如，信息沿 \(A\rightarrow B\) 传过来以后，可以继续影响 \(B\rightarrow C\)，但更新返回方向时，会排除这条立即回传的消息。设计动机是减少这种来回折返带来的冗余信息。官方实现的聚合公式中，明确排除了目标原子对应的反向消息。:chatgpt-content-reference{index="2"}

这里的 **D 是 Directed，即“有向”**：

- 指的是神经网络计算中的消息方向。
- 不表示化学键物理上只能单向连接。
- 不表示它必须使用三维坐标。

**标准 D-MPNN 可以从 SMILES 解析出的原子—化学键图进行训练。** 你在输入文件里提供 SMILES，也不意味着模型把它当成普通文本交给 Transformer；它可以先被转换成图。:chatgpt-content-reference{index="3"}

最后，Chemprop 会把学到的原子表示汇总为分子表示，再交给预测网络，输出分类分数或回归值。:chatgpt-content-reference{index="4"}

## 三、算法上有什么优劣？不能简单说 D-MPNN 全面胜出

如果具体比较**原子中心 MPNN**与**D-MPNN**，可以这样看：

| 比较项 | 原子中心 MPNN | D-MPNN |
|---|---|---|
| 主要更新的表示 | 原子的状态 | 有向化学键的状态，之后再汇总 |
| 消息组织方式 | 汇总邻居原子的信息 | 汇总进入当前原子的其他有向键信息 |
| 对立即反向传播的处理 | 取决于具体实现 | 标准设计显式排除立即回传 |
| 是否可以使用原子和键特征 | 可以 | 可以 |
| 是否天然需要 3D 坐标 | 不需要 | 不需要 |
| 能否预先判断比赛分数谁高 | 不能 | 不能 |

前几项区别可以从 Chemprop 的两个模块实现中直接核对。:chatgpt-content-reference{index="5"}

### D-MPNN 值得优先尝试的原因

它有明确的分子结构建模方式，而且已经有面向分子属性预测的现成实现。**对于你们现在需要尽快获得可信基线的情况，我认为它是一个合理的起点。**

这里的“合理起点”不等于“最终一定最好”。

D-MPNN 的原始研究做过大量分子属性预测比较，但结果仍与数据集和任务有关。该论文后来还发表了随机森林比较结果的勘误，修正后部分数据集上的相对排名发生了变化。因此，不能拿早期论文中的概括，直接推导出“D-MPNN 一定优于其他方法”。:chatgpt-content-reference{index="6"}

### 它也没有自动解决这些问题

- **数据少、标签噪声大**：换成 D-MPNN，并不会自动消除这些限制。
- **任务之间不适合共享**：采用 D-MPNN，不代表把所有任务一起训练就一定更好。
- **完整三维几何信息**：标准的二维原子—化学键图，并不会自动包含完整的距离、角度和构象信息。
- **速度和显存**：不能仅凭“有向键消息传递”判断它一定比其他 GNN 快或省显存，需要在你们的数据、批大小和设备上测量。

这些是选择模型时需要检查的条件，不能只看一个架构名称。

## 四、对你们而言，更现实的取舍是：用 Chemprop，还是自己搭 GNN？

这是另一个维度。

**Chemprop 是工具包，D-MPNN 是模型设计。你可以用 Chemprop 跑 D-MPNN，也可以自己实现 D-MPNN；使用 Chemprop 本身并没有形成一种新的模型方向。**

对于一个已经有 Harness、但还没有成熟分子模型训练管线的三人团队，我的判断是：

| 取舍 | 先用 Chemprop | 自己搭建另一套 GNN 管线 |
|---|---|---|
| 首个有效基线 | 可以复用现有模型与训练接口 | 需要自己补齐更多组件 |
| 改模型的自由度 | 已经模块化，但需遵循其接口 | 可以围绕自己的结构设计组织代码 |
| 排查实现问题 | 有现成实现可对照 | 更依赖团队自己的验证 |
| 适合的目标 | 先建立可靠基线，研究配置、任务组织和常见变体 | 已有明确结构假设，或团队有成熟代码可复用 |
| 能否保证分数更高 | 不能 | 不能 |

这是针对你们当前阶段的**工程判断**，不是两个软件实现之间的性能实测结论。

Chemprop 的模型本来就由消息传递、聚合和预测网络等模块组成，并非一个完全不能改动的黑盒。很多实验可以先在它内部完成。:chatgpt-content-reference{index="7"}

**因此，我建议先把 Chemprop D-MPNN 接进现有 Harness，作为图模型基线。只有当你们有一个具体假设，而现有接口不方便表达时，再投入另一套实现。**

例如，“我要研究一种不同的消息传递结构”是明确理由；“我要另外做一个 GNN，形成第二条路线”还不够明确。

## 五、最划算的第一组比较：在 Chemprop 内部做 Atom vs Bond

官方已经提供了两种模块，因此可以共用大部分流程，只改变消息传递方式：

```python
from chemprop.nn import AtomMessagePassing, BondMessagePassing

# 原子中心消息传递
atom_mp = AtomMessagePassing(...)

# 有向键消息传递，即 D-MPNN
bond_mp = BondMessagePassing(...)
```

这只是表示比较位置的示意代码，不是完整训练脚本。两个模块均来自官方接口。:chatgpt-content-reference{index="8"}

这个实验回答的问题很清楚：

> **在我们这份比赛数据上，原子中心和有向键中心的消息传递，哪个更值得继续投入？**

比较时尽量固定：

- 实际训练与验证样本清单。
- 原子、化学键及额外特征的定义。
- 标签、缺失值和标准化处理。
- 聚合与预测头的选择。
- 评价代码。
- 调参预算与选模规则。

同时记录模型参数量、训练时间和显存。相同隐藏维度不一定意味着参数量完全相同，相同 epoch 数也不一定意味着计算成本相同。

先用小规模试运行确认实现，然后对有希望的候选补充重复训练。最后看**逐任务表现与稳定性**，不要只看某一次最高分。

这样得到的结论，比“一套自己写的 GNN，和另一套默认 Chemprop，谁分数高”更容易解释。后者可能同时改变了特征、模型、训练策略和评价方式。

## 七、这个比赛使用 Chemprop 时，有两处要特别核对

### 1. 从头训练 D-MPNN，与使用外部预训练模型要分开

使用 Chemprop 的普通模型代码，并不自动意味着使用了外部训练数据。但某些功能会引入外部资产。

官方文档明确说明：

- `--from-foundation CheMeleon` 使用在 PubChem 分子上预训练的模型，首次请求会自动下载。
- 某种旧版归一化特征使用了从 ChEMBL 分子拟合的参数。:chatgpt-content-reference{index="9"}

按照你们目前的来源约束，首轮应明确采用**随机初始化、无外部 checkpoint、经过检查的特征处理**。不能把“安装了 Chemprop”和“启用了其中所有预训练功能”当成一件事。

### 2. 支持多任务，不等于比赛任务可以直接全部塞进去

Chemprop 支持单任务、多任务以及缺失标签处理，但你们仍需要明确：

- 哪些输出是分类，哪些是回归。
- 是否按任务或类型分开训练。
- 如果共享编码器，输出头和损失如何组织。
- 最终是否按比赛指定的逐任务指标评价。

这些选择与“Atom 还是 Bond 消息传递”是不同的问题，应该分别记录和比较。:chatgpt-content-reference{index="10"}

**我的具体建议是：把“Chemprop D-MPNN”定为你们“分子图 + GNN”路线的第一版实现，同时保留“指纹 + MLP”作为另一条大方向。图路线内部，再用同一套流程比较 Atom 与 Bond。这样既能比较不同表示路线，也能深入研究图模型，而不必一开始维护两套重复的训练系统。**

## 一、先把“模型训练”和“研究怎么训练”分开

以一个小分类器为例，比如输入分子结构，输出“某个性质属于正类的分数”。

这里其实有两个循环。

| 循环 | 谁主要负责 | 在做什么 |
|---|---|---|
| **一次模型训练** | 优化器 | 看训练样本、计算错误、计算梯度、自动调整模型内部的权重 |
| **一轮模型研究** | 人或 Agent | 决定表示方式、模型结构、学习率、训练时长等，运行实验，再根据验证结果决定下一步 |

模型里可能有几十万、几百万个权重。训练时通常通过梯度更新它们，并不是把每个权重的所有可能数值穷举一遍。

你看到训练人员调整的，往往是另一类东西——**超参数和方案选择**：

- 用指纹还是分子图？
- 网络多深、多宽？
- 学习率多大？
- 训练多久？
- 要不要加正则？
- 多个任务一起训练，还是分开训练？

这一层确实需要探索。但探索不等于必须穷尽全部组合。随机搜索等方法之所以有价值，就在于很多问题中，各个超参数的重要程度并不相同，整齐地遍历一个大网格可能非常浪费。这个结论有理论和实验研究依据，但也不意味着随机搜索永远最好。:chatgpt-content-reference{index="0"}

**你可以把训练 Agent 理解成负责设计实验、解释证据的工程师。优化器是它调用的工具之一。**

## 二、一个训练人员到底凭什么知道“往哪个方向走”？

通常依靠三个东西：

1. **已有经验提供起点。** 例如同类问题中常用的模型、合理的学习率范围、已知的软件陷阱。
2. **当前实验提供诊断线索。** 看训练过程、验证结果、错误样本和资源消耗。
3. **下一次实验用来区分解释。** 先选择能让判断更清楚的实验，再逐步缩小范围。

其中，第二、第三项最容易被“自动扫参”掩盖。

### 同样是“验证分数不好”，原因可以完全不同

你不能只看到一个分数，就知道该加深网络还是增大 dropout。

我建议训练 Agent 按下面的方式思考：

| 看到的现象 | 值得怀疑的事情 | 优先做什么 |
|---|---|---|
| 训练集和验证集都不好 | 没学起来、训练不足、实现错误、表示不合适、正则过强等 | 先检查训练链与小子集拟合，再决定是否改容量 |
| 训练集很好，验证先改善后变差 | 过拟合、训练验证分布差异、评价口径不一致等 | 先确认口径，再比较早停、正则或容量方案 |
| 到训练结束时，训练和验证仍在改善 | 训练预算不足，或学习率调度不合适 | 给少量候选更充分的训练，复查调度 |
| 换一个随机种子，优劣就反转 | 收益小于训练波动，或训练不稳定 | 先确认稳定性，暂不宣布赢家 |
| 总损失下降，但某些任务变差 | 多任务损失、样本量、尺度或权重失衡 | 拆开看每个任务，再考虑任务分组或权重 |
| 分数突然好得异常 | 真改进，也可能是泄漏、划分变化、指标或样本对齐出错 | 先核对数据与评价，再确认收益 |
| OOM、超时 | 批处理、图大小、模型或数据加载的资源问题 | 做工程诊断，不能因此判定模型方向无效 |

**这张表提供的是排查方向，不是“看到某种曲线就能确诊”。**

例如“训练和验证都差”，并不自动说明模型太小。你的标签可能错位了，参数可能根本没更新，也可能只是学习率不合适。小训练子集拟合、检查真实输入和输出，是常用的训练链诊断方法；数值不稳定则需要进一步查看损失、梯度和学习率等证据。:chatgpt-content-reference{index="1"}

### 对你这种工程背景，可以先抓住三个问题

**第一问：程序有没有按我们想象的方式学习？**

代码没有报错，不代表学习正确。

比如：

- 模型的预测对应错了标签；
- 缺失标签被当成了 0；
- 梯度没有传到需要训练的层；
- 参数没有更新；
- 输出和损失函数不匹配。

一个非常具体的例子：PyTorch 的 `BCEWithLogitsLoss` 已经在内部包含 sigmoid。如果前面又先做一次 sigmoid，再把概率当作 logits 送进去，程序仍可能运行，但训练目标已经不是你原本想要的那个。:chatgpt-content-reference{index="2"}

**第二问：模型有没有得到合理的学习机会？**

实现正确，也可能训练得不合理：

- 学习率太大，来回震荡；
- 学习率太小，预算花完了还没学到多少；
- 调度过早把学习率降得很低；
- 更复杂的模型需要更长时间，却只让它跑了一个很短的测试。

短跑适合排查明显问题和筛选候选，但短跑排名不保证等于充分训练后的排名。延长训练时，也要一起检查学习率调度。:chatgpt-content-reference{index="3"}

**第三问：模型学到的东西能否用于没见过的样本？**

前两问基本过关后，才更适合讨论泛化、正则、表示方式和任务组织。

这三个问题决定了你下一步应该查代码、调训练策略，还是探索模型方案。

## 三、“变好了，就沿着这个方向继续试”什么时候有用？

**有用，但需要同时回答：变好的证据可靠吗？这个变化可以继续外推吗？**

这里有三个容易踩的坑。

### 1. 参数的作用未必单调

假设把网络加宽一次，验证分提高了。

它只说明：**这次加宽，在当前其他条件下，产生了一个值得关注的结果。**

它不意味着：

- 再加宽一定继续提高；
- 所有任务都会提高；
- 换个划分也会提高；
- 收益一定来自宽度本身；
- 更大模型的额外成本一定值得。

因此，可以继续探索附近的范围，但不能把一个局部观察当成普遍规律。

### 2. 参数之间会相互影响

模型变深以后，合适的学习率、正则强度和训练时长可能也变了。

这也是为什么我没有给 Agent 写死“一次只能改一个参数”。

更合适的规则是：

> **一轮实验尽量回答一个主要问题，明确研究什么、允许哪些配套调整、哪些条件必须固定。**

例如比较 Chemprop 的 Atom 和 Bond 消息传递：

| 类别 | 这一轮怎么处理 |
|---|---|
| 研究对象 | Atom 与 Bond 消息传递 |
| 配套参数 | 各自合理的学习率，必要时包括正则和调度 |
| 固定条件 | 实际数据划分、标签解释、评价方法、输入特征定义、预算比较原则 |

如果把一个适合 Atom 的学习率强行给 Bond，再用一次成绩决定架构优劣，这个结论就很有限。Google 的调参指南明确区分了“研究参数、需要配套优化的参数、固定参数”，正是为了避免这类比较问题。:chatgpt-content-reference{index="4"}

### 3. 分数提高可能只是波动

有时改动只有很小的收益，而随机初始化、数据顺序、checkpoint 选择带来的变化就足以覆盖它。

这时值得做的下一步，可能是重新运行基线和候选，看看结果是否稳定，而不是立刻围绕新配置展开几十次搜索。

并且，**换种子复跑与换验证数据，是不同的检查**：

- 换种子主要看训练过程的随机性；
- 额外划分或事先留出的确认数据，才更能帮助判断结论是否依赖当前这批验证样本。

如果反复看同一个验证集、不断根据它修改方案，人和 Agent 也会逐渐适应这个验证集。模型选择本身同样可能过拟合。:chatgpt-content-reference{index="5"}

## 四、给你一个具体例子：一轮有判断力的训练怎么做？

下面是**假想的教学情境，不是本比赛实测结果**。

假设你们的 D-MPNN 已经跑通，观察到：

> 训练表现持续改善，但验证指标到某个阶段之后开始回落。

一个过于急促的行动是：“那就加大 dropout，看看涨不涨。”

更有用的行动可以是下面这样。

### 第一步：先确认这个观察可比较

检查：

- 训练和验证是不是用同一个指标？
- 训练集的诊断指标是不是也在 `eval` 模式下计算？
- 有没有把包含正则项的训练 loss，与不包含正则项的验证 loss 直接比较？
- 验证分数对应的是最后一个 checkpoint，还是预先约定的最佳 checkpoint？
- 是否有样本错位、尺度错误或缺失标签处理问题？

先把这些排除，后续的“过拟合”解释才更有意义。

### 第二步：写出本轮问题

例如：

> 在当前数据划分与训练预算下，加强正则能否改善验证表现，同时保留足够的训练能力？

这比“把模型调好”具体得多。

### 第三步：设计一小组有边界的实验

例如：

- 保留现有基线；
- 选择少量有理由的正则设置；
- 保留合理的学习率调整空间；
- 固定验证样本和评价；
- 预先约定选 checkpoint 的方式；
- 写清最多跑几次、花多少时间。

这里不需要立刻把深度、宽度、batch size、学习率、dropout、任务权重全放进一个巨大的搜索空间。

### 第四步：提前想清楚不同结果意味着什么

| 结果 | 可以采取的行动 |
|---|---|
| 验证稳定改善，训练仍正常 | 把它保留为候选，进入确认 |
| 训练和验证都变差 | 当前正则可能过强，或配套优化不合适；检查后再决定是否缩小范围 |
| 不同种子结果方向不一致 | 保留“证据不足”，暂不宣布收益 |
| 只有个别任务改善，其他任务退步 | 转向任务权重、分组或单任务对照 |
| 早期 checkpoint 已经足够好，更强正则没有额外收益 | 可以保留更简单的早停方案 |

**即使这一轮没有提高最终分数，它也可能帮你排除一个解释、缩小搜索范围。**

但也不需要为每次实验编一个宏大的科学故事。普通调参可以很朴素：有明确问题，有合理范围，有预算，知道看到什么就停。

## 五、那些“看板”到底应该怎么看？

我建议开始时只保留四组核心观测。其他图在出现具体疑问时再加。

| 看板 | 帮你回答什么 |
|---|---|
| **训练过程：loss、学习率、step/epoch** | 模型有没有在学习，过程是否稳定，调度是否合理 |
| **同口径的训练与验证指标** | 训练能力和泛化之间是什么关系 |
| **逐任务表现与有效标签数量** | 哪些任务在改善，哪些被总平均掩盖，指标是否有足够样本支持 |
| **时间、显存、吞吐与失败记录** | 一次实验成本多少，预算花在计算还是数据处理上 |

几个实用原则：

- **loss 与比赛指标分开看。** 训练损失下降，不保证指定的 AUROC、AP 或 MAE 同步变好。
- **保留原始数值。** 平滑曲线帮助观察趋势，但不能用来掩盖波动。
- **记录 best 与 last checkpoint 的区别。** 两者回答的问题不同。
- **不同运行比较真实样本和评价口径。** 仅仅都叫 `validation_v1`，并不能证明它们相同。
- **记录每个任务的有效标签数量。** 总行数很大，不代表每个任务都有很多可用标签。

看板的价值在于支持一个具体判断。图越多，并不自动意味着你对模型了解得越多。

## 六、这次分子比赛里，训练 Agent 最应该避免哪些错误？

我把通用训练错误和分子任务风险都放进文件了。这里挑最重要的几项解释。

### 1. 把缺失标签当作 0

分子任务中，一个分子可能只测过部分性质。

“这个性质没有测量”不等于：

- 分类任务的阴性；
- 回归任务的数值零。

应使用逐任务的有效标签掩码。Chemprop 支持部分缺失标签的训练，但你们的适配器仍要确保读取、损失归约、标准化和评价都保留这个含义。:chatgpt-content-reference{index="6"}

### 2. 先用全量数据标准化，再划分训练与验证

标准化器也会从数据里估计参数。

如果先对全部数据估计均值、方差、插补值或选择特征，再切训练验证，就可能把验证信息提前带进训练流程。

应先确定分区，再只在训练分区拟合这些处理，之后将固定变换应用于验证和推理。Chemprop 的缩放文档也特别说明了训练集拟合与输出反变换。:chatgpt-content-reference{index="7"}

### 3. 把“化学清洗”理解成越多越好

“全部去盐、全部去重、全部去掉立体信息”，看起来像认真清洗，实际上可能改变样本含义。

对你来说，先记住一句话就够：

> **分子处理规则会改变模型看到的对象，需要像修改模型一样，明确目的并保留前后映射。**

RDKit 的文档甚至展示过默认去盐可能把整个分子删空的情况。工具提供某个操作，不代表你应该对所有样本默认启用它。:chatgpt-content-reference{index="8"}

### 4. 随意换验证划分，然后比较分数

不同划分考察的泛化情境可能不同。

例如：

- 同分布的新测量；
- 未见过的分子；
- 未见过的分子骨架。

随机划分与骨架划分不能被当成同一张试卷。MoleculeNet 的研究明确讨论了分子任务中划分方式对评价的影响；但也不能因此把骨架划分写成所有场景的唯一正确答案。:chatgpt-content-reference{index="9"}

### 5. 让库的默认指标替你决定成功

例如把需要连续分数的排序指标，变成对 0/1 硬分类结果评价；或者把 AP 和梯形积分的 PR 面积混用。

这些名字相近，计算含义却可能不同。scikit-learn 明确指出，其 average precision 与梯形 PR 面积并不等价。:chatgpt-content-reference{index="10"}

在当前项目里，官方聚合细节尚未确认的部分，仍要保留为未知，不能自己发明一个“官方总分”。

### 6. 只存最高分，把其他尝试都丢掉

这会让队友无法知道：

- 为这个分数花了多少次尝试；
- 是否只是幸运种子；
- 哪些失败是程序错误；
- 哪些方向在什么条件下没有收益。

因此，计划、失败、负结果都要留下简短记录。稳定代码可以再进入共享主线，研究记忆应该及时共享。

### 7. 用一次失败给整个方向判死刑

下面几句话含义差别很大：

- “这次运行 OOM。”
- “这个配置训练不足。”
- “在当前划分和预算下，没有稳定超过基线。”
- “GNN 不适合这个任务。”

前面几句可能有证据，最后一句通常需要远多于一次尝试的依据。

### 8. Agent 自动引入外部拟合资产

你们此前担心的数据来源问题，不只存在于 CSV 下载。

Chemprop 的一些功能涉及外部预训练权重；部分归一化描述符也包含从 ChEMBL 分子拟合的参数。它们不能因为藏在一个软件开关后面，就被当成没有来源问题的普通代码。:chatgpt-content-reference{index="11"}

当前团队政策下，训练 Agent 应沿用已有来源审查与运行边界，不能自行开启这些资产。

## 七、应该给训练 Agent 写什么样的指导？

我认为最有用的指导，是让它在行动前能回答下面六个问题：

1. **我实际观察到了什么？**  
   引用运行、曲线、错误或预测记录。没有证据就写未知。

2. **我现在想回答哪个问题？**  
   例如“训练时长是否不足”，而不只是“想提高分数”。

3. **除了我的第一解释，还可能是什么？**  
   保留少量最相关的替代解释。

4. **哪个检查或实验能区分这些解释？**  
   有时只需检查一次标签映射，不需要再训练十个模型。

5. **什么结果会让我改变下一步？**  
   提前写清继续、停止、确认或转向排障的条件。

6. **最多花多少资源？**  
   给试验数、单次时限、总预算和最终确认留出边界。

这里还有一个适合 Agent 的工作习惯：

> **把“观察”“解释”“决定”分开写。**

例如：

- **观察：**某个任务在三次运行中的收益方向不一致。
- **解释：**可能是收益较小，也可能是优化不稳定，目前无法区分。
- **决定：**先检查曲线与运行条件；预算允许时补充确认，否则保留“不确定”。

这比直接写“该方案无效”更能帮助下一个 Agent 接着工作。

你前面提出的三人协作方式，也适合建立在这里：**每人负责完整实验，共用数据与评价约定，在薄总览里共享问题、进度与有范围的结论。** 不需要把训练、验证、解释切成三个人之间来回交接的流水线。

## 1. 为什么“不能微调”和“能用冻结权重”可以同时成立？

关键在于：**使用一个模型，与继续训练这个模型的原有参数，是两件事。**

假设别人已经训练好了一个“分子编码器”。它接收分子结构，输出一个特征向量。你们可以有两种使用方式：

| 使用方式 | 别人预训练好的部分 | 你们新加的预测部分 |
|---|---|---|
| **微调预训练模型** | 加载预训练权重，并继续更新全部或部分原有参数 | 可以同时训练 |
| **冻结模型，训练预测头** | 加载预训练权重，保持这部分固定，用它计算特征 | 随机初始化，只用比赛数据训练 |

第二种方式中，**整个参赛方案仍然包含训练，但训练的是你们新加的部分。**

用一个公式表示就是：

\[
\text{预测值}
=
\underbrace{g_{\theta}}_{\text{你们训练的预测头}}
\left(
\underbrace{f_{\phi_0}(\text{分子})}_{\text{冻结的外部编码器}}
\right)
\]

其中：

- \(\phi_0\)：别人已经训练好的参数，保持不变；
- \(\theta\)：你们用官方数据学习的新参数。

这是一种标准的迁移学习方式。TensorFlow 官方教程明确区分了“冻结预训练层、训练新增层”和“解冻原有层再微调”。:chatgpt-content-reference{index="0"}

所以，如果第一句中的“在基础上调”专门指**更新预训练主干参数**，第三句专门指**冻结主干、训练新预测头**，两句话就不矛盾。

**但如果第一句的意思是“任何别人训练好的模型都不能用，包括冻结后提取特征”，它就与第三句直接冲突。**

## 2. “需要从头自研框架”这句，不能直接理解成“什么都得自己重写”

这里至少要区分四件事：

| 概念 | 举例 | 与其他概念的区别 |
|---|---|---|
| **软件框架／工具库** | PyTorch、Chemprop、RDKit | 提供编程和计算工具 |
| **模型架构** | MLP、D-MPNN、Transformer | 描述网络如何组织、信息如何传递 |
| **训练好的权重** | 一个别人训练出来的 checkpoint | 包含从其训练数据中学到的参数 |
| **你们的参赛方案** | 数据处理、模型组合、损失、训练、评价、推理 | 可以自行设计，同时复用合法的开源工具 |

例如：

> 使用 Chemprop 已有的 D-MPNN 实现，随机初始化所有模型参数，再只用官方数据训练。

这叫**从头训练模型**，但没有要求你们从头重写 Chemprop，更没有要求重写 PyTorch。

再例如：

> 使用一个获准的冻结分子编码器，自己设计并训练一个多任务预测头。

这叫**基于冻结特征构建自己的任务模型**，也不等于从零实现所有底层软件。

因此，第二句可能有两种解释：

- 如果“自研框架”只是口头指**自行完成参赛模型与训练方案**，它可以与第三句兼容。
- 如果它指**全部网络必须原创、全部参数都必须随机初始化，或者不能使用现成开源实现**，那就是很强的额外要求，必须有明确原文，不能从“禁止外部数据”自行推导出来。

**特别是“从头训练”和“从头自研框架”，不能当作同义词。**

---

## 3. 但要注意：冻结，不会抹掉权重的外部来源

这是你们判断规则时最重要的一点。

无论参数是否被冻结，一个预训练模型都仍然包含它之前从训练数据中学到的信息。冻结只是限制后续更新方式。

因此：

- **“禁止外部数据”本身，不能自动推出“允许冻结预训练模型”。**
- **“冻结了权重”本身，也不能证明符合比赛要求。**
- 如果官方明确规定“外部预训练权重可以用，但必须冻结”，那就是赛事对这类资产设置的**明确许可和使用条件**。

这样的政策在逻辑上可以成立。主办方可以禁止参赛者自行加入外部训练样本，同时允许某些已有模型作为固定组件。关键是它需要被明确说明。

同样，也不能把“允许冻结权重”自行扩大为“允许任何预训练模型、任何外部特征、任何教师模型”。许可范围可能还涉及模型名单、版本、训练来源、使用方式等。

## 一、先讲清楚：我们到底在使用别人的什么？

你是 Agent Engineer，可以把这个方案理解成：

**使用一个现成的分子 embedding 模型，再训练一个针对比赛任务的分类器或回归器。**

这里有两部分：

| 部分 | 做什么 | 我们是否训练它 |
|---|---|---|
| **预训练编码器** | 读取分子，把它转换成一组数字特征，也就是 embedding | **冻结，不更新已有权重** |
| **新建的预测头** | 根据这组数字，预测溶解度、毒性、吸收等比赛要求的性质 | **用官方训练数据训练** |

用一个简单公式表示：

\[
\widehat{y}=g_{\phi}\bigl(f_{\theta_0}(x)\bigr)
\]

- \(x\)：输入的分子。
- \(f_{\theta_0}\)：别人训练好的编码器，参数 \(\theta_0\) 固定。
- \(g_{\phi}\)：我们新建的预测头，参数 \(\phi\) 可以训练。
- \(\widehat{y}\)：最终预测。

所以，你说“拿来调”，在这条路线里，主要是在调：

- 新预测头的结构、大小、学习率和正则化。
- 用编码器的哪种输出作为特征。
- 一个任务单独训练，还是多个任务一起训练。
- 是否组合不同编码器的特征。
- 是否加入由官方分子本身计算出的指纹或描述符。

**预训练编码器本身保持固定。**

这也带来一个工程优势：在编码器和预处理固定后，可以先把分子特征算好并缓存下来，后续很多实验只需要训练预测头。MiniMol 的论文就是按这种方式开展下游实验的。:chatgpt-content-reference{index="0"}

## 二、为什么调研变得更重要，但仍然不能直接“找一个最好的”？

### 1. 冻结以后，选到什么表示，会明显限制后面的发挥空间

假设一个编码器擅长提取分子的大小、局部结构和理化特征，那么这些信息可能对某些任务很有帮助。

但如果另一个任务需要的信息没有被它保留下来，后面的预测头即使训练得很好，也很难补回已经丢失的信息。

这可以直接从上面的公式理解：预测头只能看到 \(f_{\theta_0}(x)\)，看不到被编码器丢掉的内容。

**因此，选择合适的编码器，可能比把一个不合适的编码器后面的预测头反复调几十轮更有价值。**

你对调研重要性的判断，主要就在这里成立。

### 2. 论文里成绩好的模型，冻结之后未必仍然好

这是我这轮查资料发现的最值得你们注意的一点。

很多模型展示的好成绩，来自这样的过程：

> 加载预训练权重，然后用下游数据继续更新编码器和预测头。

你们现在要使用的过程则是：

> 编码器保持固定，只训练新预测头。

这两种用法的模型排名，不能直接互相替代。

例如，IBM 的 MoLFormer 模型卡明确支持用冻结的 embedding 训练预测器，但它页面上的主要 MoleculeNet 成绩表，标注的是 **fine-tuning 的结果**。因此，这张表不能直接证明它在你们允许的冻结模式下也最好。:chatgpt-content-reference{index="1"}

调研 Agent 必须回答的一个问题是：

> **这篇论文的实验，到底更新了哪些参数？**

甚至不能只看论文用了“fine-tuning”这个词。有的作者也会用这个词描述下游预测头的训练，最终还是要看具体方法和代码。

### 3. “最适合 ADMET”仍然是一个很宽的范围

你们要预测的是多种性质。一个模型可能在某些任务上更好，另一个模型在另一些任务上更好。

所以，最后的合理结果可能是：

- 一个编码器整体表现较好，作为主要方案。
- 不同任务使用不同的编码器或预测头。
- 两种表示组合后有稳定收益。
- 某些任务仍然由简单指纹模型或从零训练的模型表现更好。

**我们不需要预先假定存在一个模型，能在所有任务上通吃。**

同样，“预训练任务听起来特别贴合”是值得优先试的理由，但还不是验证结果。实际分子范围、标签定义、数据量和划分，都可能改变模型表现。

## 三、具体调研什么？我现在会优先看这几个候选

下面是我基于这轮一手资料核查给出的**实验优先级建议**。它们还没有在你们的比赛数据上跑过，因此不是性能排名。

### 第一批：MiniMol、CheMeleon、MoLFormer

| 候选 | 大白话理解 | 为什么值得进入候选 |
|---|---|---|
| **MiniMol** | 一个学过许多生物和量子性质任务的分子图编码器 | 论文直接采用“提取固定特征，再训练小型 MLP”的下游方式，并评估了 ADMET 任务 |
| **CheMeleon** | 基于 Chemprop D-MPNN，学习提取分子描述符相关信息的编码器 | 和你们已经讨论的 Chemprop 路线接近，作者提供直接提取分子特征的脚本 |
| **MoLFormer** | 把 SMILES 当作化学语言处理的编码器 | 官方明确支持冻结特征提取，可以和图模型形成不同表示方式的对照 |

**MiniMol 是这次调研里特别值得优先试的一个。** 它的下游方法，就是先提取分子特征，然后训练 MLP；作者仓库提供了在 22 个 TDC ADMET 基准上的结果。这与我们现在要做的使用方式直接相关。不过，公开基准的历史成绩不能当成本赛事成绩，数据划分和评价条件仍需重新对齐。:chatgpt-content-reference{index="2"}

**CheMeleon 的优势是和现有方向衔接自然。** 它基于 D-MPNN，以分子描述符为预训练目标；作者的特征提取脚本直接加载编码器、进入评估模式，并在不计算梯度的情况下输出 embedding。这说明冻结使用的路径很清楚，但它论文中主要的微调成绩，仍然不能直接当作冻结使用的成绩。:chatgpt-content-reference{index="3"}

**MoLFormer 值得作为表示方式不同的对照。** 官方模型卡明确说明，冻结 embedding 可以用于训练预测器。另外还要认准具体 checkpoint：公开的 `MoLFormer-XL-both-10pct` 是一个明确的数据配比版本，不能直接把论文中其他版本的成绩算到它头上。:chatgpt-content-reference{index="4"}

### 第二批：Uni-Mol / Uni-Mol2

如果前三条路线跑通，而且你们有余力，我会再考虑一条 3D 表示路线。

Uni-Mol 官方提供了 `UniMolRepr` 接口，可以提取分子表示。但即使接口接收 SMILES，内部也可能需要生成分子的三维构象；官方代码里还有构象生成失败后的回退路径。因此，接入时需要评估构象生成成本、失败情况以及结果是否稳定。:chatgpt-content-reference{index="5"}

我的建议是：**先把少量候选做成可以比较的真实结果，再决定是否扩展到更复杂的 3D 路线。**

这不是说 3D 不值得试，而是当前先获得一组可靠对照，更能帮助我们决定下一笔时间花在哪里。

## 四、调研的交付物，应该是一张“能直接开始实验的候选卡片”

你说最重要的环节是不是变成调研了——**调研确实成了关键前置环节，但它的完成标准应该是产出可执行的候选实验。**

我会要求每个调研 Agent 为候选填清楚这些内容：

| 要记录的内容 | 它解决的问题 |
|---|---|
| 确切模型名称、版本、checkpoint | 我们到底在讨论哪份权重？ |
| 输入要求 | 只有 SMILES 能不能运行？是否需要额外的三维处理？ |
| 预训练任务和分子范围 | 有什么理由认为它能提供本任务需要的信息？ |
| 冻结使用的证据 | 是真正做过冻结实验，还是仅仅能导出 embedding？ |
| 公开成绩的实验协议 | 更新了哪些参数？用了什么划分、预测头和集成？ |
| 特征提取方法 | 使用哪个输出、如何汇总成分子向量？ |
| 权重可获得性、使用许可、环境要求 | 能否在你们的环境里稳定接入？ |
| 最小验证实验 | 什么结果会让我们继续投入，什么结果会让我们暂时停止？ |

比如，一张有用的卡片，其核心结论应该接近：

> “MiniMol 的公开实验采用固定分子特征加 MLP，任务与 ADMET 相关。计划在共同划分上，与指纹＋MLP、CheMeleon 冻结特征作比较；先使用有限的预测头配置，观察逐任务收益和运行成本。”

这已经能够指导下一步工作。

而“这个模型很新、预训练数据很多、论文说超过很多方法”，还不足以让训练 Agent 做出好的选择。

### 调研也需要停止条件

我建议第一轮就设一个很明确的目标：

> **筛出三个有证据、能接入、使用方式符合规则的候选，然后开始本地比较。**

三个是当前团队的预算选择，不是什么科学定律。关键是不要把所有时间都花在继续找“也许还有一个更好”的模型上。

有了第一轮结果之后，第二轮调研会更有针对性。例如：

- 图模型整体较好：进一步研究图表示和预测头。
- 序列模型在少数任务上明显更好：研究这些任务的特点及互补性。
- 所有冻结模型都不理想：检查输入、表征适配性，并保留其他建模路线。

## 五、真正决定方案的，是下面这轮比较

我会把第一轮实验定义为：

> **在相同的数据与评价条件下，哪种冻结分子表示最值得继续投入？**

### 1. 留一个简单对照

至少保留：

**分子指纹＋小型 MLP。**

如果你们已经有随机初始化 D-MPNN，也保留它。

这两个对照分别回答不同问题：

- 冻结的预训练表示，是否比简单的分子指纹更有价值？
- 使用现成表示，是否比利用比赛数据学习表示更合适？

否则，只比较三个预训练模型，最后只能知道“三者中谁更好”，不知道这条路线到底有没有带来收益。

### 2. 先用简单预测头筛选，再给候选合理的调参空间

第一轮可以给每种表示配：

- 一个简单线性预测头，用来观察特征中的信息是否容易读出来。
- 一个小型 MLP，用来观察非线性组合能否改善结果。

线性头在这里是诊断工具，最终方案再结合赛事要求选择。

但不要因为“公平”，就把所有模型的学习率、正则化强度、预测头宽度锁成完全相同。不同表示的维度和数值尺度可能不同，它们需要的适配也可能不同。

更合理的是：

> **统一数据、划分、指标和预算原则，让每个候选在有限范围内调整必要的配套参数。**

Google 的模型调优指南也强调：比较某个主要选择时，要允许与之相关的配套参数分别调优，否则可能把“配套设置不合适”误判为“这个方向不行”。:chatgpt-content-reference{index="6"}

### 3. 看逐任务结果，并确认收益是否稳定

对于你们这种多任务比赛，只看一个自己拼出来的总分，可能掩盖很多信息。

至少要知道：

- 哪些任务变好了，哪些变差了？
- 收益是否只来自一次幸运的训练？
- 更复杂的方案是否值得它增加的训练和推理成本？
- 换一个合理的预测头设置后，排序是否仍然相近？

如果准备按任务选模型、融合特征或集成预测，也应该把它当作新的实验验证。反复对同一验证集挑模型，同样可能对验证集过拟合；选择更多模型，并不会自动让结论更可靠。:chatgpt-content-reference{index="7"}

## 六、三个人应该怎么推进？

结合你之前提出的“大家都做完整实验闭环、共享记录”，我仍然赞成这个组织方式。

在共同数据、划分和评价接口已经可用的前提下，可以这样启动：

| 成员 | 第一轮负责的路线 | 必须交付 |
|---|---|---|
| **你** | CheMeleon 冻结特征＋预测头，同时把特征缓存接口做通 | 候选卡片、真实实验结果、逐任务分析、成本记录 |
| **成员 B** | MiniMol 冻结特征＋预测头 | 同样的完整实验结果 |
| **成员 C** | MoLFormer 冻结特征＋预测头；共同模板中的简单指纹对照可先由他跑通 | 同样的完整实验结果及对照 |

这里是**第一轮认领**，不是永久分工。

每个人都负责：

## 七、对你的 Agent Harness，最值得加强的能力也变了

这次规则确认后，Harness 应该支持**登记并使用冻结的预训练资产**。它最有价值的工作，会是帮助团队稳定完成下面这个循环：

**读论文形成候选 → 接入指定权重 → 固定提取特征 → 训练预测头 → 统一评价 → 更新实验结论。**

给训练和调研 Agent 的规范，我会优先加入这几条：

1. **公开成绩必须附带使用方式。** 明确是冻结编码器、部分更新，还是整体更新；不能把不同协议下的成绩混着排名。
2. **候选必须对应确切 checkpoint。** 模型家族名称不能替代实际使用的权重版本。
3. **研究建议必须落到一个有限预算的实验。** 写清楚比较对象、判断依据和停止条件。
4. **特征缓存必须绑定权重、预处理和样本身份。** 避免换了模型、换了预处理，却继续使用旧特征。
5. **保留简单对照和失败范围。** 一个配置效果不好，不等于整个模型家族已经被证明无效。
6. **训练过程继续保持离线、输入明确。** 允许冻结权重后，可以提前准备指定模型资产，训练时仍然只读取固定资产和官方数据。

**我的具体建议是：现在优先推进 MiniMol、CheMeleon、MoLFormer 的冻结特征比较，保留一个指纹＋MLP 对照。把调研成果尽快转换为第一张真实的逐任务结果表，再决定把后续精力集中在哪一条路线。**

## 二、V2 具体怎样充当调研的“大脑”

我按 grapeot 的 [Best Practice Skill Writing](https://github.com/grapeot/context-infrastructure/blob/c747317c90af9d1071a1157fa95e3766edcb6441/rules/skills/bestpractice_skill_writing.md) 组织了目标、验收、资源边界和输出；实际研究采用了同仓库 [Deep Research Survey](https://github.com/grapeot/context-infrastructure/blob/c747317c90af9d1071a1157fa95e3766edcb6441/rules/skills/workflow_deep_research_survey.md) 的主张提取、重叠调研、原始来源核查和独立审阅。

V2 要让接手者能够回答以下问题：

1. **这次到底在作什么决定？**  
   是挑编码器、判断论文成绩是否适用、选择预测头，还是决定是否值得做多任务？不同问题需要不同证据。

2. **正在比较的究竟是什么？**  
   一个模型成绩必须绑定：  
   **资产版本 × 输入处理 × 数据与划分 × 参数更新时间线 × 预测头 × 搜索/集成预算 × 指标定义。**

3. **当前证据能推出多强的结论？**  
   明确区分“作者报告过”“本轮读源码观察到”“本数据已经实际验证”“研究者推断”。

4. **哪些未知真的阻塞工作？**  
   例如单位未知会阻止擅自再次取对数、按物理阈值裁剪，却不必阻止对给定数值标签设计基线。

5. **下一项工作怎样改变决定？**  
   每条建议都需要说明：要区分什么解释、最小对照是什么、什么结果会改变选择、何时停止。

6. **什么时候可以结束调研？**  
   当剩余关键问题已经变成“在本数据上效果如何”，就应进入有限实验。继续搜索之前，先说清楚：哪两个可选行动，会因为新信息而选择不同？

模型名字、当前权重版本、这批数据的异常等容易变化的事实，都放在按需材料中。这样后续换模型或更新数据时，不需要重写整套判断原则。

## 三、真实数据里最影响策略的发现

完整的 22 任务表、定义、来源、统计和复算方法在：

**[data-profile.md](<PRIVATE_ANALYSIS_REFERENCE>)**

以下来自对[你提供的数据固定版本](https://github.com/ZYDTR/admet-benchmark-data/tree/0275588ac7a5d3df032ec7dc0794cab21dfcfeeb)的实际审计。

### 1. 这批数据有 22 个任务，单任务的规模差别很大

| 项目 | 实际情况 |
|---|---:|
| 任务数 | 22：13 分类、9 回归 |
| 训练记录 | 53,695 行 |
| 验证记录 | 11,735 行 |
| 测试记录 | 16,379 行 |
| 训练集不同原始 SMILES | 34,610 个 |
| 三个角色合计不同原始 SMILES | 46,202 个 |

这意味着，**53,695 是跨任务标签记录总数，不能理解成每个任务都有这么多独立样本。**

例如 DILI 的训练集只有 331 行、验证集只有 48 行。与此同时，三个 CYP inhibitor 任务贡献了约 49% 的训练标签。直接把所有标签的 loss 平均，会隐含很不均衡的任务权重。

### 2. 最重要的新发现：验证集“没有骨架重合”和“覆盖充分”是两回事

最初化学审计发现，在固定 RDKit 定义下，同一任务的不同划分之间，非空 Murcko 骨架没有交集。

独立审阅进一步检查了**每个划分究竟包含多少种骨架**，发现：

| 任务 | 验证集的实际组成 | 对判断的影响 |
|---|---|---|
| Ames | 1,137 行，但只有 **1 种非空 Murcko 骨架** | 很多验证样本仍可能只覆盖一种骨架条件 |
| LD50 | 1,937 行，**全部为空 Murcko 骨架** | 行数多也不能忽略结构组成差异 |
| Solubility | 2,940 行，**全部为空 Murcko 骨架** | 其 train 和可解析 test 都是非空骨架，验证条件存在明显差别 |
| DILI | 48 行中，35 行为空骨架 | 样本数量和结构覆盖都限制结论 |

这里的“空骨架”是这种以环为中心的表示没有留下骨架，**不能把它解释成这些分子都属于同一个化学家族**。

这个发现会直接改变选模原则：

- 继续保留给定 valid 作固定协议评价。
- 若要依据细小优势宣布某模型更稳健，可以在原 train 内增加预先定义的分组诊断。
- 预算不足时，就把结论限定为“在当前 valid 分布上更好”。
- 增加随机种子不会补出验证集中没有观察到的化学覆盖。

我们没有据此声称官方划分错误，也没有声称模型排名已经反转；目前还没有模型实验结果。

### 3. 多任务的标签边界，比“把表合并起来”复杂

同一任务内部，原始 SMILES 跨划分没有交集；但把所有任务合起来，train 与 valid 有 **4,798 个相同原始 SMILES**。

举个直观例子：一个分子可能出现在任务 A 的 train，又出现在任务 B 的 valid。

使用 A 的训练标签，不能直接等同于泄漏 B 的目标标签；但 B 的验证也不再代表“共享模型从未见过这个分子”。

更进一步，按“是否在其他任务训练集中出现”分层，也未必能得到有解释力的结果：

- CYP2C9 substrate 的未暴露验证子集只有 **3 行，全部为负类**。
- CYP2D6 substrate 的对应子集只有 **5 行，其中 1 个正类**。

因此 V2 增加了一个要求：**在要求 Agent 报一个指标之前，先让它判断这个子集能不能回答问题。** 软件返回了一个数字，不代表科学问题已经得到回答。

### 4. “重复就平均”会改变学习问题

已经观察到：

- PPBR train 有 1,952 行、1,282 个原始 SMILES，其中 **481 个 SMILES 有不同数值标签**。
- BBB train 有 **7 个原始 SMILES 同时对应 0 和 1**。
- hERG 的 Drug_ID 存在空值。

这些不能直接归为应该删除的脏数据。重复测量、实验条件差异等是可能解释，当前没有足够资料逐项确定。

所以，V2 要求分开保存：

**原始文件行、分子身份、任务端点、测量/标签记录。**

可以复用同一个分子的向量计算结果，但不能因此把监督记录悄悄合并。

### 5. 全行覆盖已经是实际问题

用 RDKit **2025.09.6** 默认解析检查全部唯一原始输入后：

- 有 **2 条 solubility 测试输入解析失败**。
- 另有 **1 条测试输入包含 388 个重原子**。
- 数据还包含多片段、指定立体信息和多种金属元素。

这只说明特定解析器和设置存在覆盖问题，不能说这些输入对所有软件都无效。

后续候选需要说明如何保留和处理这些行。尤其 Uni-Mol 的当前前处理源码包含构象回退和随机原子裁剪，冻结权重并不自动让输入处理固定。:chatgpt-content-reference{index="0"}

| 路线 | 当前定位 | 主要要回答的问题 |
|---|---|---|
| 简单指纹／描述符 + 合理监督模型 | 必要对照 | 复杂表示到底增加了多少有效信息？ |

几个会改变判断的模型事实：

**MiniMol 的原始方法确实贴近冻结路线。** 但其公开结果包含预测头搜索、集成与重复实验，不能把成绩理解为“冻结后随便接一个默认小头”。:chatgpt-content-reference{index="1"}

**CheMeleon 的主要公开成绩不能直接作为全程冻结成绩。** 它的补充材料确实有永久冻结消融，在作者的 FNN 和验证设置下，回归任务表现受到影响。这是需要认真考虑的反证，但不足以否定所有预测头和完整方案。:chatgpt-content-reference{index="2"}

**MoLFormer 的公开 `both-10pct` 与论文 full-XL 也不能混为一个资产。** 原论文多数主要结果采用微调；公开模型卡说明了该权重的预训练范围和输入处理。:chatgpt-content-reference{index="3"}

另外，冻结 CheMeleon + TabPFN 的直接前作值得保留为后续组合支线；它用的是 **TabPFN 2.6**，两个模型都固定，其统计“赢”也不等于每项绝对第一。这个结果支持继续研究预测器与表示的配合，不能直接宣布本赛优选。:chatgpt-content-reference{index="4"}

Uni-Mol、KPGT、SMI-TED、MolE 都保留了条件化的后续位置。它们被延后，各有具体原因；没有被写成“整个方向已经证明不行”。

## 五、V1 到 V2 的实质变化

你希望规范能帮助其他 Agent 避免那些“强模型可能自己知道，但文档没说清楚”的错误。这次实际增加的，主要是下面这些判断关系：

| V1 已有原则 | 实做暴露的缺口 | V2 的补强 |
|---|---|---|
| 检查是否冻结 | 先微调、后冻结，也可能被误判为符合 | 检查完整参数更新时间线 |
| 记录模型版本 | 论文、公开权重、默认安装包可能不是同一个对象 | 每项性能主张绑定完整方案身份 |
| 检查划分重合 | 零交集仍可能伴随极端的验证分布集中 | 同时检查隔离性和代表性 |
| 多任务注意泄漏 | 容易走向“全部重合都违规”或“完全没关系” | 逐标签记录角色，明确评价条件 |
| 可以分层评价 | 子群可能没有正类或只有几条数据 | 先判断指标与问题是否可估计 |
| 保留未知 | 一个未知可能让 Agent 停掉全部工作 | 写清“仍可做什么／具体阻塞什么” |
| 查原始证据 | 证据可能只存在于研究者临时目录 | 将关键证据放入项目内并直接路由 |

最后一项是**功能试用真的发现的问题**：首次窄问题 Agent 回答正确，但为了核对 CheMeleon 许可，去项目外找临时保存的元数据。我把原始响应纳入项目，再用一个只准读取项目目录的新 Agent 复测。

## 六、其他 Agent 实际用起来怎么样

| 任务 | 实际表现 |
|---|---|
| 根据论文高分决定是否全押 CheMeleon | 找到 V2 和相关证据，保留有限 pilot，提出对照、升级条件和停止条件 |

| 离线核对 CheMeleon 具体权重许可 | 答案正确，但发现原始证据的可移交性缺口 |
| 仅项目目录内完成同类窄查询 | 修复后通过；能区分赛方允许、权重 MIT 元数据和工程尚未完成 |

这些任务没有获得预期答案或指定阅读链，也不允许读取其他测试结果。实际读取路径都保存了下来。
