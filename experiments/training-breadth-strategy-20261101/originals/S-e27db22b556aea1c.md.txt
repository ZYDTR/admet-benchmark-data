## 2. Fixed contracts (do not drift)

- Identity is `(task, split, row_index)`; `row_index` is the 0-based data row in the
  split file, independent of `Drug_ID`. Duplicated molecules are separate rows
  (`ppbr_az` has repeated SMILES with different Y).
- Blind `valid.csv`/`test.csv` must not carry `Y`; a `Y` column is a hard error.
- Product CSV: `task,split,row_index,y_pred`, exactly the expected key set, finite
  values, no duplicates. Missing/extra/duplicate/non-finite => refuse.
- Template: 16,379 rows, SHA256 `8ee41589…e9baa20`, `sample_idx` == test `row_index`
  per task, `drug_id`/`smiles` identical, all `y_pred` empty. The writer fills
  `y_pred` only and re-verifies the full identity join afterwards.
- Encoder is frozen and imported only by `encode_features.py`; `train_heads.py` never
  imports it, so fine-tuning is impossible by construction.
- Regression tasks (9): caco2_wang, clearance_hepatocyte_az, clearance_microsome_az,
  half_life_obach, ld50_zhu, lipophilicity_astrazeneca, ppbr_az, solubility_aqsoldb,
  vdss_lombardo. Everything else is classification. Override with
  `train_heads.py --train-table {"task":"regression"|"classification", ...}`.

## 3. Main-control run order

```bash
cd <this dir>                     # .../model/output
python3 -m venv .venv && . .venv/bin/activate
pip install 'chemprop>=2.2.0' 'numpy>=1.26,<2' 'pandas==2.2.3' 'rdkit==2024.9.6' \
            'scikit-learn==1.6.1' pytest      # author README: torch 2.6.0, chemprop 2.1.2

# 1. weights (explicit, never implicit)
curl -L --fail -o chemeleon_mp.pt \
  'https://zenodo.org/records/15460715/files/chemeleon_mp.pt?download=1'
python3 make_asset_lock.py --weights chemeleon_mp.pt --out assets.lock.json
#    refuses unless size==34859448 and md5==6a80b54fdb7de37ef0374d302f01e8ce

# 2. features (all 22 tasks, 3 splits) -> prints hit/miss + coverage per split
python3 encode_features.py --data-root ../input/data --weights chemeleon_mp.pt \
  --asset-lock assets.lock.json --cache .work/features --device cpu --batch-size 128
#    record the reported feature_dim, then add it to assets.lock.json ("feature_dim")

# 3. heads (22 tasks, one MLP each)
python3 train_heads.py --data-root ../input/data --cache .work/features \
  --asset-lock assets.lock.json --out .work/heads --tasks \
  ames caco2_wang ... --feature-dim <D>

# 4. predictions
python3 predict_valid.py --data-root ../input/data --cache .work/features \
  --asset-lock assets.lock.json --out .work/heads --tasks <task ...> \
  --output .work/valid.csv --feature-dim <D>
python3 predict_test.py --data-root ../input/data --cache .work/features \
  --asset-lock assets.lock.json --out .work/heads --tasks <task ...> \
  --output .work/test.csv --submission .work/submission.csv --feature-dim <D>
```

`--help` on each script prints the authoritative flag list (already exercised in
`checks.json`). Run `python3 -m unittest discover -s tests` after installing torch:
the 3 skipped head-artifact tests must then pass before training is trusted.
