# 训练前准备交付

Workflow。v1.2.2，2026-11-01。按工作区 `bestpractice_skill_writing.md` 编写。目标是交付宿主可以接手验证的代码与运行说明；执行范围以本次 TASK.md 为准。读取本 Skill 的准备会话是叶子执行者，亲自完成分配部分，不再派 Agent、开会话、运行模型 CLI 或联系其他会话。

## 派发与读取合同

本段派发职责只属于主控。每次派出准备任务，把当前 Skill 和命中的参考材料冻结到该任务 `input/rules/`，与 TASK、输入清单一起交付到执行方实际能读的位置。提示必须明确要求先读任务内 `PREPARATION_SKILL.md` 再执行 TASK，并给出两者的实际路径和 Skill 摘要；版本号须从本次原文读取，不能在生成器里写死；不能只给主控本机路径，或假设同名项目已同步。

主控用 `scripts/preparation_packet.py` 生成独占快照、文件摘要和派发提示；在目标机器运行其 `verify-target` 读回实际文件后才发送，保留 stdout、退出码及目标会话/项目身份。它只准备和核验材料，不发送消息或启动模型。OpenCode 会话仍从既有 Context Infrastructure 根创建，任务包位于其子目录；不修改运行中任务的冻结版本。

准备方在交接 `skill-use.json` 写出实际读取的路径、版本/SHA、TASK SHA，以及适用于本任务的条款→生产函数→检查记录映射。主控另看原工具轨迹确认实际读取，并复核行为；回显摘要、自报已读或测试数量都不能单独当作遵守。

## 准备阶段的边界

- 可以编写训练代码；执行仅限静态检查、输入合同核验、固定合成数值和无参数更新的轻量接口测试。CPU、一个 epoch、随机数据、临时输出或叫 smoke test，只要运行 backward、optimizer.step、fit 或训练入口，都属于训练，留给主控。整批特征提取也留给主控。
- 只读取任务指定输入和必要公开技术资料；只写自己的输出目录，包括临时文件、缓存、日志、`__pycache__`。临时路径、shell 重定向、库缓存都须显式落在自己的输出目录；命令失败也不能改用目录外 `/tmp`。环境安装、权重下载和服务器执行由主控负责；缺依赖就记录原始错误和未验证项，继续完成能做的准备，不自行扩权。
- 不寻找验证/测试真标签，不修改原始输入，不自行寻找其他会话产物；主控作为本次输入明确交付的已验收旧资产可以只读复用。保留执行证据；已经越界时如实报告位置与动作，不用删除产物或改称“仅测试”掩盖。

## 交付如何判定合格

按职责满足对应条件，方法与文件组织自行选择：

- **共同接口**：以任务合同定义行身份和预测格式。ADMET 用 `(task, split, 原始行号)` 区分行，Drug_ID、Drug 是需原样保留的属性；所有分区允许合同规定的空ID和重复ID，不得自行增加唯一/非空限制，也不去重。重复完整行键才是错误。用真实输入的无标签投影及含空/重复ID的合成数据调用生产加载/导出入口，核对全行、原序和属性；训练标签不传给盲分区。不同 split 单独运行时不依赖未请求的输出。
- **模型与缓存**：冻结编码器，变换仅拟合 train，回归还原原尺度；权重版本和来源可追溯，加载使用受限格式。缓存命中须绑定输入内容与逐行身份、编码器/权重及相关依赖版本，并检查数组摘要、形状、类型、有限值。编码、缓存、预测的数组类型与清单构造必须互通，准备环境的替代类型通过不代表真实依赖类型通过；盲 split 的加载不得索取 label。文件存在且行数相等不足以复用；损坏、错序或来源变化须拒绝或明确重建。
- **评分与导出**：实际入口的默认调用也须核对完整预期键集合；缺少可信预期集合就失败，不降级为只评已有行并返回成功。缺行、重复键、额外任务、错 split、非法标签及非有限值均明确失败，禁止字典覆盖或只评交集。空集和单类等情况按项目约定明确返回未定义及原因。导出保留模板行数、顺序和全部非预测字段；若合同要求原格式保真，还须检查引号、BOM与换行字节。
- **配置与状态身份**：实际优化器类别和参数来自显式配置并校验；宿主固定计划中的缺省选择应说明，不暗中扩大搜索。best/last 的 epoch、累计更新步数、所选权重和监测值分别对应各自时点；更换选轮指标时，旧字段的数值尺度和聚合范围也必须保持原定义，不能把历史best字段改填当前轮数值；新选轮指标另设字段，并以MSE最优轮、MAE最优轮和末轮不同的固定轨迹调用生产保存入口核验；构造最佳轮次早于末轮的反例，不把最终 steps 填入 best。检查划分、缓存及配置摘要时，明确定义摘要覆盖的字段，不把旧摘要再次包含进自身摘要。
- **恢复材料**：任务要求可恢复时，保存优化器完整 `state`/`param_groups`，包括 Adam 的动量和真实Tensor状态；只存 step 或统计摘要不算恢复。保存 Python、NumPy、PyTorch CPU、全部可见CUDA及实际使用的独立生成器状态，绑定同一 last head、配置、epoch/steps。已有依赖时可用手工构造的非空状态做受限格式存取与消费端加载，不执行训练步；普通列表替身不证明Tensor可序列化。必需的存取/重载检查失败应阻断成功，缺依赖则交接为未验证，不能捕获异常后继续写success。
- **反例验收**：用固定合成数据证明正常路径成功，以及生产入口能拒绝真正不合法输入；预期结果来自任务合同，不能把实现中的错误限制写成测试答案。至少把生产端输出接到真实消费端，核对数据类型、函数签名、键、形状和退出状态；缺依赖明确列出尚未执行的检查，不用自制替身或编译成功代替。测试自身也须遵守准备边界。
- **交接**：输出目录含代码、依赖/资产清单、`HANDOFF.md`、`skill-use.json` 和检查记录。写清实际命令/退出码、未验证项及原因、宿主下一条命令。区分已验证、静态审读、推断及未验证；包含失败原件，不把未实跑端到端写成已跑通。
