# 恢复与沉淀

## 目标

让一个没有前情的 Agent 找到已经完成的证据、真实阻塞和下一项可执行工作。

## 验收标准

- 先从 `status` 和对应 task 恢复，核对该任务引用的证据；未把旧摘要视为当前运行事实。
- 不重复已有成功实验；遇到证据缺失、哈希变化或状态冲突，报告差异并修复交接。
- 每条交接有目标、负责人、状态、已做事项、下一动作、阻塞和证据；done 有证据且无阻塞。
- 更新遵守 revision 比较；冲突时读新版本合并，不能强行覆盖队友。
- 假设、一次观察、经验证的结论分开；只有真实验证的稳定经验进入决策或 Skill。

## 资源与边界

读 [状态](../../context/state.json)、当前任务及 [交接接口](../../docs/context.md)。仅为解释已有选择时读 [决策](../../context/decisions.md)，仅查真实教训时读 [工作记录](../../docs/working.md)。无需逐页加载全部运行日志。恢复后按 [索引](../INDEX.md) 加载下一任务所需技能。

## 输出

使用 `checkpoint --input <交接JSON> --expected-revision N` 写入 `context/tasks/<task_id>.json` 和不可覆盖的历史。重大阶段、阻塞解除更新 `context/state.json`；已有 task 是进度权威，state 仅汇总。新经验包含证据、适用范围和日期，未经验证的建议不写成 Lessons Learned。
