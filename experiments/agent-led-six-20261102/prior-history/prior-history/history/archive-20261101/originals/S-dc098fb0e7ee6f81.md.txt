# 把 Harness 接到实际 Agent

## 一个入口

在 Agent 的项目工作目录打开本仓库，并把“先读 AGENTS.md”作为入口。若放在更大的 workspace，只在其已有 AGENTS/CLAUDE/技能索引中加一个指向本项目 AGENTS.md 的入口；不要全局注册八个局部技能。当前项目已提供 CLAUDE.md 转接文件。

宿主是否自动读取 AGENTS.md 取决于具体工具。本项目不假定所有客户端都会自动加载；用下述自然语言启动请求验证一次即可。

> 先读这个项目的 AGENTS.md，恢复当前状态。按任务意图加载必要 Skill，完成当前环境允许的工作；有阻塞时记录具体缺项和下一动作。

## 建议的工具分层

| 层 | 能做什么 | 不能从项目文档自动获得的保证 |
| --- | --- | --- |
| 联网调研 | 读取官方规则、方法论文、软件文档；交接候选代码和方法 | 其输出不会自行获得训练准入 |
| 工程编辑 | 在候选分支修改代码、测试与配置，提出来源变更 | 不能自己证明新增数据合法 |
| 实验调度 | 查询状态，选择审查后的配置，调用 plan/run/evaluate | 不授予任意宿主 shell、任意 mounts 或网络工具 |
| 容器执行器 | 读取冻结输入/代码，写本次产物，使用本地固定镜像 | 不限制容器外的浏览器/MCP/LLM API |

LLM API 调用可由外层协调器完成；搜索权限、宿主文件写入权限和训练工具权限分别控制。不要向训练容器传模型服务密钥；不要把 Docker socket 或整个个人目录挂进去。

## 一个实际部署检查

配置好目标机器后，核对调度 Agent 只能调用允许的命令/参数；确认联网调研无法直接写官方数据目录或正式运行快照。数据/代码/镜像的确认动作由有相应权限的队友承担。若同一个 Agent 拥有任意宿主 shell，它仍能绕开本 CLI，这时必须明确承认隔离边界不足。

通过已审查镜像执行 `scripts/check_container_boundary.py --image sha256:<实际镜像ID>`，检查断网和只读输入的真实行为。测试只验证该次工作负载；镜像审查、宿主 Agent 权限和比赛数据来源需分别验证。

## 故障与恢复

Docker/镜像缺失：继续工程单测和合成演示，正式运行保持阻塞。容器失败：从 run.json 和日志定位原因，新运行使用新 ID。不要自动安装、拉取任意镜像、改为有网络运行或降级到宿主机直接训练。
