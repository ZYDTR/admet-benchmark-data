## Preparation and experiment design recommendations

1. **Separate randomization roles.** Persist split indices/hash independently of `init_seed`, `batch_order_seed` and dropout RNG. First matched screen can use the original seed42 indices as an explicitly historical diagnostic split, a single accepted cache, all rows unchanged, with initialization/batch/dropout seed tuples (42,42,42),(43,43,43),(44,44,44). These are proposed discrete seeds, not evidence-based optimal seeds. Seed42/43 are historical; seed44 is a new prespecified replicate. Repeating three seeds addresses algorithm variability, not external sample uncertainty.
2. **Disentangle width/LR.** A bounded 2x2 factorial width{256,512} x LR{0.0005,0.001}, fixed architecture/AdamW/WD/dropout/batch/loss/stop/split/cache, has4 configurations and12 training runs at3 common seeds. A cheaper authorized screen is4 configurations x1 seed=4 runs, followed by only two finalists x2 additional seeds=4 extra runs (8 total, selected finalists then3 seeds). New comparisons must not silently mix the historical runs into fresh matched replicates if cache, code, splits or runtime changed. No execution is authorized now.
3. **Align stopping to task metric without changing targets.** Always record internal raw-Y MAE plus standardized MSE at epoch-end for both train and holdout. MSE versus raw-MAE checkpoint selection is a two-policy hypothesis. A proposal can save both best states on one fixed50-epoch trajectory:1 training fit,2 candidate checkpoint-selection policies. It is not two statistically independent runs; both selection choices consume selection budget. Alternatively change only the early-stop monitor and keep loss/optimizer fixed in separately matched runs. New Huber/MAE loss comparisons must be separate from the monitor ablation. Current archives cannot evaluate MAE-selected epoch retrospectively because epoch predictions/states were not retained.
4. **Confirm outside the tuning loop.** Use future train-only grouped outer/inner splits, maintaining all original official partitions. Outer labels never select epoch/head/HPO within their fold. Lock split generation and candidate set before execution. After selecting one challenger, compare it and control on3 fixed outer splits x3 common seeds=18 fits for2 configurations; not all directions times every split. Cross-validation on an already explored train set is supplementary and not a newly untouched external test. Truly final hidden-test generalization remains unknown until an authorized untouched evaluation.
5. **No arbitrary win threshold.** Minimum practical delta remains TBD pending domain scale and matched-run noise. Predeclare direction, full metric, config/selection budget, and a provisional decision rule: require consistent paired improvement on prespecified confirmatory fold/seed cells with no eligibility failure; if signs reverse/material rank instability, report inconclusive and retain lower-cost control. A future controller may publish permitted aggregate paired loss-difference dispersion or grouped resampling results after a separately authorized evaluation; never invent confidence from the current two scores. Do not expose exact official scores or residuals in OpenCode's guide.
6. **Respect roles.** Only analysis/controller artifacts contain these exact scores. Preparation gets technical failures, issue/proposal IDs and contracts. Current status is proposal_only. Proposed seed/fold/grid counts are planning units, not execution approval.
