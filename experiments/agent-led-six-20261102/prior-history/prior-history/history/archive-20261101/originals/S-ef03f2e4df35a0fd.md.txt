## 1. 结论与第一版范围

现有底座值得保留：薄入口、按需加载、原始数据与代码快照、不可覆盖的运行记录、严格模板对齐、候选来源核查和按任务交接都有用途。当前最缺的是能让三方独立接入、最终汇合的可执行约定，以及真实环境中的证据。

第一版应交付四项能力：

1. **可独立检查的适配器接口。** 合成参考实现真正经过训练、保存、独立进程加载、预测和评价；C 能在正式数据与容器尚未就绪时开发和自检。
2. **可追溯的数据与划分。** 区分官方原始文件和团队派生视图，冻结父数据、划分成员、标签定义和必要变换；B 可分批发布已确认任务。
3. **可复算、可比较的实验结果。** 保留逐样本验证预测及其数据、划分、标签和评价版本，统一评价器独立计算指标；记录真实调参与选模依据。
4. **完整候选的交付检查。** 模型、预处理和任务语义相容，覆盖模板全部行；保留主备候选及最终平台回执。

A/B/C 分工仍可采用。A 负责共享运行与检查工具，B 负责数据含义、划分和评价口径，C 负责深度模型与适配器。每项工作等待自己实际需要的输入，常规实验不增加全员审批。启动阶段不建设通用调度平台，不全面重写现有八个 Skill。

**四天是条件目标。** 之前给出的 Harness 12–20 人小时是初步规划，尚未经过真实接入验证，不能作为工期承诺。D1 的真实运行计时和 D2 的完整候选是两次必须重新评估范围的节点。

## 2. 规则的来源和效力

本轮规则子代理于 2026-10-29 成功读取官方公开 getTrack 接口和提交模板，主 Agent 重新读取原始响应的相关字段。网页工具读取失败，但只读 HTTP 请求成功；未检查登录后材料及其他官方通知渠道。

证据：[官方赛题页](http://www.aiinnovation.com.cn/web/#/trackDetail?id=159)、[本轮接口响应](rules-evidence/getTrack-response.json)、[响应头](rules-evidence/getTrack-headers.txt)、[官方模板副本](rules-evidence/official-template.csv)。接口内容更新时间仍为 2026-10-26；响应的服务器时间会变，不能仅用整个响应哈希不同推断规则改变。

### 2.2 团队策略与尚未明确的事项

**团队策略：**随机初始化、固定本地镜像、训练执行器断网、独立缓存及可追溯运行记录。它们服务于防误用和复现，不能写成赛事明文要求；断网和哈希也不能证明历史上从未使用外部数据。

**需要按实际采用方案澄清：**外部预训练权重、外部拟合的标准化参数或特征、额外无标签数据、测试结构参与拟合、官方 AUPRC 和总分口径、复现范围与容差。正式训练包的标签和划分说明应先从实际材料核实。

规则报告还提出多模型组合、仅使用允许训练数据的自监督、最终训练集与验证集合并重训等问题。融合判断是：这些可以作为采用相应方案时的澄清项，**公开文案未展开某种实现方式，不等于已经禁止，也不自动要求所有开发在取得额外许可前停止**。四天基线可先选择依赖这些未决问题较少的方案。不要把技术建议、内部审慎默认和官方硬规则混写。

## 3. 最影响交付的八个问题

| 问题与证据性质 | 后果与最小处理 | 可验证出口 / 时间 |
|---|---|---|
| **划分输入表示受限，代码已确认。** runtime 要求独立 train、validation 角色，且原始输入限定官方来源 | 若官方仅有一份标注表，需表达原始数据加派生划分，不能复制一份文件冒充独立验证集 | B 定义成员与父数据；A 冻结划分；C 只在允许训练部分拟合。D1 首任务完成，D2 扩展 |
| **缺少可执行参考适配器，当前事实。** adapters 只有说明，demo 直接构造预测，runtime 测试 mock 执行 | 文档正确仍可能在保存加载、路径、权限和输出形状上接不起来 | A 提供检查器和参考工程，C 替换模型实现。合成样例和目标容器真实接入分开验收，D1 |
| **metrics 过于宽松，代码已确认。** 当前只要求 JSON object | completed 不代表结果可复算，两个漂亮分数可能不具有可比性 | C 输出逐样本记录，B 统一复算，A 冻结记录及版本；缺数据或口径不同明确标为不可比较。D1 打通，D2 完整 |
| **训练到预测缺少语义兼容检查，代码已确认但未复现错误预测。** checkpoint 哈希正确不代表任务顺序、正类、尺度或变换相容 | 更新推理代码或 schema 后可能消费不相容模型 | C 将实际任务顺序及预处理状态随 checkpoint 保存；A 检查兼容标识；B 校验正类及反变换。D1 建合同，D2 完整候选前落实 |
| **任务状态粒度过粗，设计问题。** 不应把所有任务确认作为 C 写接口的前置 | B 的局部未知导致整条模型工作停工 | 显式区分合成接口、已确认子集真实运行、完整最终候选；只阻塞依赖未知信息的动作。D1 |
| **真实环境和算力未经验证，当前证据缺失。** docker 可执行文件存在不代表 daemon、GPU、挂载与训练可用 | 首次实训、默认资源限制、缓存、重复预处理或多任务争抢 GPU 都可能扩大关键路径 | A 验环境，C 实测预处理/训练/预测/保存耗时及内存显存；用目标设备测量，D1 校准 |
| **Mac 路径问题已复现。** /var 与 /private/var 混用造成默认测试 6 failures、11 errors | 队友拿包可能直接失败；调整 TMPDIR 只是规避 | A 统一受信任根路径处理，保留项目内路径拒绝逃逸的约束；默认和规范 TMPDIR 都应通过。影响开发则 D1 修，否则 D2 |
| **最终候选只验证本地一致性，能力边界。** 模板、权重、预测关联通过并不证明官方受理或全部规则满足 | 把本地通过误报为比赛通过，或 D4 才发现全任务无法汇总 | D2 产出完整真实候选，D4 检查复现与平台实际回执；没有完整候选时优先补齐，不手工填预测 |

## 4. 必须记住的模板与评价细节

主 Agent 独立复算了官方模板，统计见 [main-template-verification.json](main-template-verification.json)：

- 16,379 行、22 个任务；`(task, sample_idx)` 唯一。
- `(task, drug_id)` 有 **218 组重复键**，如果按该键去重会丢失 **297 行**；另有 1 个原生空 drug_id。
- 模板 SHA-256 为 `8ee41589d2c98e7b93081c058b3f928ac09bea4b3ffc899fa13677051e9baa20`，与旧包记录相同。

这些重复和空值不能当作需要清洗的提交错误。读取模板时保留字符串；训练数据内部如何去重另按实际数据语义决定，不能把提交模板和训练清洗混用。

评价比较需核对稳定样本身份、真实标签、缺失模式、标签/变换与评价器版本。两个完整记录文件含有不同 y_pred，文件哈希不同是正常的；比较样本身份时应排除预测值。相同 split_id 或样本数不足以证明相同验证集。

原包 AUPRC 采用 average precision，是已声明的本地口径，尚未证实与官方完全相同。单类或样本不足的指标应保留 undefined 及原因，不能为了凑齐表格填零。重复分子、骨架或跨任务目标造成的验证泄漏目前属于风险，需要取得真实数据后判断；不能宣称已经发现泄漏，也不能把某一种 scaffold 划分当作官方强制要求。

## 5. 四天排期的修订版

假设 D1 上午有正式数据、D1 有可用训练环境，三人每天各约 8 小时。理论 96 人小时还要包含交流、核查、联调和返工；它不等于 96 小时 GPU 预算。每项训练的预处理、排队、运行、推理及重跑占用另外估算。

| 节点 | 三方并行安排与退出条件 | 未达到时的动作 |
|---|---|---|
| **D1 上午：独立开工** | A 交最小接口、样例及检查器并验证环境；B 确认真实结构与首批任务；C 开发 train/save/load/predict | 数据缺失则继续不依赖数据的工程；环境缺失则继续接口开发。真实运行保持明确阻塞，不伪造确认状态 |
| **D1 下午：第一轮校准** | 首个真实任务贯通数据、划分、训练、加载、验证与预测。记录阶段耗时和资源；继续检查具有不同数据规模/任务类型的代表性路径 | 用真实规模和吞吐推算全量及重跑预算。缩小模型复杂度、实验数量与框架范围；不能凭一个小任务或合成速度承诺全量耗时 |
| **D2：完整候选** | 补齐全部任务语义与基线，生成完整模板预测，复算验证并保留选模依据。合适时由有授权的负责人做首次平台提交验证 | 若不完整，D3 改为补覆盖、修语义和运行问题，暂停增益实验；未知任务不能用合成或手工值凑齐 |
| **D3：有界改进及冻结** | 已有完整候选后做少量可比较实验，保留主备；按测得时长提前启动必要的最终训练/重跑 | 任何新实验必须给完整验证与提交留下时间；无足够可比证据不更换候选，不覆盖已经验证的产物 |
| **D4：复现和交付** | 固定 checkpoint 推理复跑、语义与完整覆盖检查；如计划包含从头重训，应已按耗时提前安排。负责人核对末次有效作品回执 | 失败优先回退到最近验证过的完整候选；目标在本次工作窗口/实际截止的较早者前 4–6 小时完成提交，保留修正余量 |

四天缓冲属于团队计划，不保证平台响应时间。推理复跑成功与从头重训成功分别记录；不能将没有完成的训练复现写成通过。

## 6. 本地两份 best practice 如何落地

按 [Project Scaffold](../../../rules/skills/project_scaffold.md) 保留现有结构，并把真正影响接手的内容落到四份文档：PRD 定义独立开工及第一轮真实交付的成功标准；RFC 解释数据、适配器、评价与版本关系；test 记录分层验收；working 记录状态和实际经验。任务结果和版本进展不能只留在聊天里。

该 Skill 要求在动目录结构之前确认未来 public/private。当前只读评审无需因此暂停；原包当前不公开也不代表未来永久私有。后续确实启动结构调整时再按适用条件确认定位。不要为了四天项目大规模搬目录或重做已有入口。

按工作区唯一标准 [Best Practice Skill Writing](../../../rules/skills/bestpractice_skill_writing.md)，Skill 默认中文，写清目标、可判断的验收、资源/边界和产物，方法保留判断空间，只固定真实依赖。潜在风险可以写，但不能称为已发生的经验；系统 skill-creator 不作为本项目写作标准。

原包静态检查器要求固定四个标题，这是局部工具约束，不是上游规范的通用模板。当前八个 Skill 并未因此自动失效，四天内也无需为了形式统一全面重写。若实际改变入口或章节结构，再同步调整对应检查，并按原包要求用无前情任务验证实际路由；静态链接通过只证明结构检查通过。

## 7. 两份报告的融合取舍与校正

1. **共同采纳：**补可执行参考适配器、有来源的划分、可复算验证记录、精确任务就绪条件和真实环境计时；保留原包已有追溯能力。
2. **修正“必须全 22 任务确认才能跑”的过度概括：**现代码检查的是传入 schema 的任务集合，已可另传已确认子集；缺的是显式入口、状态表达及与全量提交的区别。
3. **修正规则报告模板重复数口径：**主 Agent 发现并复算后，原作者已将独立报告更正为 218 组重复键、去重会丢 297 行。
4. **收敛规则澄清范围：**多模型和仅训练集自监督等问题不升级为一切开发的前置许可。外部来源、真实标签和实际采用方案仍应有相应证据。
5. **修正工期表述：**12–20 人小时与 D2 全任务基线均保留为条件估算；D1 测量后重估，不能把目标当已验证能力。
6. **保留证据边界：**schema 兼容检查缺失由源码证明，但没有实际错误预测反例；跨平台路径问题已有复跑记录；数据泄漏尚未发生实测；官方复现审核尚未参与。
