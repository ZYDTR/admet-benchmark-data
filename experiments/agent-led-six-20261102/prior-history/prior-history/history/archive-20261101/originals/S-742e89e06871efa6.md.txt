# ADMET 冻结预训练路线：调研纲领与判断规范 V1

版本：V1，2026-10-30（Asia/Shanghai）。这是深度调研前形成并保留的初版；后续修订另存 V2，不覆盖本版。

## 目标

为兴智杯赛题 159 的三人团队，基于用户提供的真实数据和已确认的冻结权重规则，产出有证据、可比较、有停止条件的模型候选与实验优先级，让另一个没有对话历史的 Agent 能继续调研并判断结果是否足够支持决策。

本文件定义研究问题、证据标准和决策边界；不代替训练程序、下载脚本、模型适配器或逐条工具操作手册。

## 一、进入任务必须带上的上下文

### 已知输入

- 赛事：[小分子药物预测技术创新赛，赛题 159](https://www.aiinnovation.com.cn/web/#/trackDetail?id=159)。目标是用分子结构预测 ADMET 性质；A/D/M/E/T 指吸收、分布、代谢、排泄和毒性。
- 赛事公开说明禁止使用其他外部数据；用户在本次对话中明确确认，已向赛方核实：外部预训练权重可用，但必须冻结。按此确认开展研究，不再次把所有外部权重判为禁止。用户转述与公开页面分别记录来源。
- 用户提供的数据：[ZYDTR/admet-benchmark-data](https://github.com/ZYDTR/admet-benchmark-data)。本轮固定提交 `0275588ac7a5d3df032ec7dc0794cab21dfcfeeb`。
- 初步目录核对：22 个任务目录，每个含 train / valid / test CSV，根目录另有 upload_template.csv，共 67 个 CSV；该提交没有 README。此项只证明文件结构，尚不证明标签语义、划分方法或官方来源链。
- 旧对话提到的 MiniMol、CheMeleon、MoLFormer、Uni-Mol 等只是候选，不能当作预先选定的赢家。
- 研究者可以阅读公开方法资料、论文与源码，分析用户提供的数据。额外公开数据集、其他人的任务标签及在线性质查询不因此成为训练输入。

### 术语约定

- 编码器：把分子转为向量的模型；预测头：用向量预测具体任务的小模型。
- 冻结路线：预训练编码器保持固定，新增预测头仅使用获准的比赛训练数据学习。
- 从零训练：模型参数随机初始化后训练；不意味着从零重写 PyTorch 或 Chemprop。
- 研究结论：由本轮证据支持的有限判断；候选建议：尚待比赛数据实验的工作假设。

## 二、什么结果算调研完成

独立 Agent 应能仅凭交付物判断以下各项是否满足：

1. 22 个任务均有数据角色、任务类型、评价指标和有效样本规模的记录；未确认项用明确状态表示，不能留成看似已知的空白。
2. 训练、验证、测试与提交模板的对应关系被检查；发现重复、缺失、冲突或文件不一致时，说明它会影响哪项决策。
3. 对标签单位、正类、变换、缺失编码、划分方式，区分字节观察、作者说明和研究推断。
4. 候选包含少量有根据的冻结编码器，也包含简单指纹模型或随机初始化深度模型的对照；不能只在预训练候选之间挑赢家。
5. 入围候选都有确切 checkpoint、输入方式、预处理要求、实际冻结协议、使用许可证据、资源条件和最低成本验证问题。
6. 主要性能判断能追溯到原论文、真实实验协议或可核对代码；论文成绩不直接写成本赛事成绩。
7. 建议有优先级、反对理由、可能改变判断的证据，以及停止或追加研究的条件。
8. 交付物能让未参与本轮的 Agent 继续工作：知道已查什么、哪些证据仍不足、下一步能做什么，以及不能从当前结果推出什么。

无训练结果时，允许以“完成文献与数据研究，模型效果待本地验证”结束。不能为了完成调研而虚构分数、运行耗时或模型优势。

## 三、研究大纲：问题与它应改变的决策

| 研究问题 | 必须拿到的证据 | 应影响的决策 |
| --- | --- | --- |
| Q1 数据究竟是什么 | 固定提交、文件哈希、列名、各划分样本数、train/valid 标签统计、模板字段 | 研究范围、适配器和数据处理 |
| Q2 每个任务要预测什么 | 标签定义、单位、正类与变换的来源；缺失与异常的实际情况 | 损失、输出、任务是否可联合 |
| Q3 怎样评价才与比赛一致 | 模板指标、官方评价文字、实现差异、总分公式及未知项 | 验证器、比较尺度、候选选择 |
| Q4 什么知识值得迁移 | 预训练目标、分子范围、下游任务和冻结实验 | 编码器候选与优先级 |
| Q5 哪些论文结果可用于本次决策 | 确切权重、是否更新骨干、划分、预测头、搜索与集成预算 | 证据强弱与公平比较设计 |
| Q6 哪些简单方法可能足够好 | 指纹/描述符、新训练深度模型、独立基准中的适用范围 | 对照与最低可交付方案 |
| Q7 组合是否值得投入 | 逐任务优劣、误差互补、额外成本及验证选择偏差 | 单任务/多任务、特征融合、集成 |
| Q8 如何在现有工程中真实落地 | 固定资产加载、特征接口、资源上限、运行与复现约束 | 首轮实验包和三人分工 |

研究投入优先考虑：这个未知是否会改变合法性、评价正确性、候选排序或交付能力。背景知识只展开到足以解释这些决策；不把生物学百科或论文目录当成果。

## 四、证据契约

### 事实、主张和判断分别记录

每个重要判断至少包含：主张 ID、原始来源 URL、定位、获取日期、简短原文或可复核计算、证据状态、适用范围、对决策的影响。

建议的证据状态：

- `observed`：直接从指定字节或代码观察到；必须注明版本与观察范围。
- `author_reported`：论文或作者报告了结果，但本轮未独立重现。
- `corroborated`：另一个独立原始研究或本轮可复核分析提供支持；说明独立在哪里。
- `user_confirmed`：用户明确提供的赛事澄清；不能伪造为网页原文。
- `inference`：研究者推断；列明前提和可反驳条件。
- `unknown` / `conflicted`：不足或冲突；写清对结论的影响和可继续的工作。

来源质量按问题判断。官方赛事材料决定公开规则；数据字节决定文件实际内容；代码可说明实现；论文实验支持其限定范围内的性能。作者的 README、论文和模型卡通常属于同一来源链，不能算三个独立验证。多个 Agent 复述同一来源也不增加独立证据。

保留一手来源；技术判断优先原始论文、源码、官方文档和第一手问题记录。问题记录能证明某版本出现过问题，不自动推翻整个模型。论文名气、发布日期、参数量和下载量不能替代适配证据。

### 必须检查实验协议

看到“fine-tuning”“frozen”“linear probing”等名称时，检查实际更新的参数，不凭名字分类。至少记录：骨干是否冻结、预测头是否新建、BatchNorm 等状态是否变化、是否有额外可训练模块，以及结果来自单模型还是集成。

研究最优模型与研究最优完整方案是不同的问题。比较编码器时，记录预测头和调参预算；允许必要的配套调整。若同时改变表示、清洗、划分、损失和集成，只能评价整套方案，不能把提升归因给其中一个部件。

### Prior work 与反例

对主要候选阅读其相关工作，追溯会改变选型的代表性前作。区分它新增的是预训练目标、架构、训练规模、评测方法还是工程便利。无需无边界展开全部引文，但不得直接接受“首次”“最好”“普适”等作者定位。

每个优先候选至少写一个合理反例或最弱前提：什么数据特征、使用限制或独立结果，会让它不再值得优先投入？

## 五、数据与规则边界

- 固定并保留原始数据。清洗、去重、标准化、切分调整作为单独假设；不要自动覆盖原文件。
- 训练/验证标签可以用于获准的研究与评估；测试标签若意外可见，隔离并报告，不拿来调参、挑模型或计算对比成绩。文件名不是数据角色的唯一依据。
- 不因任务名与 TDC 一致，就下载 TDC 数据补齐、替换或“纠错”；同名任务不等于相同版本与划分。
- 公开源码可以研究，但不默认执行其自动下载、预训练、额外特征库或 benchmark 数据加载。
- 冻结权重获准，不等于额外数据、教师标签、其他训练资产和测试集拟合自动获准。对未涵盖资产单独说明边界，不重新争论已确认的冻结权重许可。
- 对训练集学习得到的缩放、缺失填充、特征选择等参数，仅在相应训练划分拟合。
- 多任务组合要检查相同分子跨任务、跨划分的情况，以及不同任务标签是否真正可比；不能把所有表直接拼成统一训练集。
- 未确认官方聚合公式时，报告逐任务指标与明确命名的团队选择准则；不能把自定义平均数标成官方总分。
- 调研期间不自动报名、提交预测、发消息给赛方或发布数据；这些不是本次交付。

以上是当前任务约束与预防性检查，不是伪称已经发生过的失败记录。

## 六、研究组织：主 Agent 应负责的判断

采用 grapeot Deep Research 的“提取主张—交叉查证—整合分歧”思路，工具按实际环境选择，不硬绑定 Tavily 或特定子 Agent 名称。

主 Agent 保持一份共享研究问题和主张表。子 Agent 围绕不同证据功能工作，同时保留有意重叠，尤其共同检查：冻结结果能否迁移、数据是否真的对应、公开成绩协议是否可比、工程上能否复现。

建议覆盖四类视角，可按并发能力分批执行：

- 数据与评价视角：从实际字节判断问题规模与关键限制。
- 表示与前作视角：研究不同预训练目标及其冻结迁移证据。
- 反证与复现视角：查对照、独立评测、实现问题和不适用范围。
- 决策与交付视角：把证据转成有限预算的实验组合与停止规则。

子 Agent 返回结论时必须附来源和限定条件。主 Agent 自行回查直接支撑主要结论的原始材料；不能用一份总结验证另一份总结。

整合分歧时，先判断是否来自不同 checkpoint、版本、数据划分、冻结方式、指标或预算。保留真实分歧，不按多数票选答案。若冲突足以改变优先级，补做范围更窄的核查。

形成初步建议后，另请无前情 Agent 从“证据怀疑者”和“实际使用者”视角指出最脆弱前提。它们的意见应转化为补查、限制结论或明确收敛，不能仅作为赞同票。

## 七、候选决策与停止条件

### 候选状态

- `exclude`：当前规则或输入条件明确不满足；附原因和重开条件。
- `defer`：可能有价值，但证据、接口或成本不足以支持当前投入。
- `pilot`：有合理证据，值得进入有限预算的本地实验；不代表已证明优于基线。
- `preferred`：在本赛事数据、可比较协议下已有足够实测支持；只有文献时不得使用此状态。

不规定所有任务必须采用同一模型，也不规定必须按架构类别平均分配预算。优先级由预期决策价值、证据强弱、接入成本和剩余资源共同决定；缺少资源数据时给条件化方案，不编造 GPU 小时。

### 本轮结束的条件

- 数据画像足以识别会改变首轮实验的主要风险，关键未知已写明。
- 首轮候选数量可执行，且每个候选都有不同的研究价值；不为凑名单添加模型。
- 每项核心建议有证据、反例和下一实验；继续查文献的预期价值低于跑首轮对照时，可以收敛。
- 若训练数据语义仍不完整，停止受影响的正式训练建议，但继续完成不依赖该未知的模型与工程研究。
- 真实训练与性能验证不在本轮已完成事项里，除非确实执行并保留证据。

## 八、交付规格与下一轮可复用性

主交付是一份独立可读的决策报告，开头回答“现在先试什么、为什么、什么结果会改变判断”。支撑工件至少包括：

| 工件 | 必须包含 |
| --- | --- |
| 数据画像 | 版本与哈希、22 任务表、标签与划分事实、异常、未知与影响 |
| 候选表 | checkpoint、输入、冻结证据、对照协议、成本条件、建议状态 |
| 主张与来源表 | 来源 URL、短摘录、版本、状态、支持/反驳关系 |
| 逐源核查记录 | 主 Agent 回查了什么、有哪些误读被纠正 |
| 研究清单 | 子 Agent 范围、产物、检索覆盖、未覆盖内容 |
| 反方审查 | 最弱前提、补查结果、保留的限制 |
| 规范修订记录 | 本轮实际发现 → 为什么 V1 不够 → V2 改了什么 → 如何验证 |

主报告使用中文 Markdown；网页引用使用完整 URL。机器可复核的统计可另附 JSON/CSV 和分析脚本。原文摘录保持短小，遵守引用限制。

V2 应把稳定的判断原则留在主文件，把本次数据事实和模型信息放入按需引用的材料。不要让后续 Agent 为一个窄问题读整份研究档案，也不要让必要规则只存在于本次聊天中。
