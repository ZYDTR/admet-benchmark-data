## 路由验证与一次实际迭代

| 自然语言场景 | 观察到的路由与行为 |

| 准备 CSV，处理空ID/重复ID/超1分数 | submission → 无真实推理时 experiment；保留原字符串，不截断score，识别合成演示 |
| 只比较已有两次结果 | 修改后的 experiment → run-comparison/evaluation；没有加载运行/模型接口，不启动训练 |
| 单纯翻译 | 只读根入口后直接翻译，不加载state/INDEX或比赛技能 |

观察到的路由问题已修订：experiment 明确区分只读比较与启动运行；AGENTS 先判断请求是否与项目相关。之后分别用新的独立 Agent 验证比较和翻译。没有用关键词规则或向执行者透露预期答案来替代行为验证。

## 独立代码审查修复

以下 7 个具体问题由独立审查实际复现，已修复并做针对回归；审查者再次确认原反例被拒绝或正常通过。

1. 原始输入路径别名可把同一文件登记为训练/验证：改为规范化文件身份去重。
2. 产物路径别名可把同一文件登记为checkpoint/metrics：改为规范化输出身份去重。
3. root + umask 077 导致非root worker无法遍历快照：显式设置目录/文件权限，并检查训练和预测路径。
4. 镜像检查期间配置变坏留下无run.json目录：独占创建后立即建立preparing，失败留记录。
5. 空容器值被当作已确认标签语义：明确要求非空字符串。
6. 只信plan.json模板条目可与冻结输入冲突：核对run记录哈希约束下的输入控制文件、manifest及模板快照。
7. 合法大整数预测在导出和验证中使用不同语义：统一float转换，并说明数值表示范围。

另修复了全套无环境变量启动测试时的测试模块导入问题。正常train/predict快照链由运行器实际代码生成并通过候选验证，Docker调用仍为mock。
