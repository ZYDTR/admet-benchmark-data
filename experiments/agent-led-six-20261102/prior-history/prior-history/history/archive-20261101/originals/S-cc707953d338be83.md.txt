# 数据准入边界

## 官方规则与团队默认

[赛事契约](../competition/contract.json) R01 明确禁止其他外部数据。对尚未解释清楚的预训练权重、外部拟合参数、教师分数和额外无标签样本，当前团队默认不接入。拿到明确答复后记录来源与适用范围，再修订配置和政策。

查算法论文或 API 文档不会自动变成新增训练样本。用外部服务给官方分子补标签、输入外部分子嵌入、加载外部模型或归一化参数，则改变模型输入或初始化来源，必须审查。研究笔记、网上代码中的常量和配置同样可能携带这类信息。

## 准入材料

原始文件由 B 从官方授权途径取得，放入 `data/official/`；记录来源、下载时间、角色、SHA-256、文件说明和审查者。下载/来源证据应是实际记录，不能用本项目的规则说明假装已下载训练包。原始文件与证据的合法性由团队核实；程序只验证路径、哈希和声明完整性。

配置 schema 见 [runtime contract](runtime-contract.md)。所有未接入输入保持 pending。当前示例不能靠把 status 改成 approved 获得有效数据，缺失文件、证据和标签仍会阻塞。

## 派生数据

首版执行器只接收官方原始输入。特征、词表、标准化器和缺失掩码在审查后的适配器内生成，记录父输入、代码版本和拟合数据范围；保存在该 run 的产物中。独立派生缓存的复用接口尚未提供，不能将缓存标为 competition_official 来绕过来源契约。

首版正式训练入口要求独立的 train 与 validation 文件。这是当前实现支持的输入形式，不是已确认的官方包结构。若正式包只给一个标注文件，需要 B/C/A 先增加有父输入和划分证据的分区接口；不能复制同一文件分别登记角色，也不能把自行切分的文件冒充官方原文件。实际接入应由 harness-development 完成这项明确的兼容调整。

## 缓存与镜像

HF_HUB_OFFLINE 仍可读取已有缓存，所以每次运行使用独立 tmpfs 缓存，并审查镜像与适配器是否预置权重、拟合参数或数据。镜像哈希只固定内容，不能证明内容合法。镜像构建阶段可下载批准的软件依赖，不能顺便预下载训练资产。依赖与模型数据分开审查。

## 发现误用时

标记受影响的 run；保留记录；追踪派生特征、参数和 checkpoint 的依赖；从允许的输入重新生成受影响的结果。已提交且确认受影响的情况由参赛负责人依据官方要求处理。Agent 不替用户发送说明或操作赛事平台。

## 当前已观察的来源提示

Chemprop 文档明确说明某种 descriptastorus 归一化使用 ChEMBL 分子拟合的参数；使用相关功能前核实政策。此处是已核实的工具特性，不是“本队曾违规”的经验记录。来源见 [sources](sources.md)。
