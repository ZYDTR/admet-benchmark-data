# 官网提交与成绩取回

类型：Workflow。v0.1.2，2026-11-01。按工作区 Best Practice Skill Writing 编写。唯一项目入口：[AGENTS.md](../../AGENTS.md)。专用角色及当前模型以 `submissions/thread.json` 和本次REQUEST为准；用户已将首次 Terra 执行更换为新的 GPT-6.1 Sol Thread。材料总入口是 [submissions/README.md](../../submissions/README.md)。现有Sol回执已记录两次正常文件选择上传和官网46.418分；第一份按顺序及页面状态变化关联基线，官网没有提交ID且时间戳异常；第二份仍未获得可归属新分数，不能宣称四份均完成。

## 目标与权限

把用户此次指定、已验收的模型预测提交到正确赛事与本人已有参赛团队，取得官网提交编号、状态与实际分数；每个结果都能反查上传文件的字节摘要和来源模型。

2026-11-01 用户明确授权新专用 Thread 登录内置 Browser、提交当前训练结果并查看分数。此任务是原训练流程“不自动上传赛事”的人工触发例外，仅在对应 `REQUEST.json` 内有效；训练、取回、Chat网关仍无自动赛事提交权。之后只响应用户在本专用 Thread 的手动请求，不订阅训练完成消息、不建定时、不自动消费新文件。初次请求覆盖首批登记候选，不覆盖未来批次。

亲自执行，不派生 Agent、Codex/OpenCode 会话或 CLI 模型，不给其他角色派任务。不能训练、重新推理、清洗、读取私有验证标签、改动原预测或利用官网分数自动调参。允许按当前网页要求复制/重命名已核验 CSV，字节必须不变。

## 材料与提交条件

读取 `submissions/CURRENT.json` 指向的批次、其 `REQUEST.json`、`manifest.json` 和验收结果。先核对摘要、每行 task/sample_idx、ID/SMILES、模板非预测列、行序、行数及有限数值。空/重复ID合法，身份不是单独的drug_id。16379行/22任务是现有模板的观测值；以当前网页模板与冻结原件核验，格式变化时报告实际差异。

现有完整基线可直接提交；单任务预测必须有已验收的完整候选，不能把273行 valid/test 混合预测直接上传。候选合成仅允许固定脚本按任务/原行号搬运原模型test预测，不做平均、截断、挑值、补值或任何数值后处理。所有未替换任务原样来自登记基线。该组合来源须进入回执，不能称作22任务全部重新训练。

官网入口来自项目规则快照 `evidence/official-contract-20261029.json`。通过内置 Browser 的正常页面核对赛事159、登录账号/现有团队、最新公告、当前提交入口、额度、格式及“末次有效提交”等计分规则。登录使用当前会话或已有获准凭据；不把密码、Cookie、令牌写入记录。验证码/本人确认/新协议按工具要求交给用户处理，保留准确页面，不绕过。不能猜团队、创建新报名或代替用户接受新法律协议。

优先在提交前读取现有历史。每项上传前保存意图（候选ID、SHA、文件名、时间）；上传响应不明时按历史编号/文件名/时间核实原提交，不能直接重传。只在页面明确失败且无已接受记录时有界恢复，保留原故障。重复触发先读取本地回执与官网历史，已有成功或排队记录只查分，不再消耗次数。

本次按REQUEST顺序提交，最多登记数量且服从当前额度；额度用尽保留剩余项，下次用户手动触发继续。不因暂未出分另建后台监控。当前turn可有界查分（默认总计20分钟，间隔不小于60秒；每次工具等待不超过60秒）；仍评测中则保存pending及准确提交链接。不得把本地验证分数或模型自报当官网成绩。

## 上传选择器的已知误判

首个Terra会话点击“上传”后，只看见网页遮罩/转圈，反复刷新并错误断言没有文件选择器。用户实际看见系统文件选择器；随后 `cua.getApp('Codex')` 返回 `Computer Use is not allowed to use the app 'com.openai.codex' for safety reasons.`。这证明应用控制被拒绝，不证明官网不可用，也不证明所有Browser上传能力都不可用。原始拒绝及交接见 `submissions/handoffs/sol-takeover-20261101/tool-rejection.json`。

需要区分网页内容、网页触发的文件选择事件和原生应用窗口。上传前先读当前Browser工具文档；若文档提供公开的文件选择器事件及 `setFiles` 或文件输入能力，使用其正常接口，只填已核验CSV并以网页接收状态验收。需要等待文件选择事件的接口，应在点击前按文档建立监听；网页截图未含原生对话框不能推出没有弹出。现有弹窗状态不明时先确认，避免刷新丢状态或反复触发。

不猜测API、不访问隐藏端点/Cookie、不用脚本/其他应用控制绕过对Codex原生应用的拒绝；拒绝不会因换Thread或模型失效。若Browser公开接口确实不支持或也被拒绝，准确说明哪项能力缺失，仅请用户完成必要的选文件动作，之后由执行方继续核对上传和取分。不得凭旧错误断言必须用户手动，也不得承诺更换模型一定解决。

记录使用实际换行的JSON/JSONL/Markdown，写后重读解析。取回网页状态和工具拒绝按原件保存；不得把“已点击上传”当作文件已被网站接收。

Sol接手时另发生下载事件超时，但两份模板实际已在本机Downloads；用户催促后才找到。下载事件未返回不等于文件未落地，应在已知下载位置核对本次文件的时间、名称、大小和内容摘要，找不到才报告缺失；不因此换隐藏通道绕过浏览器拒绝。两处官方模板有7611行drug_id格式差异，必须保留实际版本与差异，不能任意改候选内容。

官网旧分数持续可见不代表新文件已经评分。回执分开记录文件已送出、网站已接收、结果已与候选对应；无提交ID时保留上传前后状态及可区分证据，时间戳矛盾明确标注。第二候选已上传但仍显示旧46.418的原件见 `submissions/batches/existing-models-20261101/attempts/20261101-sol-02/`；先对账，不把旧分数给新候选，也不为催出分重复上传。新版只约束下次手动任务，本次不重新提交。

## 结果文件

每次操作保存到 `submissions/batches/<batch_id>/attempts/<独立编号>/`：

- `receipt.json`：候选ID、SHA、实际上传文件名、原模型来源、赛事/团队身份（避免多余个人信息）、提交前额度、实际提交编号/链接、提交/观察时间、网站原始状态和原始分数字段、是否末次有效提交、原始证据路径。
- `evidence/`：相关页面正文和截图，成功后在回复中给出截图及可点开的提交/成绩链接；不保存凭据。
- `TIMING.json`：从接到任务到登录、校验、提交、评测、取回的整段耗时，等待与操作分开。
- `REPORT.md`：明确区分已登录、已提交、已受理、已出分、失败或需要本人处理。组合候选总分不等于Caco2单任务分；网站没给的分项、公式或排名不推算冒充官方结果。

批次 `status.json` 更新每候选最新状态；`submissions/RESULTS.jsonl`只追加真实事件，不改旧记录。无合格候选、网站不可用或权限不足时留下具体原因和恢复入口即可，不扩大任务。完成或明确阻塞后直接向该Thread里的用户报告，后续由用户手动触发；不要求主控继续批准、不反复通知主控。
