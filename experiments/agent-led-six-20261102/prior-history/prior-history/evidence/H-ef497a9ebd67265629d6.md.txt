# 广度研究 Prompt 复核与修订

2026-11-01。主控亲自核对实际发送全文、首版与同请求补全版；本次没有再次向Pro发送研究，没有新增训练。

结论：用户的质疑成立，主控Prompt及交付合同有可定位的缺口。原文写了“全面”不等于已把任务交代到可验收程度。应同时记录输出缺陷与主控交接缺陷，不能把观察到的遗漏直接解释成模型能力不足。

## 原文已要求什么，仍缺什么

| 发现 | 直接证据与责任判断 | 当前修改 |
|---|---|---|
| 要求广泛，但未逐问题验收 | 原文明确要求22任务全景、小/中/大预算、广泛方向及完整配置；不能声称主控忘了要求全面。原返回检查只看文件/字段，没有逐问题答复映射，因此少一档预算也可通过部分结构检查。 | 主控先封口decision_contract；每个问题有完成条件、产物位置、答案/证据/缺口回执。遗漏不能宣称全部答完。 |
| 数量示例可能形成锚点 | 主控模板主动给20–40示例，首版选40+24。但仅时间顺序不能证明这是唯一原因。 | 删除通用模板中的默认数量例子；规模由任务覆盖、信息量、实际成本与预算推导。研究方向数不受首批执行数限制。 |
| 方案的计数单位未讲透 | v1字段task/exact_config隐含单元却未明确一行单位；首版将零fit门槛、10任务×2配置、未选定S2任务放进同一实验数组。 | 确定实验逐task/config/split展开，可列多个明确seeds；零fit准备放指南；待结果决定的分支单列并给选择、触发、跳过和预算上限。 |
| 科学语义与机械验收脱节 | 原文要求指标方向和对照，首版仍统一maximize且混淆多因素组合与单因素；v1没有独立loss/早停/预测尺度字段，检查器不核对任务指标。 | 显式training_objective与design_type；检查任务、指标方向、训练目标、单因素声明、自依赖和资产版本计数。主控仍须核对实际配置和科学结论。 |
| 长清单挤占问题定位 | 55项阅读要求含42项历史，实际值里独立复算字段还重复背景和研究问题。完整材料有用，但主问题在长合同之后、不易逐项回收。 | 问题及完成条件前置；精确阅读JSON放末尾；按决策依赖安排阅读优先级，仍保留全部必读与原件。独立复算字段只列具体计算。 |
| 研究完成与工程就绪混为一关 | 未读、不可达、未记录、可计算、需新实验是不同缺口；比如21任务单文件train摘要不在公开材料中，Prompt无法创造事实。 | 缺口逐项关联受影响结论/方案。一个方向的工程未就绪不应推翻全部研究，也不能将needs_evidence一律当成Pro没研究完。 |
| 主控观点及建议被升格 | 首版可把推荐的valid使用频率当硬规则；主控倾向也可能被当指定答案。 | 主控观点是待反证假设；研究建议和用户/赛事硬边界分开，不新增“一任务只准看一次valid”的规则。 |

原验收中“Pro unfinished research”等origin是对当时产物状态的描述，并非已证实的根因归属。本报告补充主控责任，保留原记录，不改写历史。首版MAE方向和悬空引用仍是实际输出错误；不能反过来把所有错误都归因于Prompt。
