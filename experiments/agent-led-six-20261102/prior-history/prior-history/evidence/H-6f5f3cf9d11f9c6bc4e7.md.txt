# 按结果导向重写 Skill，撤除固定流程脚本

2026-11-01，主控亲自执行。用户要求重新完整阅读 Best Practice Skill Writing，以结果确定性优于过程确定性重写，并删除固定流程脚本。本次完成了项目规范、执行入口和派发参考的修改，实际删除 351 个文件，其中 227 个 Python 源文件、1 个 Python 缓存文件。没有发起新训练、重放旧任务或向 Pro 新发请求；新版真实执行效果尚未验证。

## 改变的核心

原设计的问题不是出现了几个语法错误，而是 Skill 文字允许灵活处理，实际任务却绑定整包运行实现和固定准入。环境、传输和监控的普通变化被变成主控反复打包、审查、再派发的依赖；实现没有共享分支，又实际缩窄了用户允许的算力使用范围。继续给同一套流程补分支无法解决这种设计冲突。

当前由主控交代科学目标、输入、权限、预算及可复核的结果，执行 Agent 根据现场选择部署、选卡、采样、诊断和恢复方法。在原授权范围内可修复自己的运行辅助实现、核验后继续，不为普通修复重新申请整个代码包准入。科学定义、额外实验和权限变化仍由主控判断。工具提供事实与计算，不代替 Agent 解释异常；没有旧工具支持不代表任务被禁止，工具返回 PASS 也不代表训练成功。

硬边界保持：外部编码器参数及 buffer 冻结；选模阶段仅 train.Y 学习；训练/准备不拿逐行 valid 真值；保留数据原行与预测映射；海南任务写入仅限授权的 project-compute 路径；不停止他人服务、不改删他人文件；共享余量必须有不影响他人的依据；未知启动先查原作业，不能重复学习。计算预算仍有效，主控自设检查点不机械等同用户截止。

以下路径相对项目根，完整逐文件路径、大小和 SHA-256 见 [DELETION_MANIFEST.json](DELETION_MANIFEST.json)，实际删除结果见 [DELETION_RECEIPT.json](DELETION_RECEIPT.json)。

- 各项目 Skill 的 `scripts/`、`tests/`：准备包、输出封口、Prompt 渲染、索引、评审与训练证据检查器及测试。
- 六项周期 `runtime/source`、`runtime/proposed`、`runtime/tests`：原部署、选择、监督及恢复实现。
- 该周期 `training/operator/attempt03-main-v1` 的活动源码、candidate 整包及顶层构建/检查程序；包含配套配置和可部署压缩包。

先核验归档每个成员与原件摘要一致，再实际删除所有列出的路径。只移除已为空的对应目录。归档 [retired-procedure-code.zip](retired-procedure-code.zip) 共 2,351,629 字节，SHA-256 为 `407884f100a41ff7625a65175dde86d667fffb7a98f764221cb98f42d01ee028`。预删除清单的 `deletion_performed:false` 保留其当时含义，完成事实以独立删除回执为准。

旧 run 的原始消息、冻结证据和科学模型/数据没有删除；其中可能包含历史代码副本，只能解释历史，不能恢复成下一任务入口。保留科学计算、既定评分定义、原始资源测量和通用连接能力，没有新建一套替代流程引擎。本次没有远端删除；远端历史文件不作当前执行入口。独立海南资源观察继续原任务，没有新增训练授权或恢复已关闭的 009 请求。
