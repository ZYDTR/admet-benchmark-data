# ADMET 冻结底座训练

Workflow，2026-11-01。按[工作区写作指南](../../../../rules/skills/bestpractice_skill_writing.md)重写。适用已获训练授权的宿主执行 Agent；[项目入口](../../AGENTS.md)、[policy](../../policy.json)与当次科学任务共同确定范围。目标是交付可复现的新模块和完整预测，并证明实际执行遵守硬约束。

## Agent 可以决定什么

在已授权任务、预算和写入范围内，执行 Agent 自行选择和调整部署、环境复用、选卡、监控方式、诊断工具及恢复方法。可以检查真实依赖、改自己的运行辅助代码、验证修复并继续；记录变化和验证依据。普通路径、参数传递、日志、临时文件、连接和工具兼容问题，不要求为每次修复回主控重新批准一整包代码。工具只是当前方法，不具有高于用户目标的地位；没有旧脚本、旧布局或检查器支持某分支，不等于任务被禁止。

当前项目不再提供必须调用的固定 launcher、receiver、watcher、状态机或准入脚本。已删除的旧实现及冻结快照仅供解释历史，不作为下次运行模板恢复使用。需要临时自动化时围绕本次具体计算、采样或证据处理编写最小实现，实际审读和验证；不要重新造一套决定所有现场分支的通用流程引擎。

科学任务定义保持明确：哪些任务、底座版本、允许学习的模块、输入、损失/早停/评价含义和实验预算。改变这些含义、增加实验或超出权限时回主控判断。复现依赖记录实际代码版本；记录版本不等于禁止修复运行方法。已开始的作业先查真实状态，避免新方法与旧进程同时执行同一项学习。

## 必须守住的边界

- 外部预训练参数和buffer保持冻结。编码器eval、编码无梯度，优化器排除它；新模块是本次允许学习的部分。实际训练前后完整状态与原权重摘要可核对，仅磁盘文件未变不足以证明冻结。
- 当前只用官方train.Y学习，标准化仅拟合内部fit部分。valid用于指定宿主评分/分析；准备和训练方只取得盲valid/test及允许的汇总诊断。最终train+valid合训另议。保留原行、原分区、原标签及预测身份，不自行清洗、补标签或拟合test。
- 海南操作先完整读[连接Skill](../../../../rules/skills/hainan-compute-access/SKILL.md)及命中引用。全部项目写入及缓存、临时文件、依赖副作用限于project-compute与本任务允许位置；不停止他人的服务、不删除或改动他人文件。共享UID不证明作业属于自己。
- 资源充足且核实不影响他人时，可以用空闲卡，也可以共享剩余资源。选卡和并发数由当前负载、预计峰值和运行影响决定，没有零显存、固定卡号或通用单作业限制。现有记录不足时补查；不能把一次低利用率或空余显存当作共享已经安全。
- 同一逻辑任务不能因未知响应重复启动。已完成学习先收集核验；恢复可用checkpoint时核对输入、模型/优化器/RNG与进度。原任务已退出且符合已委派的恢复范围时可有界恢复；重新开始学习的次数或预算未获委派时由主控决定。保留旧失败和所有尝试消耗。

## 现场判断与工具使用

[资源日志](../../resources/hainan/README.md)可减少盲查，现场核对解决陈旧或不足证据。启动时掌握当前GPU健康、负载和任务身份；运行中的采样频率、控制方式由风险和作业时长决定。持续的数值采样可以自动化，异常解释、是否需补查、怎样修复及如何续接由 Agent 结合原件判断。

确认真实越界、资源干扰或无法可靠约束影响时，控制自己的作业；不因模型自报正常就忽略风险。瞬时连接失败、进程正常退出或文件原子改名不自动等于训练失败：保存原始返回、时间、PID/启动身份和错误，区分已确认失败、可恢复故障、观察不足与已完成。需要暂停才能澄清时只暂停受影响的自有任务；不把缺字段填零，也不凭未知结果继续依赖动作。偶发连接恢复沿用通用连接Skill。

复用环境、权重或冻结原特征时核对来源和行映射；只读复用已批准环境，安装或修依赖限本任务私有范围。缓存须与输入、编码器、特征含义、形状和行序一致；拟合后的统计量随fit划分重新产生。无需为每个新头重新部署一整套运行包装。

## 怎样判断完成

| 结果 | 主控能够复核的证据 |
|---|---|
| 确实完成指定学习 | 实际设备计算、优化步数、新模块张量变化与有限loss/梯度；实际头结构、超参数、seed和停止原因匹配任务。 |
| 编码器冻结 | 参数及buffer训练前后摘要相同，优化器/梯度状态与实际源码一致；原权重身份未变。 |
| 数据与输出正确 | 全部目标行有有限预测，task/split/原行序及原属性对应；预处理可重建，预测回到约定尺度，重载结果一致。 |
| 环境、资源与写入符合边界 | 实际环境和命令、GPU UUID、自有PID/启动身份、相关负载和实际写入证据；退出和自有资源释放有依据，未覆盖范围说明清楚。 |
| 失败没有被掩盖 | 原始错误、不同尝试、worker与外层工具退出分别保留；科学产物可用性单独判断，不用一项success代替全部结果。 |

检查可以用通用工具、临时计算和主控独立审读组合完成，不要求某一脚本返回PASS。验证真实使用的实现与消费端，测试数量不等于真实训练可靠。

## 交付与接续

每项run保留科学任务、实际源码/环境/输入身份、原始日志、模型和预测、核验结论及当前状态。目录由当次任务约定；旧产物不覆盖。状态至少说明开始/完成学习、优化步数、冻结与写入核验、资源释放、预测/评分/上传是否发生，以及未知项。未知写未知，不能默认成功。

报告完整Thread耗时，并区分准备、诊断、资源等待、实际计算和取回。主控自设的进度检查点用于重新判断，不机械终止尚有授权的工作；用户明确的截止和实际计算预算照常遵守。执行方在原范围内解决普通问题并继续，主控只接收完成、实质风险、科学/权限/预算变化或无法自行解决的阻点。其他独立任务是否能继续由依赖关系判断，不因一项失败机械停止全部批次。

专职执行Thread为gpt-6.1-sol/xhigh；它不再派生Agent或转授海南权限。算力观察独立运行。主控亲审实际结果；本版只有文档与入口清理完成，尚未通过新一轮真实训练。

## 真实教训

六项配对试验曾因固定包装中的PID调用、临时文件改名、旧日志冲突和部署清单错误反复返工；一次监控先拒绝后记日志，丢掉触发证据。Skill允许共享，实际运行路径却只支持无其他工作的卡。这些问题说明结果边界与实现方法必须分开，不能靠给同一流程继续叠分支解决。历史与删除记录见[本次重写](../../audits/agent-led-execution-20261101/REPORT.md)，原始失败保持可查。
