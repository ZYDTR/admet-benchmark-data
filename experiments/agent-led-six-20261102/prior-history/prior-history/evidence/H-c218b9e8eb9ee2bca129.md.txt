## 共有的是可读证据和固定版本

公开包以 START_HERE、ANALYSIS_BUNDLE、manifest统一导航。集中可读入口嵌入核心科学源码和证据，明细仍保留完整文件。大二进制有安全只读结构摘要；外部底座原权重用来源和SHA引用，未随意再分发。发布文件的源摘要、脱敏/排除原因和原件位置在source-map逐项记录。不能把链接可访问当成Chat已经阅读。

指定网关已验证目标Chat处于Pro选择状态，用户已确认其subagent能力，不再做能力调研。实际发消息前仍核对正确聊天与模型选择。Prompt包含固定commit入口和身份，首轮要求六份完整正文和文件，已收回六原文件；后续模板改为短正文、完整文件及可计算的读取回执。现按用户纠正，消息发送与读取使用应用原生工具；模型选择、全文和附件能力不足分别留证，不使用内置浏览器补足。原文截断要明确修复，不把预览当全文。

本地建议在 `admet_training/exchange/` 建立如下逻辑空间，引用已冻结原件而不覆盖旧 run：

```text
exchange/
  registry.json                   # 角色、目标Chat、权限和预算身份
  events/                         # 分生产者只追加事件
  assets/<sha256>/                 # 可复用底座、固定数据和环境证据
  runs/<run_id>/manifest.json      # 指向原件，绑定完整摘要
  rounds/<round_id>/packet-vN/     # 发送时封口的不可变证据包
  rounds/<round_id>/chat-replies/  # 原文、附件、消息ID及摘要
  rounds/<round_id>/decision/      # 主控采用/不采用及理由
```

全部获准、可能影响质量的现存原件都保留。Chat 的阅读顺序分层，不把摘要当作替代品：

| 层次 | 内容 |
|---|---|
| 首读入口 | 本批要回答的问题、来源规则和差异、完成/失败实验总表、可比较性、主要曲线、缺失材料、历史已否定方向、在途实验和剩余预算。 |
| 可核查明细 | 实际配置与源码、全部 epoch/已有 batch 日志、样本身份与划分、获准逐样本预测和残差、失败日志、冻结及资源证据、每个结论的文件/行定位。 |
| 完整原件 | 权重、表示/缓存、全部原始日志和依赖元数据；manifest 明确 Chat 能直接读取、只能查看摘要、按需可补或暂不可读取。所有可影响结论而未能读取的部分必须披露。 |

共同底座/输入按摘要去重一次上传，后续每批发送新增项及精确版本引用；没有目标 Chat 的实际读取验证，不能用“之前发过”作为当前已读证明。CSV/JSON/文本和图可直接分析；复杂二进制由安全只读导出的结构说明辅助，不让模型凭一个权重文件名猜内容。对决策必需却不可读的文件，Chat 返回 needs_evidence，网关按原批准范围补材料。

取回原件、给 Chat 的分析包、交给 OpenCode 的准备任务是三种权限视图。准备任务只含技术需求、获准输入和可公开诊断，不带私有验证标签、精确分数或逐样本验证残差。按用户本轮明确分工，取回 Thread 在宿主私有评分区用官方 valid 评分，评分报告和声明字段的诊断进入指定分析 Chat 的批次材料；原真值留私有区。逐行诊断具有标签信息，不能当作盲数据转给准备/训练方。官方允许 valid 调参与本地隔离要分清楚。

新训练未来应保存现有缺口中确实支持判断的记录，例如训练/内部验证逐样本预测、epoch 曲线、学习率、检查点选择与 RNG/优化器状态。那是后续获准训练计划的记录要求，本次设计和取回不会补跑历史数据。

## 按比较问题成批，按实际终态触发

一个 run 定义为任务、底座、特征/预处理、头配置、划分和 seed 的具体组合。一个比较组使用相同任务、数据版本、划分、指标及同一组 seed。一个 Chat 评审批次可以覆盖几个比较组，但不能把不同任务的原始 loss 混排成一个总冠军。

建议起始参数，属于流程配置候选，不是已测最优值：

| 触发 | 建议 |
|---|---|
| 协议首测 | 用现有两个已完成Caco2 run做一次完整公开链接读取/回收；明确多因素混杂，不新增训练。 |
| 快速候选筛选 | 每批 4–8 个有对照的配置，先用共同固定 seed/划分；包括基线，结果只能作初筛。 |
| 候选确认 | 2–4 个保留配置，在同一组 3 个 seed 下复验，共 6–12 个 run；比较均值、离散性和逐样本差异。 |
| 任务扩展 | 按预先选定的代表任务组织，不把一个 Caco2 结果推广为所有 ADMET 任务；全任务比较保留各任务指标方向、覆盖率和官方聚合定义。 |
| 正常发 Chat | 预登记比较组达到终态并通过取回验收后立即发送，失败也纳入总表；不只挑最好成绩。 |
| 防止久等 | 自首个新可用结果起 30 分钟检查一次是否已有可独立判断的比较组；最多等到 60 分钟发送一次明确标记的 partial 批次。核心对照未到时只分析缺口/故障，不抢判优劣。没有新证据不重复发送。 |
| 重大故障 | 非有限预测、冻结/标签/文件边界失败先通知主控处置；有价值的诊断证据单独给 Chat，不等待批量凑齐，也不把失败 run 计入模型胜负。 |

这不是固定每半小时训练一次。运行、取回、分析按依赖触发；主控可在同一已批准预算内继续无依赖的在途实验。Chat 同一研究分支同时只处理一个固定快照，新结果排到下一版，以免分析依据中途变化。队列积压时合并完整比较组或缩减后续派发，不丢失败结果，也不为了占满 GPU 无限产生没人审的实验。

本地记录显示两次 Caco2 的 `elapsed_seconds` 为 4.81 与 3.56 秒；这是训练脚本口径，不包含 Thread 准备/环境检查/取回。取回首测传输 66.97 秒、字节校验完成 77.42 秒、整会话 575.06 秒，见 [验收](../../retrievals/hainan-follow-full-20261031/acceptance/report.md)。因此缓存相同底座表示、同一训练执行任务批量跑获准新头、按批次取回增量，应比每头走完整会话循环更值得做。批量执行仍须独立 run 身份和资源核验，首轮通过不等于并发/共享已通过。

一个循环的时间为：准备与验收 + 排队/环境准入 + 本批训练 + 完成发现 + 取回/评分 + Chat 分析 + 主控决策。本次发送至网关六件验收记录为64分47秒，包含连接故障、观察中断和取回等待；UI显示思考36分31秒，不能当独立测得的后台计算时长。此前15–45分钟条件估计没有被本次完整墙钟支持，不能继续作周期承诺。应按完整比较组触发、同分支单请求、队列背压；下一轮先测短正文/ZIP协议，积累样本后再定延迟预算。

## 状态落盘，消息只负责唤醒

网关读取稳定状态，消息携带 ID 和证据路径；遗漏通知后仍能从账本恢复。采用至少一次投递和消费去重，不声称跨聊天 exactly-once。每个发送动作先落 outbox，再发送，再保存回执。响应未知先核对目标消息，不盲目重发训练/Chat 请求。

训练状态：registered → admitted → running → completed/failed，暂不可达为 unknown/waiting_for_connection。取回状态：requested → retrieving → verified/partial/source_changed。评审状态：collecting → packet_ready → published → sent → chat_running → received → response_validated → delivered → consumed。各状态各自存在，训练完成不代表取回、评分或分析完成。

稳定完成的三个条件：正确 request_id/turn_id，服务或工具有终态证据，规定交付存在且匹配本轮身份。OpenCode idle、Chat 暂时停止输出、最后一句“完成了”均不足以替代它们。Chat 只有 UI 时，结合生成结束控件、当前请求后的完整回答、固定结束标记和附件实际下载校验判断；有限时间不动只记 unknown/stalled。

本次已见真实案例：Terra 记录 MiniMol/MoLFormer 为 idle_incomplete，最后消息无完成时间/finish，服务曾重启。该证据说明空闲不等于成功，[当前原件](../../../../contexts/infrastructure/opencode_terra_monitor_20261031/status.json)可复查；本文不重发或修复那些任务。

恢复策略：临时网络故障由既有 Skill 有界退避；一次预算耗尽保留等待、证据和已登记作业身份。外部写入/发送结果不明先核实；真实身份/路径/规则不符停止依赖动作。Chat 回复缺文件/结构时同 request_id 记录补件 attempt，最多两次有界修复，然后交主控；失败不自动追加训练。
