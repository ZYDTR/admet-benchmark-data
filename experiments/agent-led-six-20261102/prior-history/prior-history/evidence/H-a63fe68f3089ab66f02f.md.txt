# Registered six-run runtime candidate

This is a local candidate for `contract-follow-e2e-20261101`. Its base is the
actual execution-04 deployed snapshot, runtime manifest SHA256
`509bf7be06cb9cf88a4a0bf1d700e92fe215c3200a0e555831c6c342ecbf7809`.
The closed default profile and six candidate profiles do not authorize a start.
The controller subsequently admitted scientific sources at preparation/host-admitted-v1;
the six config candidates match those admitted bytes. Runtime acceptance and
target dispatch remain pending. No scientific source is modified here.

`job_waiter.py` is the finite per-run entry. It records the pipeline's actual OS
return separately from its propagated exit (negative signals normalize to 128+n).
`batch.py` invokes six independently installed per-run entries sequentially;
every phase and failed attempt consumes the same 5400-second budget. A reserved
allocation survives an ambiguous launch. The lifetime batch/run/learning locks
are never reclaimed by this implementation. A repeated invocation reads original
identity, locks and status and returns73. Completed learning is never replayed.
Generic optimizer/RNG checkpoint resume is not implemented by this candidate;
recovery needs a separate bounded main decision and verified implementation.
An archived production query keeps registered scope and actual target identity
checks but returns before START expiry/budget/admission gates. It cannot launch.
If cancellation's second wait times out, a per-job finally durably records the
original identity, elapsed charge and unknown release, retains the reservation
and stops the batch. It does not signal an identity-unknown process.

The original125 remains unknown in historical records. `process_state.py`
preserves raw stat-before/status/stat-after, errors and expected starttime for
bounded sampling. Missing live RSS is unknown. Permission denial, malformed or
negative memory, unknown state and lifetime mismatch cannot be erased by a later
valid sample or successful receipt. A narrowly eligible disappearance/missing
field can wait at most80ms for a real child exit. A success then requires the
same registered lifetime, a valid current receipt, terminal/absent process proof,
fresh final resource checks and a cleared filesystem trace. Timeout, nonzero
exit or known safety failure never takes that path.

Signals use each recorded PID and start identity, never a process group or shared
UID. Linux opens a pidfd before checking the lifetime and sends through that same
kernel handle, preventing PID reuse between check and signal. The guarded worker
must verify pidfd signal0 on itself before scientific imports. Missing support is
a preflight failure. Offline macOS tests signal only held unreaped direct Popen
children; they do not certify Linux pidfd or real /proc behavior.

Protection still precedes the science helper's NumPy import. The unchanged
Linux boundary/environment and optional own-thread compatibility shim are copied
from the actual deployment. Production finalization checks the current token,
worker/launcher identity, exact artifact hashes, real Tensor/optimizer/RNG
metadata, actual process exit and a conservative syscall audit. That audit has
the same documented narrow parser/device limitations as the actual reference;
it is not a whole-host or ioctl isolation proof. RAM/GPU targets are monitored,
not aggregate kernel quotas.

Production admission requires the exact registered run, canonical project-compute target,
PLAN/config/monitor/seed/input identities, current formal main dispatch, frozen
instructions, common cycle runtime manifest, exact science manifest and passed
scientific acceptance. Runtime GPU UUID/index are filled only after future fresh
resource qualification. No remote client or credential code is included.

Offline modes use only the fixed `tests/toy_science.py` under this candidate's
`raw/offline/` directory. Those synthetic .pt/.npz bytes certify neither learning
nor Tensor storage. Tests invoke the actual waiter, pipeline, supervisor and
worker entries, capture real stdout/stderr and OS exits, and separately exercise
the production classifier and trace parser with raw fixtures.

The deployment contract is at `DEPLOYMENT_INTERFACE.json`. `bundle.py` is a
local-only exact-byte stager; it rejects pending science/runtime acceptance,
digest mismatches and old state/output/cache inputs. A future reviewed receiver
must verify exact framing and the old own checkpoint before byte-copying it into
a new run, then issue independent deployment admission. No receiver is executed
in this phase.
