# ADMET 宿主训练唯一入口

团队私有项目。本文件是准备、算力观察、训练、取回评分、发布、Chat分析和主控验收的统一入口。先读 [控制合同](control/README.md)、`policy.json`、`docs/source-map.md`，再按 [项目Skill索引](skills/INDEX.md) 进入本角色规范及对应run/周期合同。所有项目专用Skill只在此项目内维护与注册；全局仅保留项目路由和通用基础设施能力。已读内容无需循环重复读取。计划只是授权范围的记录，不自行授予计算或远端写入权限。

## 规则来源与适用范围

用户本聊天的明确要求决定当前任务；公开赛事原文、用户向赛方确认的条件、主控选择的本地控制、某次试验限制和代码能力必须分开。`policy.json` 的 train-only/盲验证等是当前本地选择，`pilot_*` 只描述首试；都不能冒充赛事逐项禁令。单项试跑不是长期单任务上限；批量范围按用户已授权任务登记，已批准范围内不逐卡、逐次重新询问。

当前用户已授权的一次完整自主闭环从 [contract-follow-e2e-20261101](cycles/contract-follow-e2e-20261101/CONTINUE.md) 进入；实时阶段见其 `status.json`，本轮任务与预算见 `CYCLE.json`。六个新run已通过科学、运行源码与计划准入并正式派发；实际目标预检、学习和验收以当前状态为准。控制合同、全部流水线Skill及Prompt整合的离线验收见 `audits/control-consolidation-20261101/REPORT.md`，不能当成本轮真实闭环通过。最近已结束周期为 [monitor-mae-e2e-20261101](cycles/monitor-mae-e2e-20261101/CONTINUE.md)。角色 Skill 定义职责，冻结的当次任务定义具体输入/预算，历史报告只证明过去事实。新规则不回写旧证据；发现冻结任务与用户新要求冲突时，主控明确版本化接续，不能让执行方自行猜优先级。

## 固定规则

- 外部预训练权重允许使用，但必须保持冻结。这来自用户已向赛方确认并在本聊天重申的条件；不得冒充公开网页逐字条款。`requires_grad=False`、`eval()`、推理无梯度、优化器排除编码器参数、运行前后参数与 buffer 摘要一致均需实际检查。磁盘 checkpoint 摘要不变单独不足以证明内存中未微调。新预测头允许训练；从零训练方案另行登记，不能混成预训练底座微调。
- 原始赛事要求、用户确认、本地控制和未确认项分开记录。读取 `policy.json`；不得把旧 Harness 的随机初始化、只能本机 Docker 或未部署网关当成通用赛事禁令。
- 本入口选模阶段仅使用官方 train.Y 学习，内部划分做早停；valid保留用于评分与分析，最终是否train+valid合训由用户另行决定；训练执行方的 valid/test 只输入 Drug_ID、Drug。预测、标签评分和赛事上传分别处理。官方允许 valid 调参；2026-10-31 用户明确由指定取回 Thread 在本机用 valid 真值及固定评分器评分，主控独立验收，评分与训练隔离是本地控制。评分报告和问题诊断进入逐批登记的专职分析 Chat；经主控核验来源、行映射与evaluation_scope后，可提供本批明确准入的valid真值用于诊断，分析访问不等于新公开发布授权。历史aggregate_only任务不变。准备/训练会话可接收任务级、分组级精确汇总评分和技术诊断，保留指标、分组与来源身份；不接收逐行valid真值、残差或查表答案，也不能通过极小分组或差分还原个体答案。实际评分仍由指定宿主角色完成。外部补标签、教师伪标签和测试拟合仍不纳入。
- 保留任务、分区、原始行号和全部输入行；ID 可以重复或为空。未经新的清洗授权不删行、不去重、不改标签。模型内标准化仅在内部训练划分拟合并保存，输出还原到给定 Y 数值尺度。已发现的清洗包仅有审计，尚未替换基线。
- 实际运行前执行 `python3 -B scripts/check_plan.py runs/<run_id>/PLAN.json`。该检查目前是 Caco2/CheMeleon、单GPU、已登记试跑的专用检查器，硬编码范围见 `src/plan_checks.py`；不支持新任务/并行不是用户禁止。新模型/批次应先扩展并核验任务合同，不能伪造旧run通过。该检查不能代替代码、GPU、路径、运行及冻结状态审计。
- 海南相关一切操作先完整读工作区 `rules/skills/hainan-compute-access/SKILL.md` 及命中的连接参考。只能经既有 Windows 路由；全部目标机写入、副作用、环境和缓存都在 `<AUTHORIZED_PROJECT_ROOT>`。绝不停止他人服务、删除或改动他人文件。先核实资源，再选卡，启动前复核，记录 GPU UUID、PID、启动时间并持续观察，仅处理自己的有身份作业。
- 只有主控或用户明确指定的宿主执行会话可按当次授权亲自使用连接入口。准备 Agent 仍不取得凭据或任意远端 shell。不能自行再派发 Agent、Thread、CLI 模型或转交执行权限。
- 每次 run 独占目录；失败留证，不覆盖旧尝试。未来批次遇到已查明的可恢复故障，主控可在原科学配置及已批准总预算内登记有界恢复；先核对原作业身份与状态，恢复不可行时须证明原作业已退出，再决定是否重训。全部尝试计入总预算；已完成学习的当前作业不因此重跑。运行状态不明先查询原作业，不能重复提交。模型、输入、代码、环境、日志及产物均保留摘要。训练/准备角色不自动上传赛事或推送仓库；用户已授权的分析材料由取回方按登记清单发布到 ZYDTR 仓库，官网提交只走用户手动触发的专用角色。

## 项目路由

2026-11-01 用户另行授权专用手动官网提交与查分Thread，先用 GPT-6.1 Terra，随后明确改由新 GPT-6.1 Sol Thread接手；当前身份见 `submissions/thread.json`。入口 [submissions/README.md](submissions/README.md)，规范为 [赛事提交Skill](skills/competition-submission/SKILL.md)。这是每次明确手动请求范围内的官网上传例外；`policy.json` 中训练/自主循环的 `official_upload` 排除及旧run合同保持原样。材料进入固定批次不自动触发提交，该角色不训练、不监控其他Thread、不建定时，结果仍直接向该Thread的用户报告。主控可按统一反馈边界将已取得的任务级/分组级汇总评分与技术诊断纳入后续准备材料。

准备方可在mini任务私有目录准备任务依赖、下载已批准底座，并做不更新参数的轻量接口检查；环境、缓存和临时文件须在TASK登记的私有写入范围内，不修改共享环境、不训练、不操作海南。准备方使用 `skills/ml-preparation-only/SKILL.md`，主控每次派发冻结到目标机实际可读的任务包并明确要求读取；OpenCode仍从mini Context Infrastructure根进入。训练方使用 `skills/admet-frozen-training/SKILL.md`；独立 `gpt-6.1-sol/xhigh` 观察Thread按 `skills/hainan-resource-observation/SKILL.md` 每10分钟只读记录到 `resources/hainan/`。训练执行Thread也固定为 `gpt-6.1-sol/xhigh`，先读资源日志，陈旧/缺失时自行查询，实际启动前总要再次直接复核。取回评分方使用 `skills/hainan-training-retrieval/SKILL.md`，网关和主控研究使用下述证据Skill。角色不能凭其他角色的规范扩大自身授权。

Chat网关按用户2026-11-01最新授权使用混合通道：可用内置Browser新建本批普通Chat并核实Pro；真实会话ID可用后优先原生发送/续问、读取正文。如果首条消息前没有原生可寻址的真实ID，允许Browser发送一次已封口的首条正式任务，核实服务端接收后交回原生接口。不得为占位另发消息、未知发送后重复提交或用Work Cloud替代Pro Chat。文件继续允许Browser从真实附件页取回。创建、首次发送、原生接管分别留证，具体见项目证据Skill。

Chat研究Prompt由主控维护固定模板及每批研究目标；网关仅按主控绑定的版本与封口材料填小字段，发送前使用项目证据Skill的固定渲染/核验入口。模板变更不自动触发新的Chat分析。

资源观察与训练按用户2026-11-01明确要求直接衔接：观察更新文档，原训练Thread在等待时消费通知、现场复核并继续已准入任务。主控负责任务/源码准入、实质故障处理与结果验收，不逐次中转普通资源变化。资源判断按本任务预计需求、余量及对他人影响，不能规定显存必须为0；共享资格遵守通用海南Skill，某实现尚未验证的共享分支要如实保留。

持续整理实验历史、构建新Chat阅读包及登记结论验证/推翻时，使用 `skills/admet-evidence-review/SKILL.md`；本地实例入口 `exchange/catalog/README.md`。该Skill不扩大训练、标签或发布权限。

`policy.json` 保存适用约束；`evidence/` 保存源规则快照与出处；`docs/source-map.md` 说明旧 Harness 的采用/排除；`scripts/` 是无凭据检查入口；`tests/` 是离线反例；`runs/` 保存计划、实现和证据。原 Harness、旧基线和准备 Agent 交付只读。

原单作业试验 `runs/hainan-skill-pilot-20261030/` 已失败留证。用户随后授权主控修复跑通；`runs/hainan-frozen-training-20261031/` 已完成真实训练和独立验收，参考报告见其 `acceptance/report.md`。执行会话只写指定 run，不能改本入口、policy、Skill 或验收标准；这些由主控按用户要求维护。新方案/配置另建 run，先登记来源和预算，不能重放完成的 run。

每个可用阶段更新 `docs/working.md`（仅主控修改）；获准提交时分阶段提交，无推送授权时保留本地记录。本项目 Python 检查仅用标准库、`-B`，不在只读检查中隐式训练。

## 主控复核与新版 Skill 派发

用户要求主控持续审读各角色的实际行为和产物。每发现需要沉淀的新问题，在创建或修订Skill前重新完整读取[Best Practice Skill Writing](../../rules/skills/bestpractice_skill_writing.md)，判断问题应进入项目Skill、固定工具或验收反例；以真实失败和证据为依据，不把未确认根因写成事实，不靠不断堆叠提醒替代代码修复。保留旧版、修订原因和可检查的成功标准，更新本项目skills/INDEX.md；项目专用能力不注册到全局。

此要求覆盖准备、训练、资源观察、取回评分发布和Chat网关。下次向相应Thread派发新任务或明确重跑时，主控须在对方实际可读的任务位置交付当前适用Skill及命中引用的冻结版本，提示中明确要求使用，并登记路径、版本/摘要及任务身份。对方读取记录与实际行为分别验收，不能仅凭“已读”或回显摘要判通过。长期Thread有旧历史也必须收到本次版本绑定。

新版本用于后续派发；正在执行任务的冻结输入、历史规则快照和失败原件保持原样，紧急恢复另有版本化决策。Skill修订本身不授权追加训练、评分、发布或模型会话。主控工作记录区分代码检查通过、真实运行通过和新版Skill模型行为尚未实测。

主控消费已到达的结果是当前任务的一部分：答复状态/疑问后继续处理，不能只记review_pending就结束并等用户催。每个需动作回报应有真实接续决定、负责人和证据，或明确外部依赖/用户阻点；交接细则见[项目接续合同](skills/admet-evidence-review/references/handoff-completion.md)。该合同不新增常驻轮询或训练授权。
