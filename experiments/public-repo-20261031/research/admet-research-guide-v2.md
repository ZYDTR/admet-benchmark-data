# ADMET 调研纲领与判断规范 V2

日期：2026-10-30（Asia/Shanghai）。适用：兴智杯「小分子药物预测技术创新赛」赛题 159。V1 已先行交付并保留；本版依据真实数据审计、并行研究和独立审查修订。**这份文件规定研究者必须想清楚什么、用什么证据作决定、何时足够；具体工具和实验实现由执行者选择。**

## 1. 目标、输入与完成标准

目标是为三人团队选择有限、可执行、能被反驳的模型实验组合。结论必须连接到这批数据与赛制；另一位没有聊天历史的 Agent 应能继续工作，并知道哪些结论尚不成立。

固定输入：

- [赛事页面](http://www.aiinnovation.com.cn/web/#/trackDetail?id=159)公开禁止其他外部数据，要求设计并训练深度学习模型。**用户已向赛方确认外部预训练权重允许使用，但必须冻结。** 将其标为 `user_confirmed`，不要重复要求确认或把全部预训练资产一律禁掉。
- [用户指定数据仓库](https://github.com/ZYDTR/admet-benchmark-data)，本次提交 `0275588ac7a5d3df032ec7dc0794cab21dfcfeeb`：22 个任务，每个有 train/valid/test；train/valid 有 Y，test 没有 Y。目录、规模、单位和划分的已知程度见 [数据画像](data-profile.md)。
- 本轮可以研究公开论文、代码和文档，分析用户给的数据。新外部样本、外部标签、在线性质查询或教师输出不因“用于研究”而变成获准训练输入。当前任务若指定只读、禁联网或只做计划，该限制优先。
- 当前候选、版本、许可和证据见 [候选卡](candidate-evidence.md)；它们是会过期的事实，不是本规范的固定赢家。

研究完成必须达到以下可检查结果：

1. 数据、指标、标签角色与全行输出要求已明确；未决事项有具体影响范围。
2. 主要结论能够回到原始资料或可复算分析；版本和协议对应，支持与反证同时保留。
3. 首轮每项实验回答一个会改变决策的问题；有适当对照、预算边界、停止与重开条件。
4. 分开报告规则资格、证据支持、接入成熟度和本赛实测表现；未跑模型时不宣布最优。
5. 接手者能指出下一步可做什么、哪一步暂不能做、需要什么新增证据；不能只留下“待进一步研究”。

## 2. 先确定本次要决定什么

用一句话描述决策，再决定读哪些材料。下面是问题地图，不是必须逐行照走的流程。

| 问题 | 要解决的判断 | 主要入口 |
| --- | --- | --- |
| 数据实际是什么 | 样本行、分子、测量和标签各有多少；哪些输入真的存在 | 数据画像、固定快照与审计 |
| 怎样评价 | 指标定义和方向；验证支持哪类泛化结论；官方未知在哪里 | 数据画像 §4–7、来源索引的评价资料 |
| 哪种知识可迁移 | 预训练信号是否相关；冻结条件是否有证据；其他头能否改变判断 | 候选卡及原论文方法/补充材料 |
| 哪项公开成绩可引用 | 资产、数据、更新参数、head、搜索和集成是否一致 | 本规范 §3 |
| 能否完整接入 | 资产可取得、许可范围、输入覆盖、确定性、资源与现有工程能力 | 候选卡、模型接口 |
| 是否需要共享或融合 | 增益是否来自表示、标签共享、head 或预算；是否存在负迁移 | 本规范 §5–6 |
| 是否继续查资料 | 新信息是否可能改变候选、限制或实验，而非只是增加引用 | 本规范 §7 |

ADMET 是吸收、分布、代谢、排泄、毒性的统称，并非一个统一标签。编码器把分子变成向量；预测头根据向量学习某项性质；D-MPNN 是分子图 GNN 的一种，CheMeleon 是该架构上的一种预训练方案。共同使用一个冻结编码器，不会自动产生任务之间的学习迁移。

## 3. 证据必须绑定完整方案和时间线

### 3.1 一个成绩的最小身份

**资产版本 × 输入处理 × 数据/划分 × 参数更新时间线 × 预测头 × 搜索/集成预算 × 指标定义。**

这七项不匹配，最多得到相关线索，不能继承成绩。比较编码器时尽量控制 head 和预算；比较完整方案时允许不同配套，但只能把胜负归给整套方案。相同 head 也不保证相同可训练参数数目或优化难度，必要的配套调整要记账。

冻结核查覆盖从外部 checkpoint 到最终预测的全程。先在目标任务微调，再冻结抽特征，不能当成“原始外部权重始终冻结”。检查实际可训练参数、优化器对象、模型 buffer、输入预处理与随机性；`eval()`、`no_grad()`、函数叫 `fit` 或命令含 `from-foundation`，单独一项都不能证明完整训练语义。LoRA/adapter 等额外可训练模块应单列其位置和来源；用户的冻结确认不自动证明任意插入式改造均在同一许可范围内。

资产是一个组合：代码、NN 权重、tokenizer/字典、预拟合归一化参数、特征定义与配置可能分别有版本和许可。元数据给出的哈希与本轮下载后计算的哈希分开记。研究中未下载权重不是失败；正式接入前必须完成对应资产的核验。

### 3.2 事实状态和来源证明力

每条改变决策的主张至少记录：**主张、来源与定位、版本/日期、证据状态、支持范围、反证或限制、决策影响。** 不要求给无关背景写冗长卡片。

| 状态 | 含义 |
| --- | --- |
| `observed` | 本轮直接读到的指定字节、源码或可复算统计；注明工具与定义 |
| `author_reported` | 原作者的实验结果；本轮未复现 |
| `corroborated` | 另一原始研究或本地分析支持；必须写明独立在哪里 |
| `user_confirmed` | 用户明确提供的规则澄清，不伪造为网页原文 |
| `inference` | 从事实推出的有限判断，列明前提与推翻条件 |
| `unknown` / `conflicted` | 证据未闭合或存在冲突，写清影响哪一步 |

规则以赛事材料和已确认澄清为依据；文件内容以字节为依据；实现以相应代码为依据；性能以对应实验为依据。官方概述与数据实物不符时，保留两者，采用实际文件设计输入，不虚构缺失特征。任务同名不证明数据同版、单位相同或历史 split 相同。

证据的**独立性**与**本赛适用性**分开评估。同一团队论文、README、模型卡属于同一来源链；三个 Agent 读同一篇论文不是三次独立实证。第三方论文也可能重切数据、换指标、更新骨干，或由某个被测模型的作者参与。无论赞成还是反对预训练，都接受同样严格的协议审查。

### 3.3 遇到冲突时怎样判断

优先查能解释冲突的差异：论文版本、checkpoint、原始/清洗数据、冻结阶段、head、预算与指标含义。主表没有冻结结果时，定向检查方法、消融、补充材料与后续版本；不要把“没找到”写成“没有”。网页抽取空字段或抓取失败时，尝试该发布方的原页/API/开放原文；无法核实时保留未知，不借用相邻资产的许可或结论。

反证也限定作用对象：某环境报错不是所有版本都坏；预训练中见过结构、见过相关 assay 标签、见过目标端点标签、目标测试标签参与训练或选模，是不同事实。不能从结构相似直接跳到本赛违规，也不能因用户允许冻结就把任何性能污染疑问抹掉。此类证据会限制公开分数的可信度和可迁移性，不自动改写已确认规则。

## 4. 数据判断：分清身份、分布和可用信息

**保留四个层次：原始文件行、分子身份、任务端点、测量/标签记录。** 行的稳定身份使用 `(task, split, row_index)`；Drug_ID 可以为空或有字符串差异，SMILES 也可能重复，不能任意当唯一主键。固定向量可按合适身份缓存，监督行不因此合并。

身份比较必须命名：原始串、保留立体的 canonical、去立体、去盐、互变异构体、Murcko scaffold 不是同一关系。报告工具版本、解析失败和空骨架如何处理。空 Murcko scaffold 不是“这些分子同属一个有意义的化学家族”；非空骨架零交集也不能恢复官方历史切分算法。

检查划分既要看**隔离性**，也要看**代表性**：每划分分子数、非空骨架种类/集中程度、空骨架占比、标签分布、覆盖异常。验证集行数多，仍可能集中于一个骨架。保留官方划分；若要补充稳健性证据，只在获准 train 内预先定义诊断划分，清楚标为补充实验，不悄悄替换官方 valid。所有诊断选择不得使用 test 标签。

重复或冲突标签不自动是脏数据。删除、平均、取最后一个、去盐或更改立体信息都是科学假设，需要依据和对照。相同输入出现冲突标签时，要求 tiny-fit 训练损失必为零是不合理的普遍验收。回归数值为负不自动说明无效；尚未核实单位/对数变换时，保护给定 Y，不能凭任务名再 log 或按物理阈值裁剪。

**未知应局部阻塞：**

| 未知/问题 | 当前仍可做 | 暂不能据此做 |
| --- | --- | --- |
| 单位、既有变换或生物正类映射未闭合，但 Y 有限且类型明确 | 原数值 Y 的基线设计、按数值1定义的分类评分、文件/模型研究 | 擅自 log、物理裁剪、反转标签、合并 assay 或作生物学定量解释 |
| 官方聚合式/AUPRC 细节未知 | 分任务报告，明确标注本地 AP，事先定义团队选择准则 | 伪造官方总分或声称本地 AP 已被赛方确认 |
| 个别模型输入不覆盖 | 比较表示、设计/验证程序化回退；先记录完整异常清单 | 丢提交行、手改预测、把未完成覆盖的方案称为可提交 |
| 资产许可字段抓取不完整 | 定向补查该资产来源，继续其他候选 | 以代码许可替代权重许可，或直接宣判整个模型不可用 |
| 没有 Docker/实际适配器或正式登记数据 | 完成只读调研、实验设计、证据审查 | 把计划写成训练完成，绕开既有正式执行边界 |

模型覆盖不只看“支持 SMILES”：需区分解析、词表/元素、立体信息、片段、token/原子上限、构象与裁剪/回退。实际失败应定位到具体输入和版本；不把一种解析器失败说成分子在所有软件中无效。输入处理可以有合理程序化策略，但要保留原行、验证范围与输出来源；不能隐式截断后声称完整理解原分子。

## 5. 训练信息与多任务归因

从公开页面学习方法与给模型添加数据是两种行为。使用官方本地 SMILES 通过固定变换抽向量，与在 train+valid/test 上拟合 scaler、PCA 或特征选择不同。需要拟合的处理只用相应训练部分；推理缓存的复用不授予跨任务标签权限。

多任务计划必须说明：共享哪些可训练参数；每个标签来自哪个 task/split/row；缺失标签如何 mask；每任务采样和 loss 权重；用什么早停和模型选择依据。只共用一个冻结编码器、各头完全独立，应称“表示复用”，不能把提升归为任务间训练迁移。检验多任务时，以同一表示的独立头作对照。

同分子在 A.train、B.valid 的情形：训练使用 A 的标签，不自动等于使用 B 的目标标签；但是 B 验证也不再代表全局从未见过该分子。宽表转换必须保留**逐标签**角色，不得把 valid 标签补入训练，也不能把缺失端点补 0。若目标是证明未见分子泛化，另行定义隔离所有端点的诊断，或在现有 valid 中报告见过/未见过的子群及样本限制。

分层前先查该子群能否回答问题：样本数、类别和骨架覆盖是否足够。没有正类时，软件给出的AP约定值不是正类检索能力证据；只有几条样本时，不把分层报分当成已证明迁移。不能估计就明确保留未决，继续评价完整方案，不补造子群结论。

不强制把 22 个任务训成一个共享网络。任务量、尺度、噪声和相关性不同；共享可能帮助小任务，也可能由大任务主导。总 loss 下降不能替代逐任务评价。结构相似、同属 CYP 或预测相关性高，都不足以单独证明共享会带来收益。

## 6. 从文献走向有限实验

每项建议说明四件事：**要区分的解释、最低成本对照、什么结果改变决定、何时停止。** 以此排序，不按“每个人一个架构家族”平均分预算。

- 保留简单指纹/描述符对照与从零训练的小型深度模型对照。前者检测表示复杂度是否必要，后者检测冻结限制的代价；不要求重写现成框架。
- 首轮将主要自由度用于表示或一个清楚的设计问题，给候选对称且有限的 head/优化预算。合理配套允许变化，但不得同时换数据、划分、head、loss、ensemble 后声称仅编码器更好。
- 某表示在一个 head 上弱，不足以永久排除整个表示。只追加一个有理由且可能改变决定的对照；不要以“也许没调好”为由无限续费。
- 区分随机种子波动、有限验证样本不确定性、反复选最大值的选择偏差。多 seed 主要处理第一项。重复测量和骨架集中时，行级 bootstrap 或更多 seed 不会凭空增加化学覆盖。
- 四种指标分别看，MAE 越低越好，其他三种越高越好。AUPRC/AP 的实现明确标注；需要排序分数的任务不改成0/1硬判。自定义汇总只叫本地选择规则，不能混合量纲冒充官方分。
- 若某个官方未明确的指标实现会决定微小优势的取舍，在相同已保存预测上做预先指定的有限敏感性检查；实现改变排名就收窄结论，不挑对自己有利的实现。该可能性不等于本赛已出现排名反转。
- 融合先要求单模型有用且有实测互补，再考虑简单、预先约定的组合。低相关可能来自噪声；在极小 valid 上搜索大量逐任务融合权重会制造额外选择偏差。

成本按完整方案看：接入、预处理、覆盖处理、一次编码、缓存、head 搜索、推理、最终可复现。权重文件大小不是显存，参数多不是必然更强，论文训练时间不是当前设备实测。没有硬件信息时给名额/阶段预算和条件方案，不编 GPU 小时。

## 7. 决策状态、停止和重开

| 状态 | 依据 | 后续动作 |
| --- | --- | --- |
| `exclude` | 当前明确违反规则或硬性条件 | 指明具体不满足项和什么改变才能重开 |
| `defer` | 可能有价值，但当前证据、资产或预算不足 | 写可触发重开的证据，不能误写成性能不行 |
| `pilot` | 值得投入有限实验的条件化判断 | 列接入前置条件与判别问题；不保证优胜或立刻可运行 |
| `preferred` | 本数据、固定协议、适当对照下已有足够实际结果 | 写适用任务和稳健性；不能升级为普适最佳 |

状态之外另列：规则资格、资产成熟度、运行覆盖、本赛性能证据。某模型可进入候选研究而还没通过正式运行准入；有许可不证明有用，有用也不证明全行可交付。

当主要不确定性已转为“在本数据上效果如何”，且少量候选、对照、评价与覆盖计划都已闭合，就结束广泛文献搜索。只补会改变决策的窄问题。出现新的规则/数据版本、输入不覆盖、关键反证或本地结果推翻假设，才定向重开。任何“停止”都应说清本轮未做的实验，而不是填上想象的验证结果。

## 8. 多 Agent 研究与可接续输出

主 Agent 保留决策问题和主张表。分工围绕不同证据功能，同时对关键主张有意重叠；原始资料共享不增加统计独立性。子 Agent 给来源和限定条件；主 Agent 自行回查支撑主要结论的原文、代码或计算。整合按证据与协议差异，不按票数。

形成初步决定后，用未参与研究的 Agent 检查最弱前提和实际可执行性。收到意见后，分别记录接受、拒绝或降级结论的理由；不要把审阅作为赞同票。规范交付前，再让无对话背景的 Agent 只拿入口和真实任务试用，观察实际读取路径及决定，不能把预期答案塞进任务提示。

一次完整研究交付最少保留：

| 工件 | 交付内容 |
| --- | --- |
| 决策报告 | 先试什么、为何、反对依据、最小实验、停止/重开条件 |
| 数据与候选证据 | 版本、实际统计、协议、资产、覆盖、未知及影响 |
| 逐源核验与研究记录 | 主张→来源→回查结果；范围、原始反证、未覆盖事项 |
| 修订与验证记录 | 真实发现→V1不足→V2变化→独立试用；预测风险另标 |

窄查询只回答相关项，不强制新建所有工件。接续时先看当前决策、完成程度、未决及其阻塞范围，再读所需来源；不要从模型名单重新开始。负面实验只排除其实际测试的条件，不把一个失败写成整个方向的永久禁令。

### 可直接交给下一位研究 Agent 的任务说明

> 阅读本文件，针对指定决策选择必要证据。保持用户确认的冻结权重前提，优先复用已有研究而非重新列模型。输出你的判断、证据与适用范围、最强反对理由、未知影响、下一项能改变判断的最小工作、停止条件。未跑的实验标为计划。若遇到资料冲突，先比较版本/数据/更新时间线/head/预算，再决定补查；不要默认停止全部工作。
